# 提案報告規範

本文件屬於 `專案需知/` 專案需知文件集（Omniplay 產線），總覽、共通原則與完成條件見 [_README.md](其他/_README.md)。

**存放位置**（總表見[總覽](_README.md#3-文件存放位置)）：

| 檔案 | 存放位置 |
|---|---|
| 發想中遊戲（尚無 Game ID）的提案簡報 | `Slots/遊戲發想/<遊戲名>/提案/` |
| 已有 Game ID 的遊戲的提案簡報 | `Slots/H0xx_遊戲名稱/其他/` |

## 1. 用途與範圍

提案報告（遊戲提案說明簡報）用於向內部或客戶說明一款遊戲的玩法、規格、特色與競品差異。適用於遊戲發想（`Slots/其他/遊戲發想/`）與正式專案（`Slots/H0xx_遊戲名稱/`）。

- 內容一律以 `game_rule.md` 為準，示意畫面取自該遊戲的 Demogame；簡報不得出現與 Game Rule 不一致的規則。
- 版式範本：`JB 工作區/game_spec/101026_Super Neko/04_客戶提案/SUPER_NEKO_提案說明_v16.pptx`。
- 首份依本規範產出的範例：`Slots/遊戲發想/急速糖果 2/提案/CANDY_RUSH_2_提案說明_v01.pptx`。

## 2. 檔案

| 項目 | 規則 |
| --- | --- |
| 格式 | `.pptx`，16:9（13.333 × 7.5 in） |
| 檔名 | `{英文遊戲名大寫，空格改底線}_提案說明_v{兩位數版本}.pptx`，例：`CANDY_RUSH_2_提案說明_v01.pptx` |
| 位置 | 遊戲資料夾下的 `提案/` 子資料夾 |
| 版本 | 內容每次修改版本 +1，舊版保留不覆蓋 |

## 3. 章節結構

章節名稱與順序固定。中文標題不加編號；右上頁碼用兩位數章節號（`01`～`08`），同一章的多頁沿用該章頁碼。

| 頁碼 | 英文小標 | 章節 | 必要內容 |
| --- | --- | --- | --- |
| — | — | 封面 | 英文遊戲名、中文遊戲名、三個賣點標籤、`遊戲提案說明 · 遊戲代號 · 規則基底／數學 · JumboRD` |
| 01 | OVERVIEW | 遊戲概述 | 簡單說明玩法與核心特色：主題與定位一句話、核心特色、右側 demo 主畫面 |
| 02 | GAME SPEC | 遊戲規格一覽 | 只列規格，不說明怎麼玩：Line／Way 類型、盤面、押注模式、最大贏分／RTP 等 |
| 03 | SYMBOLS | 符號說明與賠付 | 符號種類（一般符號、特殊符號）與賠率表；註腳寫得分公式 |
| 03 | ART REQUIREMENT | 符號與美術需求（**隱藏頁**） | 一般與特殊符號清單（代號、等級）、美術風格參考、其他需求（場景、Loading、大廳 Icon、特色演出）；**一定要做，但設為隱藏投影片**，簡報時不播放 |
| 04 | CORE GAMEPLAY | 核心玩法 | 逐項說明玩法要素；內容多時拆成多頁，每頁只講一個特色（「一句話：…」主旨＋步驟圖或規則卡＋demo 逐幀截圖） |
| 05 | FREE GAME | 免費遊戲 | 觸發、FG 內規則（例：倍數累積或重置，以深色卡強調）、加局；右側 FG 畫面 |
| 06 | GAME FLOW | 遊戲流程圖 | 不要畫太細，只針對容易看不懂的地方畫流程（含迴圈）＋重點說明 |
| 07 | SPECIAL BET | 特殊押注 | Extra Bet、Buy Feature 等特殊押注；有才放，內容多就拆頁，每種押注一頁（例：3 種 EB、2 種 BF 拆成 5 頁） |
| 08 | VS. {競品} | 與{競品}差異對照 | 一句話核心差異＋對照表（最右欄為本作並以亮色標示）＋結論註腳 |
| — | — | Q&A | 遊戲名、資料來源、`Q & A` 大字、待確認事項（標明給數學／PM／美術） |

- 主章節不可刪除；只有「特殊押注」在遊戲沒有 Extra Bet、Buy Feature 時整章省略，並在規格表寫「不提供」。
- 「核心玩法」「特殊押注」依遊戲實際內容增減頁數，每頁只講一個特色或一種押注。
- 競品預設為規則基底遊戲；另有指定時依指定。

## 4. 頁面版式

### 4.1 封面與 Q&A（深色頁）

- 背景：主題色放射漸層圖（中心偏上較亮）。
- 封面：遊戲徽章（圓形、置中）→ 英文遊戲名（Georgia 粗體 54～56pt、置中）→ 中文遊戲名（字距加寬）→ `✦ ✦ ✦` → 三個膠囊標籤 → 底部資訊列。
- Q&A：左上小徽章＋遊戲名＋資料來源，左側「待確認」條列，右側 `Q & A` 大字（Georgia 粗體 60pt 以上），底部斜體註腳「※ 數值仍待數學調校，最終以認證版本為準。」

### 4.2 內文頁（米白底）

| 元素 | 位置 | 格式 |
| --- | --- | --- |
| 英文小標 | 左上（x 0.7, y 0.42 in） | Georgia 斜體 12.5pt、字距 2pt、金色、全大寫 |
| 中文標題 | 小標下方（y 0.78 in） | 微軟正黑體粗體 30pt、標題色、不加編號（例：`遊戲概述`） |
| 頁碼 | 右上（靠右對齊） | Georgia 斜體 13pt、金色、兩位數 |
| 主旨句 | 標題下方（y ≈ 1.6 in） | 15pt，開頭「一句話：」或直接陳述，關鍵字用強調色粗體 |
| 註腳 | 底部（y ≈ 6.9 in） | 11pt 斜體、註腳色；資料來源、公式、待確認說明放這裡 |

- 左右邊界 0.6～0.7 in；內容區塊間距 0.2～0.5 in，同頁一致。
- 每頁都要有視覺元素（大數字卡、表格、編號卡、demo 截圖或流程圖），不做純文字頁。

### 4.3 元件

| 元件 | 樣式 |
| --- | --- |
| 大數字卡 | 圓角矩形、深色底、金色 1.25pt 外框、陰影；大字 Georgia 粗體 28pt 淺金色，下方 13pt 白字說明 |
| 淺色卡 | 圓角矩形、淺色底、淺金外框 0.75pt；標題 15～16pt 強調色粗體，說明 12.5～13pt |
| 編號圓 | 金色圓形、Georgia 粗體 18pt 數字 |
| 表格 | 表頭深色底＋淺金色粗體字；內文白底與斑馬色交錯；第一欄粗體深色；對照表本作欄用亮色表頭與淺色底 |
| demo 截圖 | 金色圓角外框＋陰影，維持原比例；圖下 11.5pt 置中說明 |
| 流程圖 | 圓角步驟框（依階段用淡金、淡綠、淡藍、淡粉、淡紫區分）＋金色箭頭；迴圈用強調色線＋說明字 |
| 強調字 | 內文中的關鍵詞用強調色粗體，不另加底線或色條 |

- 不使用標題底線、色條、單邊框線等裝飾。

### 4.4 字型與字級

| 用途 | 字型 | 字級 |
| --- | --- | --- |
| 中文（標題、內文、表格） | Microsoft JhengHei（微軟正黑體） | 標題 30pt；內文 12.5～15pt；表格 12.5pt |
| 英文小標、頁碼、大數字、封面英文名 | Georgia | 小標 12.5pt；頁碼 13pt；大數字 28pt；封面 54～56pt |
| 註腳、圖說 | Microsoft JhengHei 斜體／一般 | 11～11.5pt |

- 符號代號（`sym_M1` 等）與含中文的字串一律用微軟正黑體，不用 Georgia（舊式數字會讓 `1` 看起來像 `ı`）。

## 5. 內容規則

- 數值一律取自 `game_rule.md` 與 Config；未定案的數值在數字後加 `*`，並在該頁註腳寫「* 為待確認數值」。不得用 ⏳ 等 emoji（PowerPoint 會顯示成圖示）。
- 尚未調校完成的 RTP、最大贏分不得寫成目標值，一律寫「待數學訂定」，並列入 Q&A 待確認事項。
- 賠率表欄位過多時，只列代表欄（例：5／8／10／12／15+），註腳註明完整賠率見 `game_rule.md` 對應章節。
- 每頁文字精簡：一句話主旨＋條列不超過 4～5 項；細節留在 Game Rule。
- 待確認事項寫成可決策的問題，並標明對象（數學／PM／美術）。

### 5.1 demo 截圖

- 一律從該遊戲 Demogame 擷取，不使用示意繪圖代替實際畫面。
- 以 Debug 的 RNG Seed 重現指定局、用逐幀（Previous／Next）停在要展示的瞬間截圖，確保畫面可重現；以 2 倍解析度擷取（例：Chrome deviceScaleFactor 2）。
- 截圖範圍只取 By Game 區域（Feature Status＋盤面＋盤面訊息），不得帶到 Debug 面板。
- 畫面上的 Stats 不得出現誤導數字（例：連跑多局 FG 後的超高 RTP）；需要時用全新頁面跑單局。
- 每張截圖附一行圖說，說明畫面重點（例：「金光＝計分群集　藍光＝連帶消除」）。

## 6. 製作與檢查

- 建議以 `pptxgenjs` 產生（版面以程式定義，方便改版時重建）；產生後執行 pptx 技能的 `validate.py` 檢查檔案結構。
- 以 PowerPoint 將每頁匯出成圖片逐頁目視檢查（實際字型渲染）。
- 產生腳本與暫存截圖放在暫存區，不放進專案資料夾；專案內只保留最終 `.pptx`。
