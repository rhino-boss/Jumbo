# 提案報告規範

本文件屬於 `專案需知/` 專案需知文件集（Omniplay 產線），總覽、共通原則與完成條件見 [_README.md](其他/_README.md)。

**存放位置**（總表見[總覽](_README.md#3-文件存放位置)）：

| 檔案 | 存放位置 |
|---|---|
| 發想中遊戲（尚無 Game ID）的提案簡報 | `Slots/遊戲發想/<遊戲名>/提案/` |
| 已有 Game ID 的遊戲的提案簡報 | `Slots/H0xx_遊戲名稱/其他/` |

## 1. 用途與範圍

提案報告（遊戲提案說明簡報）用於向內部或客戶說明一款遊戲的玩法、規格、特色與競品差異，適用於遊戲發想與正式專案。

- **版式直接參考指定的過去簡報修改**，不另訂版面規則；沒有指定時用 `JB 工作區/game_spec/101026_Super Neko/04_客戶提案/SUPER_NEKO_提案說明_v16.pptx`。
- 範例：`Slots/遊戲發想/急速糖果 2/提案/CANDY_RUSH_2_提案說明_v01.pptx`。

## 2. 檔案

| 項目 | 規則 |
| --- | --- |
| 格式 | `.pptx`，16:9 |
| 檔名 | `{英文遊戲名大寫，空格改底線}_提案說明_v{兩位數版本}.pptx`，例：`CANDY_RUSH_2_提案說明_v01.pptx` |
| 版本 | 內容每次修改版本 +1，舊版保留不覆蓋 |

## 3. 章節結構

章節名稱與順序固定。中文標題不加編號；右上頁碼用兩位數章節號（`01`～`08`），同一章的多頁沿用該章頁碼。

| 頁碼 | 英文小標 | 章節 | 必要內容 |
| --- | --- | --- | --- |
| — | — | 封面 | 英文遊戲名、中文遊戲名、三個賣點標籤、`遊戲提案說明 · 遊戲代號 · 規則基底／數學 · JumboRD` |
| 01 | OVERVIEW | 遊戲概述 | 簡單說明玩法與核心特色：主題與定位一句話、核心特色、demo 主畫面 |
| 02 | GAME SPEC | 遊戲規格一覽 | 只列規格，不說明怎麼玩：Line／Way 類型、盤面、押注模式、最大贏分／RTP 等 |
| 03 | SYMBOLS | 符號說明與賠付 | 符號種類（一般符號、特殊符號）與賠率表；註腳寫得分公式 |
| 03 | ART REQUIREMENT | 符號與美術需求（**隱藏頁**） | 一般與特殊符號清單（代號、等級）、美術風格參考、其他需求（場景、Loading、大廳 Icon、特色演出）；**一定要做，但設為隱藏投影片**，簡報時不播放 |
| 04 | CORE GAMEPLAY | 核心玩法 | 逐項說明玩法要素；內容多時拆成多頁，每頁只講一個特色 |
| 05 | FREE GAME | 免費遊戲 | 觸發、FG 內規則（例：倍數累積或重置）、加局 |
| 06 | GAME FLOW | 遊戲流程圖 | 不要畫太細，只針對容易看不懂的地方畫流程 |
| 07 | SPECIAL BET | 特殊押注 | Extra Bet、Buy Feature 等；有才放，每種押注一頁（例：3 種 EB、2 種 BF 拆成 5 頁） |
| 08 | VS. {競品} | 與{競品}差異對照 | 一句話核心差異＋對照表（最右欄為本作）＋結論註腳 |
| — | — | Q&A | 待確認事項，寫成可決策的問題並標明對象（數學／PM／美術） |

- 主章節不可刪除；只有「特殊押注」在遊戲沒有 Extra Bet、Buy Feature 時整章省略，並在規格表寫「不提供」。
- 競品預設為規則基底遊戲；另有指定時依指定。

## 4. 內容規則

- **規則與數值**一律以 `game_rule.md` 與 Config 為準，不得出現與 Game Rule 不一致的內容。
- **未定案的數值**在數字後加 `*`，該頁註腳寫「* 為待確認數值」；尚未調校完成的 RTP、最大贏分寫「待數學訂定」，並列入 Q&A。不得用 ⏳ 等 emoji（PowerPoint 會顯示成圖示）。
- **文字精簡**：每頁一句話主旨＋條列不超過 4～5 項，細節留在 Game Rule；賠率表欄位過多時只列代表欄，註腳註明完整賠率見 `game_rule.md`。
- **demo 截圖**一律從該遊戲 Demogame 擷取，不用示意繪圖代替：
  - 用 Debug 的 RNG Seed 重現指定局、逐幀停在要展示的瞬間，以 2 倍解析度擷取，確保可重現。
  - 只取 By Game 區域（Feature Status＋盤面＋盤面訊息），不得帶到 Debug 面板；Stats 不得出現誤導數字（需要時用全新頁面跑單局）。
  - 每張截圖附一行圖說，說明畫面重點。

## 5. 製作與檢查

- 建議以 `pptxgenjs` 產生（版面以程式定義，方便改版重建）；產生腳本與暫存截圖放暫存區，專案內只保留最終 `.pptx`。
- 交付前檢查：
  - [ ] 章節與頁碼符合第 3 節，「符號與美術需求」頁已設為隱藏。
  - [ ] 規則、數值、截圖符合第 4 節。
  - [ ] 以 PowerPoint 匯出圖片逐頁目視：沒有文字溢出、元件重疊。
  - [ ] 檔名、版本符合第 2 節，pptx 技能的 `validate.py` 通過。
