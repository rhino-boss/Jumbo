# 壓測說明書

這份文件回答兩個問題：**要壓什麼**，以及**壓出來的數字怎麼判**。

設定來源為 [Slot 開發注意事項](./Slots/slot_development_specification.md) 第 1.4 節與
[iGaming 機制說明書](./System/iGaming%20機制說明書.md)；本文件不重複定義設定本身。

目前採用的機制版本：**新手體驗 D 版**、**老手救援 B 版**。

壓測與其他驗證工具的分工：

| 工具 | 產出 | 驗證對象 |
|---|---|---|
| 數學模型 XLSX | 理論 RTP、倍率權重 | 模型本身的理論值 |
| Simulator | 單一 Config／Bet Mode／Profile 的大場次報表 | 單一組合的 Game RTP、Feature 觸發率、Card System |
| **壓測** | 固定玩家數 × 固定把數的後端報表 | **玩家實際歷程下的 RTP**，含新老手切換與機制介入 |
| `System/simulator_system.py` | 多分頁玩家模擬報表 | 機制本身的觸發率、Pool 上限、RTP 增量 |

關鍵差異：Simulator 每批固定一個 Profile，壓測則是**同一位玩家從第 1 轉跑到第 N 轉**，中途由新手期切到老手期，並且會被新手體驗與老手救援介入。

## 一、要壓什麼？（必跑組合）

### 1.1 壓測把數影響

壓測以「玩家數 × 每位玩家把數」定義。範例：20,000 位玩家 × 每人 500 把 = 10,000,000 spins。

每人把數決定機制能不能驗到：

| 機制 | 生效轉數 | 需要的最少把數 |
|---|---|---:|
| 新手體驗 D 第一次判定 | 第 50 轉 | 50 |
| 新手體驗 D 第二次判定 | 第 150 轉 | 150 |
| 老手救援 B 起始 | 第 301 轉（新手期 200 ＋ 計算基底 100） | 301 |
| 老手救援 B 第 1 個完整返還區間 | 301～450 | **450** |
| 老手救援 B 第 2 個完整返還區間 | 451～600 | **600** |

### 1.2 押注分級與換算

```text
實際押注 = Coin in × currency denom
```

`currency denom` 直接寫在報表檔頭，不必另外查。目前平台值為 `0.002000`，即 `實際押注 = Coin in ÷ 500`。

| 分級 | 判定依據 | Game RTP 版本 | 可拉 Link | 上限倍數 |
|---|---|---|:---:|---|
| 小 Bet | `< $2` | 94 版 | ✗ | 依數學文件「倍率線型」 |
| 中 Bet | `$2 ~ $100` | 92 版 | ✓ | 依數學文件「倍率線型」 |
| 大 Bet | `> $100`（預設，各遊戲可不同） | 92 版 | ✓ | 依數學文件「倍率線型」 |

- 一般模式（NB／EX1／EX2）用**實際押注**分級，界線固定 `$2` 與 `$100`。
- BF／SF 用**基礎面額**分級，界線放大為 `倍率 × $2` 與 `倍率 × $100`（等價於用面額判 `$2`／`$100`）。
  Buy Feature 的高價不會讓玩家升級到更高的 Bet 分級。

### 1.3 測項產生規則

先取得該遊戲支援的押注模式（`NB`／`EX1`／`EX2`／`BF`／`SF`）與各模式的押注倍率。不支援的模式整組跳過。

每個支援的模式產生「小／中／大押注 × 新手／老手」共六格測項，再套一條排除規則：

| 排除規則 | 適用 | 原因 |
|---|---|---|
| 倍率 `≥ 2` 時不產生**小押注** | NB／EX1／EX2 | Extra Bet 最低成本已是 $2，不可能落在小 Bet |

BF／SF 不套用上述排除，六格全跑。

### 1.4 實例：H026

H026 支援的模式與倍率：`NB = 1`、`EX1 = 2`、`BF = 75`；`EX2`、`SF` 不支援。

| # | 模式 | 級距 | 新老手 | 押注範圍 | 目標 Game RTP |
|---:|---|---|---|---|---:|
| 1 | NB | 小押注 | 新手 | `x < 2` | 93% |
| 2 | NB | 小押注 | 老手 | `x < 2` | 94% |
| 3 | NB | 中押注 | 新手 | `2 ≤ x ≤ 100` | 93% |
| 4 | NB | 中押注 | 老手 | `2 ≤ x ≤ 100` | 92% |
| 5 | NB | 大押注 | 新手 | `100 < x` | 93% |
| 6 | NB | 大押注 | 老手 | `100 < x` | 92% |
| 7 | EX1 | 中押注 | 新手 | `2 ≤ x ≤ 100` | 93% |
| 8 | EX1 | 中押注 | 老手 | `2 ≤ x ≤ 100` | 92% |
| 9 | EX1 | 大押注 | 新手 | `100 < x` | 93% |
| 10 | EX1 | 大押注 | 老手 | `100 < x` | 92% |
| 11 | BF | 小押注 | 新手 | `x < 150` | 92.5% |
| 12 | BF | 小押注 | 老手 | `x < 150` | 92.5% |
| 13 | BF | 中押注 | 新手 | `150 ≤ x ≤ 7500` | 92.5% |
| 14 | BF | 中押注 | 老手 | `150 ≤ x ≤ 7500` | 92.5% |
| 15 | BF | 大押注 | 新手 | `7500 < x` | 92.5% |
| 16 | BF | 大押注 | 老手 | `7500 < x` | 92.5% |

EX1 小押注被排除（倍率 2 ≥ 2）；其餘支援的級距皆同時產生新手與老手測項。

## 二、壓測報表

### 2.1 TG 訊息
**Formal RTP Report**

壓測的主要判定對象是 TG 訊息中的 `Formal RTP Report`。訊息結構如下：

```text
Formal RTP Report
Report ID: <報表編號>
Generated At: <產生時間>
- machineType = <Game ID>
- extraBet = <BetType>
- Bet = <實際押注>
- OldHand Init = <enabled | disabled>

Scenario RTP
整體 RTP
- Game RTP = xx.xx%
- Jackpot RTP = xx.xx%
- Bonus Game RTP = xx.xx%
前 50 次 Spin ...
前 200 次 Spin ...
RTP <=200 ...
RTP >200 以後 ...

SettingID RTP
SettingID 1 xxx（一般）
- Game RTP = xx.xx%
- Jackpot RTP = xx.xx%
- Bonus Game RTP = xx.xx%
SettingID 2 xxx（新手體驗 D）
...

SettingID Trigger Count
...
```

**Scenario RTP：五個時間切片**

| 顯示欄 | 來源標籤 | 涵蓋範圍 | 是否判定 |
|---|---|---|---|
| 整體 | `整體 RTP` | 全部 spin | 只判 `0 ≤ x < 100%` |
| ~50 | `前 50 次 Spin` | 每位玩家第 1～50 轉 | 只判 `0 ≤ x < 100%` |
| ~200 | `前 200 次 Spin`（或 `前 100 次 Spin`） | 每位玩家第 1～200 轉 | 只判 `0 ≤ x < 100%` |
| **OG ~200** | `RTP <=200`（或 `<=100`） | **新手期**（≤200 轉） | **依目標值判定** |
| **OG 200~** | `RTP >200 以後` | **老手期**（>200 轉） | **依目標值判定** |

前三欄是觀察用，只確認沒有爆掉。真正的目標值判定只做後兩欄。

因為報表本身已經把新手期與老手期分開，**逐欄各判自己的目標值，不需要做加權平均**。

每一欄都有三個 RTP：`Game RTP`、`Jackpot RTP`（＝Link）、`Bonus Game RTP`（＝Bonus）。

**SettingID RTP：機制拆分**

各機制的 RTP 貢獻由 SettingID 分開列出：

| SettingID | 名稱 | 歸屬 |
|---|---|---|
| 1 | 一般（沒有機制） | 自然結果基準 |
| 2, 4, 5, 6, 7, 8 | 新手救援、新手體驗 D（新手體驗 FG）、新手 mini game 體驗 D（新手體驗 JP）等 | **新手體驗**，取 Game RTP **加總** |
| 3 | 老手救援 | **老手救援**，取 Game RTP |

**新老手模式的區分**

`OldHand Init` 決定這次壓測玩家的起始身分：

| `OldHand Init` | 模式 | 玩家歷程 | OG ~200 欄的目標 |
|---|---|---|---|
| `disabled` | **新手** | 從第 1 轉開始，≤200 轉是新手期 | 新手目標（93%） |
| `enabled` | **老手** | 玩家一開始就是老手 | 老手目標（92% 或 94%） |

若 `OldHand Init` 欄位缺漏，退而用「Jackpot RTP 是否 > 0」推斷（老手才會有 Link 收入）。這是備援，不是正規判斷依據。

### 2.2 壓縮檔：RTP Validator TXT

ZIP／RAR 壓縮檔內是 **RTP Validator** 的逐分支 TXT（每個 `Coin in` × `WTIdx` 一個資料夾）。它不是判定的主報表，但提供了統計判定需要的關鍵資料：

| 欄位 | 用途 |
|---|---|
| `pool[n] hit = N, ttlWin = X, avg = Y, rtp = Z` | 各彩金獎級的命中次數與 RTP，用於硬檢查及異常追查 |
| `TotalSpin`、`TotalBet`、`currency denom` | 樣本量與押注換算 |

`pool[n] rtp` 的分母是**基準押注**（`default_coin_in`，H026 為 100），不是該次的實際 `Coin in`。所以同一個 pool 的 rtp 在不同押注下應該一致，這本身就是一項檢查。

## 三、壓測標準

### 3.1 目標值

#### 3.1.1 Game RTP

| 模式 | 押注範圍 | OG ~200（新手期） | OG 200~（老手期） |
|---|---|---:|---:|
| 新手（`OldHand Init = disabled`） | `x < 2` | 93% | 94% |
| 新手 | `2 ≤ x` | 93% | 92% |
| 老手（`OldHand Init = enabled`） | `x < 2` | 94% | 94% |
| 老手 | `2 ≤ x` | 92% | 92% |
| Buy／Super Feature | 全部 | 92.5% | 92.5% |

`x` 為報表中的實際押注 `Bet`。一般模式直接判斷 `x`；BF／SF 以 `x ÷ 模式倍率` 判斷基礎面額。

#### 3.1.2 Link 與 Bonus

| 模式 | 押注範圍 | Link OG ~200 | Link OG 200~ | Bonus 兩欄 |
|---|---|---:|---:|---:|
| 新手 | `x < 2` | 0% | 0% | 2% |
| 新手 | `2 ≤ x` | 0% | 2% | 2% |
| 老手 | `x < 2` | 0% | 0% | 2% |
| 老手 | `2 ≤ x` | 2% | 2% | 2% |
| Buy／Super Feature | `x < 模式倍率 × 2` | 0% | 0% | 4% |
| Buy／Super Feature | `模式倍率 × 2 ≤ x` | 老手 2%／新手 0% | 2% | 老手 2%／新手 4% |

**Link 目標為 0% 時必須精確等於 0%**，不套用任何容許範圍 — 這是規則問題不是精度問題（小 Bet 不能拉 Link、新手期不能拉 Link）。

#### 3.1.3 機制目標

| 項目 | 來源 | 目標 | 判定欄 |
|---|---|---:|---|
| 新手體驗 | SettingID 2, 4, 5, 6, 7, 8 的 Game RTP 加總 | 1% | OG ~200 |
| 老手救援 | SettingID 3 的 Game RTP | 1% | OG 200~ |

機制依〈3.2 判定方式〉判定；目標為 0% 時必須精確等於 0%。

> 注意：老手救援 B 版的返還公式為 `(0.95 − Total Win / Total Bet) × Total Bet`
> （機制說明書 3.2.4），是補到 RTP 95%，而觸發門檻只要 `RTP < 50%`。
> 機制說明書 3.2.9 已標註「返還目標寫 55% 但公式是 95%，兩者不一致」。
> 因此 1% 這個目標在 B 版下是否成立需要實測確認，見〈待確認事項〉。

### 3.2 判定方式

各項目以〈3.1 目標值〉中的目標為基準，容許範圍如下：

| 項目 | 容許範圍 |
|---|---:|
| Game RTP | 目標值 ±0.5 個百分點 |
| Bonus Game RTP | 目標值 ±0.5 個百分點 |
| Link（Jackpot RTP） | 目標值 ±1.5 個百分點 |
| 新手體驗／老手救援機制 | 目標值 ±1.5 個百分點 |

**目標值為 0% 時不套用容許範圍，實測值必須精確等於 0%；只要出現任何數值就判定失敗。**

### 3.3 硬檢查

不涉及統計容差，不符合就是錯：

| 檢查項 | 條件 |
|---|---|
| 小 Bet 不可拉 Link | 小 Bet 所有欄的 `Jackpot RTP` 必須為 0，且 `pool[1]`、`pool[2]` 的 hit 必須為 0 |
| 新手期不可拉 Link | 新手模式的 `OG ~200` 欄 `Jackpot RTP` 必須為 0 |
| 前三欄範圍 | `整體`／`~50`／`~200` 的 Game RTP 必須 `0 ≤ x < 100%` |
| RTP 拆解 | `Game RTP + Jackpot RTP + Bonus Game RTP` 須等於總 RTP（浮點誤差內） |
| 上限倍數 | 各分級的實際開出最大倍數不得超過數學文件「倍率線型」所定義的上限 |
| BG Trigger Cap | BG 進 FG 的最大倍數不得超過同 Profile 的 BG Trigger Cap |
| Scatter Pay | 遊戲無 Scatter Pay 時對應欄位必須為 0 |
| `pool[n] rtp` 一致性 | 同一個 pool 的 rtp 在不同 `Coin in` 下應一致（分母是基準押注，與實際押注無關） |
| Bet Mode 對應 | 判定用的目標必須依 `extraBet` 決定，不可只看 `Coin in` |

### 3.4 實測參考值（H026）

以下依目前〈3.2 判定方式〉整理 H026 的判定範圍。其他遊戲若目標值相同，可使用相同容許範圍；押注分級與上限倍數仍須依各遊戲文件判定。

#### 3.4.1 各項目通過範圍

| 項目 | 目標值 | 通過範圍 |
|---|---:|---:|
| Game RTP（一般模式新手期） | 93% | 92.5%～93.5% |
| Game RTP（老手低押注） | 94% | 93.5%～94.5% |
| Game RTP（老手中／大押注） | 92% | 91.5%～92.5% |
| Game RTP（Buy／Super Feature） | 92.5% | 92.0%～93.0% |
| Bonus Game RTP | 2% | 1.5%～2.5% |
| Bonus Game RTP | 4% | 3.5%～4.5% |
| Link（Jackpot RTP） | 2% | 0.5%～3.5% |
| Link（Jackpot RTP） | 0% | **必須精確等於 0%** |
| 新手體驗／老手救援機制 | 1% | 0%～2.5% |
| 未配置的機制 | 0% | **必須精確等於 0%** |

機制目標 1% 套用 ±1.5pp 後，數學下限為 −0.5%；RTP 不會小於 0%，因此實際通過範圍寫為 0%～2.5%。

#### 3.4.2 已知實測案例

| 項目 | 實測值 | 目標值 | 差異 | 判定 |
|---|---:|---:|---:|---|
| H026 `NoExtraBet`、`Coin in = 500`、老手 Game RTP | 93.4111% | 94% | −0.5889pp | ❌ 超出 ±0.5pp |
| H026 Bonus Game RTP（已知 12 次實測範圍） | 1.970%～2.033% | 2% | −0.030pp～+0.033pp | ✅ 落在 1.5%～2.5% |

#### 3.4.3 Pool 獎級對照

| pool | 獎級 | 倍率（相對基準押注 100） | 理論 RTP | 歸屬 |
|---|---|---:|---:|---|
| pool[1] | Grand | 約 18,000x ～ 20,000x（累進，會變動） | 1% | Link |
| pool[2] | Major | 約 9,500x ～ 10,200x（累進，會變動） | 1% | Link |
| pool[3] | Minor | 50x（固定） | 0.8% | Bonus |
| pool[4] | Mini | 10x（固定） | 1.2% | Bonus |

`pool[1]` 最大、`pool[4]` 最小。`Jackpot RTP` = pool[1] + pool[2]；`Bonus Game RTP` = pool[3] + pool[4]。

### 3.5 檢查清單

#### 3.5.1 前置

- [ ] 已記錄玩家數、每人把數、`N`。
- [ ] 每人把數 ≥ 600（老手救援 B 至少 2 個完整返還區間）。
- [ ] 已取得 `currency denom` 與該遊戲的大 Bet 門檻、上限倍數。
- [ ] 已取得該遊戲各模式的押注倍率，並產生完整測項清單。
- [ ] 每個測項都有對應的 `Formal RTP Report`。

#### 3.5.2 判定資料

- [ ] 每格的 Game／Link／Bonus 目標值與實測值都已取得。
- [ ] 新手體驗與老手救援機制的目標值與實測值都已取得。
- [ ] 所有差異都以百分點（pp）記錄。
- [ ] 各 pool 的 `hit` 已取得，供硬檢查與異常追查。

#### 3.5.3 判定

- [ ] 前三欄 Game RTP 都在 `0 ≤ x < 100%`。
- [ ] `OG ~200` 與 `OG 200~` 的 Game／Link／Bonus 都已逐項判定。
- [ ] Game／Bonus 都在目標值 ±0.5pp 內。
- [ ] Link／機制都在目標值 ±1.5pp 內。
- [ ] 所有目標為 0% 的項目都確認精確為 0%。
- [ ] 硬檢查全部通過。

#### 3.5.4 紀錄

- [ ] 通過的測項已記錄 `Report ID`、時間、目標值、實測值與差異。
- [ ] 未跑的測項已列出並註明原因。
- [ ] 警示與異常都有結論或追查方向。

### 3.6 常見異常與處置

| 現象 | 可能原因 | 處置 |
|---|---|---|
| Game 超出目標 ±0.5pp，且各押注同方向 | 設定或口徑錯誤 | 追查 Config 家族、Profile、押注分級是否套錯 |
| Game 超出目標 ±0.5pp，但只有一格 | 該格設定單獨出錯 | 檢查該 `Coin in` 的 WTIdx／Config 對應 |
| Link 超出目標 ±1.5pp | 彩金設定、獎額或權重異常 | 追查 `pool[1]`／`pool[2]` 設定 |
| Link > 0% 但目標 0% | Bet 分級或 Link 資格設定錯 | **硬性錯誤**，直接退回 |
| Bonus 超出目標 ±0.5pp | Bonus 權重或獎額異常 | 追查 `pool[3]`／`pool[4]` 權重與獎額 |
| 機制超出目標 ±1.5pp | 新手體驗或老手救援設定異常 | 追查對應 SettingID 的設定與觸發狀況 |
| `pool[n] rtp` 隨 `Coin in` 變動 | 彩金分母口徑錯 | 追查後端 rtp 計算 |
| 缺某個測項 | 該組合未納入本批壓測 | 列入待跑，不得視為通過 |
| `OldHand Init` 缺漏 | 報表欄位不全 | 用 Link > 0 推斷並在報告註明，或要求重出報表 |

---

## 四、建議作法

**建議每人 600 把以上**，讓老手救援 B 至少有 2 個完整返還區間。500 把只有 1 個完整區間，救援樣本偏少。
