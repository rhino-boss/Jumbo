Reskin 數學模型規範

本文件屬於 專案需知/Reskin/，適用於 Reskin 產線：以既有 Omniplay 遊戲數學為底，換皮輸出到 Reskin（SC／GC 雙幣）與 Vietnam 等市場的版本。

本文件採差異式撰寫：只列 Reskin 產線與 Omniplay 不同或新增的規則；凡本文件未覆寫的條款，一律沿用 Omniplay 的 數學模型規範.md。兩者衝突時以本文件為準。

1. 定位與範圍

  • Reskin 不重新設計數學：輪帶、Paytable、Feature 流程、倍率權重沿用來源遊戲的正式版本（ParSheet ID 不變），只調整押注結構、幣別與市場相關參數。
  • 來源遊戲的數學版本必須記錄於 Game Description 工作表（ParSheet ID、基礎數學版本、RTP／Variant 四碼版本）；Reskin 版不得回頭修改來源數學。若市場需求迫使改數學（例如最大賠付限制），依 Omniplay 第 1.3 節升版並回寫來源遊戲，不得只在 Reskin 版分叉。
  • 目前已定義的市場：Reskin（SC／GC）、Vietnam。新增市場時在第 3 節補一節，並同步更新 Config。

2. 押注結構

押注金額由三個參數相乘，不直接列舉金額：

押注金額 = 最小押分（credits）× Denom × Bet Multiplier
最小押分 = 100 credits（所有市場固定）
參數定義由誰決定
最小押分1 倍押注的 credit 數，固定 100產線共用
Denom每 credit 的幣值，依市場／幣別不同市場設定（第 3 節）
Bet Multiplier押注倍數選項，1～1000 共 44 組產線共用（第 2.1 節）

4. 數學模型與 Config 的要求

  • 數學模型 XLSX 的押注相關工作表以 Bet Multiplier 為單位列示（1 倍、EB 倍數、BF／SF 價格倍數），不以任何一種幣值列金額；幣值金額只在 Game Description 以「Denom × 倍數」舉例。
  • Config 必須分開存放：bet_multipliers（44 組共用表）、各市場的 denom 與 min_credits = 100、各市場啟用的倍數子集；不得把 SC／GC／Vietnam 的金額清單各寫一份。
  • 押注層級（Omniplay 第 1.4.3 節的 bet_tier_amount）在 Reskin 市場如何換算成美元門檻，待確認（第 7 節）；確認前 Config 不得寫死 $2／$100 門檻，須以參數提供。
  • GC 無現金價值，SC 可兌換；兩幣別是否共用同一套 RTP、Card System Profile 與 Link 資格，待確認；確認前模型對兩幣別使用相同數學，只有 Denom 不同。
  • 系統最大賠付：以各市場最大押注 × Max Multiplier 驗算，超出該市場系統上限者調低倍率上限或裁掉高倍數選項，並在數學文件明記；各市場上限值待確認。
  • Simulator 的 BATCH_RUNS 押注檔位自動選組（模擬程式規範 §3.2.3）必須能依市場的 Denom 與倍數子集產生檔位；報表要標示市場與幣別。

6. 開發前檢查

  • ☐ 來源遊戲的 ParSheet ID 與數學版本已記錄於 Game Description，Reskin 版未改動輪帶、Paytable、權重。
  • ☐ 押注以 100 credits × Denom × Bet Multiplier 計算；Config 存共用倍數表與各市場 Denom／子集，未寫死金額清單。
  • ☐ SC／GC／Vietnam 的押注清單與第 3 節逐檔一致（GC 以 v2 44 檔為準）。
  • ☐ 各市場 最大押注 × Max Multiplier 已驗算，GC 大數值的顯示與欄位不溢位。
  • ☐ 押注層級門檻、Link 資格、系統上限等待確認項已取得答案或以參數保留。
  • ☐ Omniplay 第 1.6 節其餘檢查項目全部通過。
