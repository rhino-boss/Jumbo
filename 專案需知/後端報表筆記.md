# 後端報表筆記

這份筆記說明**後端 SPS（RTP Validator）逐分支 TXT 報表**怎麼讀、怎麼換算成 Simulator 的指標、怎麼拿來核對倍率權重。

它與 [壓測說明書](壓測說明書.md) 的分工：

| 報表 | 內容 | 用途 | 說明文件 |
|---|---|---|---|
| TG `Formal RTP Report` | 固定玩家數 × 把數的玩家歷程 RTP | 新老手切換與機制介入後的 RTP 判定 | [壓測說明書](壓測說明書.md#二壓測報表) |
| **SPS 逐分支 TXT**（ZIP／RAR） | 每個 `BetType` × `Coin in` × `WTIdx` 一份統計 | **核對後端是否套對權重表、Card System 是否與 Simulator 一致** | 本文件 |

SPS 報表固定一張權重表跑到底，不經過新老手切換與機制介入，所以可以直接和 Simulator 的 Card-On 報表、倍率權重工作簿逐格比對。

## 一、檔案結構與命名

壓縮檔內每個分支一個資料夾，資料夾內一份 TXT（檔名為時間戳記，無意義）：

```text
JHS<GameID>_<BetType>_Null_<Coin in>_WTIdx_<n>/<時間戳記>.txt
```

| 片段 | 意義 | 範例 |
|---|---|---|
| `<GameID>` | 遊戲編號 | `101027` |
| `<BetType>` | 押注模式（見下表） | `NoExtraBet` |
| `<Coin in>` | 該分支每轉實際押注（coin 單位） | `5000` |
| `WTIdx_<n>` | 權重表索引（WeightTableIdx），對應哪一組 Profile／版本由後端設定，**每款遊戲要先確認** | `WTIdx_2` |

### 1.1 BetType 對應

| BetType | 押注模式 | 模式倍數 |
|---|---|---:|
| `NoExtraBet` | Normal Bet（NB） | 1 |
| `ExtraBet_PowerUp` | Extra Bet（EB） | 依遊戲（H027 為 2） |
| `ExtraBet_BuyFreeGame` | Buy Feature（BF） | 依遊戲（H027 為 100） |

### 1.2 Coin in → Config

```text
實際押注（$）＝ Coin in × currency denom
基礎押注（$）＝ 實際押注 ÷ 模式倍數
```

再依 [數學模型規範 §1.4.3](數學模型規範.md#143-押注模式分類與層級判定) 決定押注層級：

- NB／EB 用**實際押注**判 `< $2`／`$2～$100`／`> $100`。
- BF／SF 用**基礎押注**判同一組邊界。
- 小 Bet → 94 版；中 Bet → 92 版；大 Bet → 92_Bet100 版。

檔頭的 `betMultiplier` 是基礎押注對 `default_coin_in` 的倍數，可用來交叉核對：`基礎押注 = betMultiplier × default_coin_in × currency denom`。

### 1.3 WTIdx 對應

WTIdx 的順序由後端決定，沒有固定規則。拿到報表後先用數據反推並向後端確認：

- **Newbie 與 Oldhand**：看 BG 有次數的最高區間（Newbie 受 BG 倍率上限限制，如 30x）。
- **A 版與 B 版**：看 BG 最高區間、`BG WheelTable` 的選表比例（應接近該版 Parameter 的選表權重）。
- 推得的對應要與後端設定表一致，不一致時以後端設定為準並回報差異。

## 二、檔頭欄位

```text
BetType = NoExtraBet
WeightTableIdx = 0
version = H027192:A-7.0.0.0 B-7.0.0.0/H027194:A-7.0.0.0 B-7.0.0.0 GameID = 101027, JP optionID = 28, Coin in = 5000, currency denom = 0.002000, betMultiplier = 50, ...
TotalSpin = 10000000, TotalBet = 50000000000
```

| 欄位 | 意義 | 檢查 |
|---|---|---|
| `BetType`、`WeightTableIdx` | 同資料夾名稱 | 與資料夾名稱一致 |
| `version` | 後端載入的各 RTP／Variant 模型版本 | **必須等於各倍率權重工作簿 `Overview!B3`** |
| `JP optionID` | OP Jackpot 設定編號 | 與上線設定一致 |
| `Coin in`、`currency denom` | 見 §1.2 | — |
| `TotalSpin` | 付費轉數（樣本量） | — |
| `TotalBet` | 總押注（coin），＝ `TotalSpin × Coin in` | 不等時代表有中途改押 |

## 三、報表區段

| 區段 | 內容 | 用途 |
|---|---|---|
| `Total RTP` | `BaseGameRtp`、`ScatterRtp`、`FreeGameRtp`、`TotalRtp (excluding JP/bonus)`、`BonusJP Rtp`、`LinkJP Rtp` | RTP 對帳 |
| `BaseGame info` | `BaseGameTTLWin`、`BG SymbolHit[符號][連線長度]`、`BG WheelTable[n] Count`（BG 選表次數）、`BG FeatureHit[n]` | 選表比例、符號命中 |
| `FreeGame info` | `FreeGameTTLRound`（免費轉總數）、`FreeGameTTLWin`、`FG SymbolHit`、`FG Wheel Table` | FG 場次與得分 |
| `JP info` | `pool[n] hit / ttlWin / avg / rtp`、`JPTotalRound`、`avgPeriod` | JP 硬檢查（見 [壓測說明書 §2.2](壓測說明書.md#22-壓縮檔rtp-validator-txt)） |
| `BaseGame 倍數` | 每轉 BG 得分的分桶次數與 Pay；**不含觸發 FG 的那一轉** | BG 線型核對 |
| `BaseGame 進 FreeGame 倍數` | 只統計觸發 FG 那一轉的 BG 得分 | 觸發轉天花板、扣除觸發轉 |
| `整場FreeGame 倍數` | 每一場 FG（整場總分）的分桶次數與 Pay | FG 線型核對 |
| `FreeGame 單round 倍數` | 每一個免費轉的得分分桶 | 參考 |
| `by Game Data` | 消除次數、`BGtableWin[n]`（各選表總得分）、`Freegame Count`（FG 場數）、`bgC1Count`／`fgC1Count`（每轉特殊符號數量分布） | 觸發率、SCR 參考 |
| `Base Game RNG INFO`、`FreeGame RNG INFO` 等 | 後端 RNG 除錯資料 | 不用於判定 |

**分桶標籤**：`Nx` 代表區間 `(N, 下一個標籤]`，`00` 代表 0 分。例如 `BaseGame 10x` 是 `(10, 15]`，`BaseGame 0x` 是 `(0, 1]`。標籤與 [數學模型規範 §1.5](數學模型規範.md) 的 64 格線一一對應。

各分桶列後面的 `1C1`～`5C1` 欄依特殊符號數量拆分次數，目前未用於判定。

## 四、指標換算

| Simulator 指標 | SPS 換算 |
|---|---|
| 總 RTP（不含 JP） | `TotalRtp (excluding JP/bonus)` ＝ `BaseGameRtp + ScatterRtp + FreeGameRtp` |
| BG RTP | `BaseGameRtp + ScatterRtp`（Scatter 賠付屬 BG；BF 的入場轉也記在 `ScatterRtp`） |
| FG RTP | `FreeGameRtp` |
| BG Hit Rate | `1 − BaseGame 00 ÷ TotalSpin` |
| FG 觸發率 | `Freegame Count ÷ TotalSpin` |
| 平均 FG 轉數 | `FreeGameTTLRound ÷ Freegame Count` |
| FG 平均倍數（基礎投注口徑） | `FreeGameTTLWin ÷ Freegame Count ÷ Coin in × 模式倍數` |
| 區間平均倍數（基礎投注口徑） | `Pay ÷ 次數 ÷ Coin in × 模式倍數` |
| JP RTP | `BonusJP Rtp`、`LinkJP Rtp` |

**SCR**：SPS 沒有直接輸出 SCR。可用 `(bgC1Count ≥1 的次數 ＋ fgC1Count ≥1 的次數) ÷ TotalSpin × 10¹⁰` 近似，但**計數定義尚未與 Simulator 對齊**（H027 實測 NB／EB 低約 1%，BF 高約 13%），所以 OP Jackpot 的 SCR 一律用 Simulator Card-On 報表的值，不用 SPS 推算值。

## 五、倍率權重核對方法

### 5.1 BG

`BaseGame 倍數` 區段**已排除觸發 FG 的那一轉**，與 [模擬程式規範 §3.1.4](模擬程式規範.md#314-輸出報表) 的 BG 統計口徑相同，直接比對即可，不要再扣一次：

```text
BaseGame 00 次數 ＋ 各桶次數 ＋ Freegame Count ＝ TotalSpin
BaseGame 倍數 Pay 合計 ＋ BaseGame 進 FreeGame 倍數 Pay 合計 ＝ BaseGameTTLWin
```

1. 每桶占比 ＝ 次數 ÷ `TotalSpin`，對應倍率權重工作簿 `Multiplier_Weight` 的 BG 欄（權重 ÷ 10⁹）。
2. `BaseGame 00` 占比對應 `(-1, 0]`；Free Game 列對應 `Freegame Count ÷ TotalSpin`。
3. `BaseGame 進 FreeGame 倍數` 只用來檢查觸發轉的 BG 得分有沒有超過 BG Trigger Cap。

### 5.2 FG／BF

`整場FreeGame 倍數` 各桶次數 ÷ 總場數，對應 FG 欄（BF 對應 BF 欄）。

### 5.3 判定

| 項目 | 標準 |
|---|---|
| 總 RTP（不含 JP） | `σ = volatility_std ÷ 模式倍數 ÷ √TotalSpin`，**\|實測 − 目標\| ≤ 2σ**；`volatility_std` 取同 Config／Profile／模式的 Simulator Card-On 報表 |
| 有權重的區間 | `z = (實測占比 − 權重) ÷ √(權重 × (1 − 權重) ÷ N)`，**\|z\| ≤ 3** |
| 權重為 0 的區間 | 次數必須為 0（超限保留最後結果的情況除外，數量須 ≤ Retry 超限次數） |
| 最高／最低有次數的區間 | 與權重表的最高／最低有權重區間相同（樣本太少時最高區間可能沒抽到） |
| 觸發轉 BG 得分 | 不得超過 Config `free_game` 卡的 `max`（BG Trigger Cap） |
| 區間平均倍數 | 與 `Avg_Multi` 工作表相近；差異大時代表區間內條件分布不同 |

N 為該欄的總樣本數（BG 用 `TotalSpin`，FG 用總場數）。Simulator 的 `volatility_std` 以 Normal Bet 基準成本計，換成 RTP 的 σ 時必須除以模式倍數（EB ÷2、BF ÷100），漏除會讓 EB／BF 的 σ 被高估、偏差看起來比實際小。單一報表 64 格同時檢定，偶有一兩格 |z| 落在 3 附近屬正常；多格同向偏離才是問題。

## 六、檢查清單

- [ ] 資料夾數量 ＝ BetType × Coin in × WTIdx 的必跑組合，沒有缺漏
- [ ] `version` 等於所有倍率權重工作簿的 `Overview!B3`
- [ ] WTIdx 對應的 Profile／版本已和後端確認
- [ ] 每個 Coin in 落在預期的押注層級，套用預期的 config（92／94／Bet100）
- [ ] 各區間占比、上下限、權重 0 區間依 §5.3 通過
- [ ] Newbie 觸發轉的 BG 得分沒有超過 BG 上限
- [ ] 總 RTP、BG／FG RTP、BG Hit Rate、FG 觸發率與 Simulator Card-On 報表在抽樣誤差內一致
- [ ] 若 RTP 系統性偏低，先對照 Simulator 的 Retry 超限次數，再查後端重抽上限是否與 Config `retry_limit` 相同
- [ ] JP 依 [壓測說明書 §3.3](壓測說明書.md#33-硬檢查) 硬檢查

## 七、實例：H027 v7（2026-10-05）

壓縮檔 `101027_AB版.rar`，32 份報表，每份 NB／EB 10⁷ 轉、BF 10⁶ 次。

### 7.1 Coin in 對應

`currency denom = 0.002`，`default_coin_in = 100`。

| BetType | Coin in | 實際押注 | 基礎押注 | 押注層級 | Config |
|---|---:|---:|---:|---|---|
| `NoExtraBet` | 500 | $1 | $1 | 小 Bet | 94 |
| `NoExtraBet` | 5,000 | $10 | $10 | 中 Bet | 92 |
| `NoExtraBet` | 750,000 | $1,500 | $1,500 | 大 Bet | 92_Bet100 |
| `ExtraBet_PowerUp` | 1,000 | $2 | $1 | 中 Bet（依實際押注） | 92 |
| `ExtraBet_PowerUp` | 10,000 | $20 | $10 | 中 Bet | 92 |
| `ExtraBet_PowerUp` | 1,500,000 | $3,000 | $1,500 | 大 Bet | 92_Bet100 |
| `ExtraBet_BuyFreeGame` | 50,000 | $100 | $1 | 小 Bet（依基礎押注） | 94（BF 權重 92＝94 共用） |
| `ExtraBet_BuyFreeGame` | 500,000 | $1,000 | $10 | 中 Bet | 92 |

EB $2 那組實測 FG RTP 約 49.8%，是 92 家族水準，確認後端用實際押注分層。此批沒有 BF 大 Bet（基礎押注需 > $100，即 Coin in > 5,000,000）。

### 7.2 WTIdx 對應

| WTIdx | 對應 | 反推依據 |
|---|---|---|
| 0 | A 版 Newbie | BG 最高 30x、選表 (3) 約 17% |
| 1 | B 版 Newbie | BG 最高 30x、選表比例同 B |
| 2 | A 版 Oldhand | BG 最高 (200, 250] |
| 3 | B 版 Oldhand | BG 最高 (1000, 2000] |

### 7.3 核對結果

| 項目 | 結果 |
|---|---|
| 版本字串 | `H027192:A-3.1.0.0`，其餘 7.0.0.0；數據內容是 v7，屬版號未更新 |
| 區間分布 | 64 區間與 v7 權重一致；BG 各桶差 ≤ 0.015 pp，FG 最大 \|z\| ≤ 3.0，上下限全對 |
| BG Hit Rate、FG 週期、FG 均倍 | 全部在抽樣誤差內（28.17～28.23%、NB 1/444～456、EB 1/90） |
| Newbie、BF RTP | 16 組只有 A Newbie NB $10 偏 +2.1σ，其餘 ≤ 1.9σ |
| Oldhand NB RTP | 6 組都在 2σ 內，但 5 組偏低，與 Simulator 的 Retry 超限方向一致 |
| Oldhand EB RTP | A 三組 −2.2～−2.6σ、B $20 −3.6σ；BG 高倍桶 \|z\| 到 4.3，屬 Retry 超限造成的高倍桶不足 |
| Newbie 觸發轉 | 12 組全部有觸發轉 BG 得分超過 30x（每組 13～125 次，約 0.06～0.11% 的觸發），違反 `free_game` 卡 `max = 30` |
| SCR | SPS 推算值與 Simulator 不一致（見 §4），OP Jackpot 仍用 Simulator 值 |
| JP | EB 的 `BonusJP Rtp` 約 0.1%，NB 約 2%，待後端確認 JP 設定是否刻意 |
