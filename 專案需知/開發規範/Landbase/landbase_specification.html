Landbase 轉製 系統機制

本頁說明 Landbase 轉製遊戲的新手體驗與系統限制。RTP 配置與 Link 彩金見數學模型規範。

1. 新手體驗

轉製遊戲使用新手體驗 D 版，轉製時要用到的規則如下。

1.1 救援倍數

新手體驗預設給出下列倍數（可依遊戲調整），轉製遊戲必須能產生這些結果：

判定救援倍數
第一次15×
第二次強 30×／弱 15×

1.2 轉製遊戲要注意的地方

  • 只給新手 Profile，RTP 預算 2.00%。
  • 新手 Total RTP 97.00% ＝ Game 95.00% ＋ 新手體驗 2.00%；數學模型只負責 Game RTP，新手體驗的派彩計算與驗證時必須和 Game RTP 分開統計。
  • 遊戲必須能在判定回合產生上表倍數（預設 15× 與 30×）的結果，且演出與自然得分無法區分；做法依腳本規範的新手體驗腳本，或由 Card System 重骰產生。
  • 新手期不得拉 Link 彩金（第 2 節），新手體驗給出的得分也不得觸發 Link 事件。

  • ☐ 新手（含 BF／SF）與低注的 Link RTP 為 0%，且結果中無已觸發但不派彩的 Link 事件。
  • ☐ 倍率上限已依天花板說明驗算（BG、FG、系統賠付上限）並記錄。

天花板說明

本文件屬於 專案需知/ 專案需知文件集，總覽、共通原則與完成條件見 _README.md。

天花板是系統對派彩金額設的上限。超過上限的結果整把重骰：重骰後該結果不會出現，不是把派彩截到上限。數學模型、Config、Simulator 與 Demogame 必須實作同一套天花板。

1. 金額上限

範圍押注 <= $1,500押注 > $1,500超過時
單把 BG 派彩$500,000$1,000,000整把重骰
單場 FG 派彩$2,000,000$5,000,000整把重骰
系統賠付上限（單把總派彩）$10,000,000$10,000,000整把重骰
  • 押注 $1,500 屬於低的那一級；只有大於 $1,500 才適用 $1,000,000／$5,000,000。

各押注層級使用的模型與天花板：

押注層級押注金額 x使用模型BG 天花板FG 天花板
小 Betx < $294 版$500,000$2,000,000
中 Bet$2 <= x <= $10092 版$500,000$2,000,000
大 Bet$100 < x <= $1,50092_Bet100 版$500,000$2,000,000
超大 Betx > $1,50092_Bet100 版（與大 Bet 共用）$1,000,000$5,000,000
  • 超大 Bet 不另做模型，與大 Bet 共用 _Bet100 權重，只有天花板較寬；所以 _Bet100 權重必須同時通過大 Bet（以 $1,500 驗算）與超大 Bet（以遊戲最大押注驗算）兩組天花板，取較嚴者（見第 2 節）。
  • 押注金額的判定方式與數學模型規範.md第 1.7.1 節相同：NB／EB 用實際押注金額，BF／SF 用購買價格反推的基礎押注。
  • 系統賠付上限對所有押注一律 $10,000,000，是 BG、FG 上限之外的最後一道保護。

2. 對倍率上限的影響

每個押注層級的倍率上限必須讓該層最大押注踩不到天花板，否則高注玩家會實際觸發重骰、RTP 系統性偏低：

BG 倍率上限 × 該層最大押注 ≤ BG 上限
FG 倍率上限 × 該層最大押注 ≤ FG 上限
遊戲最大押注BG 上限BG 最高可填區間FG 上限FG 最高可填區間系統上限（單把總派彩）
$1,000$500,000 ÷ 1000 = 500x(450, 500]$2,000,000 ÷ 1000 = 2000x，但大 Bet 上限 1000x(950, 1000]$10,000,000 ÷ 1000 = 10000x
$1,500$500,000 ÷ 1500 = 333x(250, 300]$2,000,000 ÷ 1500 = 1333x，但大 Bet 上限 1000x(950, 1000]$10,000,000 ÷ 1500 = 6667x
$5,000（例：H026、H027、H028）$1,000,000 ÷ 5000 = 200x(180, 200]$5,000,000 ÷ 5000 = 1000x(950, 1000]$10,000,000 ÷ 5000 = 2000x
  • 配權重時以各卡片區間的上限驗算：區間上限 × 該層最大押注超過天花板的區間，不得配權重。例：$1,500 的 BG 上限是 333x，(300, 350] 的上限 350 已超過，所以 BG 只能填到 (250, 300]；押注開到 $5,000 時再取超大 Bet 的 200x，只能填到 (180, 200]。
  • 系統上限管的是 BG＋FG 加總：$5,000 時 200 + 1000 = 1200x，在 2000x 內不會擋到。
  • 大 Bet 共用同一套權重時，取該層所有押注中最嚴的一個；押注開到 $5,000 的遊戲，大 Bet 只能填到 BG (180, 200]、FG (950, 1000]。
  • 以 NB 驗算即可：EB 實際押注是 2 倍，落在較寬的那一級，算出來的上限只會更寬。
  • 計算結果比數學模型規範.md第 1.7.2 節的預設上限低時，以天花板推得的值為準，並記錄於數學文件；比預設高時（例：上表 $1,000 的 FG 2000x）仍以預設為準，大 Bet 一律不超過 1000x。
  • 押注跨越 $1,500 的遊戲，<= $1,500 與 > $1,500 要分開驗算。

3. 實作與驗證

  • Simulator 與 Demogame 必須實作相同的重骰，否則模擬結果與實際遊戲不一致。
  • 卡片系統的觸發局 BG 上限（數學模型規範.md第 2.3 節的天花板機制）是另一道限制，兩者同時成立。
  • 模擬報表要能看出重骰次數；重骰比例明顯不為 0 時，先檢查倍率上限與區間權重是否違反第 2 節。

4. 檢查清單

  • ☐ 各押注層級的 BG／FG 倍率上限已依第 2 節驗算並記錄於數學文件。
  • ☐ 超過天花板的卡片區間權重為 0。
  • ☐ Simulator 與 Demogame 已實作 BG、FG 與系統賠付上限的重骰。
  • ☐ 正式模擬的重骰次數為 0 或已說明原因。

腳本規範

本文件屬於 專案需知/ 專案需知文件集，總覽、共通原則與完成條件見 _README.md。

內容涵蓋：表演腳本（預錄結果腳本）的用途、清單結構、格式欄位、挑選規則、權重整合與交付檢查。

1. 用途與定位

表演腳本是預先錄製的 RNG 序列與固定結果，供前端在特定情境直接重放，用於新手體驗、Buy Feature 展示與 Free Spin 系統等。

  • 腳本只影響「被挑中的那幾局」的表演結果，不改變真實遊戲的數學模型、Config 與派彩公式。
  • 每支腳本的 RNG 序列必須能在該遊戲的正式輪帶／掉落設定下重放出相同結果；輪帶或掉落權重改版時，必須驗證既有腳本仍可重放，否則重錄。
  • 腳本表以遊戲為單位維護（每款一張，依 RTP 版型分組），欄位格式見第 3 節。

2. 腳本清單結構

依遊戲實際支援的押注模式建立；遊戲不支援的模式不得出現對應腳本。

新手體驗NB Jackpot Game A／B2OP Jackpot 小遊戲體驗，固定總倍率
新手體驗其他押注模式（EB 等）之 Free Game／Jackpot Game A／B依支援遊戲支援該模式才建立

4. 挑選規則

4.1 新手體驗

  • 每支權重＝1、押注＝1；同名 A／B 兩支等權重擇一。
  • 總倍率為體驗設計值，製作前與使用者確認（參考值：Free Game 12x、Jackpot Game 10x）。

4.2 Buy Feature

  • 每個版型三支：高／中／低 RTP 各一，另配抽選權重；押注＝Buy Feature 價格倍數。
  • 加權整合必須等於該遊戲 BF 的 RTP：Σ(RTP × 權重) ÷ Σ(權重) = BF RTP。BF RTP 取該遊戲數學模型規範的 BF／SF RTP 配置（有多個 RTP 版本時依版本）。
  • 三檔 RTP 先定，權重由上式解出並整數化；解出後驗算到小數 2 位精確。
  • 參考例（前作 92 版，當時 BF RTP 目標 96.00%）：105.67%×800＋88.80%×200＋81.53%×435 → 加權 96.00%。

4.3 Free Spin 系統

  • 適用新手 NB 的免費遊戲段（一段 10 把）。
  • 挑法：10 把中挑一把跑 0-1x 腳本、挑一把跑 9x 腳本，其餘各把不中獎。
  • 9x 腳本固定 10 支，抽選權重鎖死全部＝1（等權重擇一），不得調整。
  • 整段合計約 10x（參考值：0-1x＝44%＋9x＝955.56% → 999.56%）。

4.4 版型與共用

  • 腳本表依 RTP 版型分組（例：92 版一張）；同一支 RNG 序列若在多個 RTP 版可重放出相同結果，可跨版共用並註記。
  • 大額投注使用獨立模型（_Bet100）的遊戲：腳本倍率不得超過該模型的倍率上限（例：大 Bet BG／FG 上限 1,000x）。

5. 製作前確認

  1. 新手體驗涵蓋哪些押注模式（NB 以外是否含 EB／BF 體驗）。
  2. 各體驗腳本的目標倍率（Free Game／Jackpot Game）。
  3. 腳本表做哪些 RTP 版型、是否跨版共用。
  4. Buy Feature 三檔 RTP 的目標值（權重由「加權＝BF RTP」約束解出）。

6. 交付檢查

  • ☐ 腳本清單依第 2 節結構建立，未支援的模式沒有腳本。
  • ☐ 每支 RNG 序列已在正式 Config 下重放驗證，結果與表列 Multi 一致。
  • ☐ Buy Feature 各版型加權整合＝該遊戲 BF RTP（小數 2 位精確）。
  • ☐ Free Spin 系統：9x 腳本 10 支、權重全部＝1；0-1x 與 9x 各佔一把、其餘不中獎。
  • ☐ 腳本倍率未超出該模式（含 _Bet100 模型）的倍率上限。
  • ☐ 輪帶／掉落改版後已重新驗證重放（或重錄）。

7. 範例：H028 雷神爆金1000（101016）

支援 NB＋BF（無 Extra Bet），FG 觸發＝4 SC＝10 把：

類別腳本支數

    5. 倍率權重核對方法

    5.1 BG

    BaseGame 倍數 區段已排除觸發 FG 的那一轉，與 模擬程式規範 §1.1.4 的 BG 統計口徑相同，直接比對即可，不要再扣一次：

    BaseGame 00 次數 ＋ 各桶次數 ＋ Freegame Count ＝ TotalSpin
BaseGame 倍數 Pay 合計 ＋ BaseGame 進 FreeGame 倍數 Pay 合計 ＝ BaseGameTTLWin
    1. 每桶占比 ＝ 次數 ÷ TotalSpin，對應倍率權重工作簿 Multiplier_Weight 的 BG 欄（權重 ÷ 10⁹）。
    2. BaseGame 00 占比對應 (-1, 0]；Free Game 列對應 Freegame Count ÷ TotalSpin。
    3. BaseGame 進 FreeGame 倍數 只用來檢查觸發轉的 BG 得分有沒有超過 BG Trigger Cap。

    5.2 FG／BF

    整場FreeGame 倍數 各桶次數 ÷ 總場數，對應 FG 欄（BF 對應 BF 欄）。

    5.3 判定

    項目標準
    總 RTP（不含 JP）σ = volatility_std ÷ 模式倍數 ÷ √TotalSpin，**\實測 − 目標\≤ 2σ**；volatility_std 取同 Config／Profile／模式的 Simulator Card-On 報表
    有權重的區間z = (實測占比 − 權重) ÷ √(權重 × (1 − 權重) ÷ N)，**\z\≤ 3**
    權重為 0 的區間次數必須為 0（超限保留最後結果的情況除外，數量須 ≤ Retry 超限次數）
    最高／最低有次數的區間與權重表的最高／最低有權重區間相同（樣本太少時最高區間可能沒抽到）
    觸發轉 BG 得分不得超過 Config free_game 卡的 max（BG Trigger Cap）
    區間平均倍數與 Avg_Multi 工作表相近；差異大時代表區間內條件分布不同

    N 為該欄的總樣本數（BG 用 TotalSpin，FG 用總場數）。Simulator 的 volatility_std 以 Normal Bet 基準成本計，換成 RTP 的 σ 時必須除以模式倍數（EB ÷2、BF ÷100），漏除會讓 EB／BF 的 σ 被高估、偏差看起來比實際小。單一報表 64 格同時檢定，偶有一兩格 |z| 落在 3 附近屬正常；多格同向偏離才是問題。

    6. 檢查清單

    • ☐ 資料夾數量 ＝ BetType × Coin in × WTIdx 的必跑組合，沒有缺漏
    • ☐ version 等於所有倍率權重工作簿的 Overview!B3
    • ☐ WTIdx 對應的 Profile／版本已和後端確認
    • ☐ 每個 Coin in 落在預期的押注層級，套用預期的 config（92／94／Bet100）
    • ☐ 各區間占比、上下限、權重 0 區間依 §5.3 通過
    • ☐ Newbie 觸發轉的 BG 得分沒有超過 BG 上限
    • ☐ 總 RTP、BG／FG RTP、BG Hit Rate、FG 觸發率與 Simulator Card-On 報表在抽樣誤差內一致
    • ☐ 若 RTP 系統性偏低，先對照 Simulator 的 Retry 超限次數，再查後端重抽上限是否與 Config retry_limit 相同
    • ☐ JP 依 壓測說明書 §3.3 硬檢查

    Landbase 轉製 數學模型規範

    本頁說明 Landbase 轉製遊戲的數學模型與 Card System。新手體驗與系統限制見系統機制。

    1. 數學模型

    1.1 必要內容

    • 數學調性目前沒有明確方向，由負責人自由發揮（待討論）。
    • 自由發揮不代表免記錄。負責人決定調性後，必須在數學模型的 Game Description 工作表與 game_rule.md 寫明：
      • 以原機數學為底還是重新設計；若以原機為底，記錄原機 RTP（Game List 的「RTP 版本」欄，例：84%）與調整到線上目標 RTP 的方式（改輪帶、改 Paytable、Card System 或其他）。
      • 波動度／最大倍數目標與 Hit Rate 目標。
      • 是否啟用 Card System；啟用時依第 2 章。
    • 原機既有的 Bonus／Feature 玩法屬於 Game RTP 的一部分，不另拆 Bonus Game RTP（見第 1.3 節）。

    1.2 模型命名

    • Landbase 轉製遊戲的 ParSheet ID 仍為 H<三位數字>1；同一數學供多個 Game ID 使用時（如 H0111 → 102001／102002），數學模型只建一份，Game ID 對應記錄於 Game Description 工作表與 Game List。

    1.3 RTP 配置

    Total RTP = Link RTP + Game RTP + 新手體驗 RTP
    • 轉製遊戲不拆 Bonus Game RTP；試算表「轉製遊戲」欄的 Bonus／Game 為同一合併欄位，原機的 Bonus／Feature 派彩全部歸入 Game RTP。
    • 新手滾入彩池的 Increment 不計入新手 Total RTP；定義見第 1.4 節。
    • RTP ＝ Total Win ÷ 實際 Total Bet；產品顯示可四捨五入，但計算用完整精度；各 Bet Mode 分母用該模式實際成本。

    • 老手的押注層級只分 < $2／>= $2 兩級（低注／高注）；新手不分層級。
    • NB／EB 以該模式的實際押注金額判定；BF／SF 以 Feature 購買價格 ÷ Feature Price 倍數反推的基礎押注判定，不用購買總價。
    • 倍率上限依系統機制的系統最大賠付反推；Newbie 上限 BG 30x／FG 120x。

    2. Card System

    2.1 設定結構
