Landbase 轉製 導覽

本規範適用於 Landbase 轉製遊戲：實體機台數學轉製為線上版，Game List 備註「線上-Landbase轉製遊戲」者，例如 102xxx／105xxx。

Landbase 規範採差異式撰寫：只列 Landbase 產線與 Omniplay 不同或新增的規則。凡未覆寫的條款，一律沿用 Omniplay 的規範（數學模型規範.md、送驗文件規範.md 等）。兩者衝突時以 Landbase 規範為準。

RTP 配置與系統機制的正式來源為 Google 試算表 RTP 設定（數值設定、彩金參數 兩頁）。目前引用 2026/05/14「全平台」版的「轉製遊戲」欄；試算表更新時必須同步修訂並記錄日期。

Landbase Knowhow

本頁記錄 Landbase 轉製產線的市場與平台背景，作為數學設計的前提。

1. 市場與平台要求

項目內容
市場菲律賓
平台 RTP 要求同 Omniplay：Total RTP 須介於 96.5%～97%
  • 平台要求同 Omniplay Knowhow；Landbase 的 RTP 拆分見數學模型規範第 2 節。

Landbase 轉製 系統機制

本頁說明 Landbase 轉製遊戲的新手體驗與系統限制。RTP 配置與 Link 彩金見數學模型規範；未覆寫者沿用 Omniplay（見導覽）。

1. 新手體驗

轉製遊戲沿用 Omniplay 的新手體驗 D 版，完整說明見 機制說明.md。轉製時要用到的規則如下。

1.1 救援倍數

新手體驗預設給出下列倍數（可依遊戲調整），轉製遊戲必須能產生這些結果：

判定救援倍數
第一次15×
第二次強 30×／弱 15×

1.2 轉製遊戲要注意的地方

  • 只給新手 Profile，RTP 預算 2.00%。
  • 新手 Total RTP 97.00% ＝ Game 95.00% ＋ 新手體驗 2.00%；數學模型只負責 Game RTP，新手體驗的派彩計算與驗證時必須和 Game RTP 分開統計。
  • 遊戲必須能在判定回合產生上表倍數（預設 15× 與 30×）的結果，且演出與自然得分無法區分；做法依 Omniplay 腳本規範.md 的新手體驗腳本，或由 Card System 重骰產生。
  • 新手期不得拉 Link 彩金（第 2 節），新手體驗給出的得分也不得觸發 Link 事件。

2. 系統限制

限制規則
新手標籤玩家仍帶有新手標籤時，任何 Bet Mode（含 BF／SF）都不得拉 Link 彩金；不得因為購買 Feature 而繞過新手限制。
新手期新手期不得拉彩金，Link RTP 必為 0%；>= $2 時只滾 Inrc、不中彩。
低注bet_tier_amount < $2 不得拉 Link 彩金，新手、老手皆同；NB／EB 以實際押注、BF／SF 以反推基礎押注判定。
系統最大賠付單把派彩上限 $10,000,000，超過整把重骰。BG／FG 另有單把上限，規則見 Omniplay 天花板說明.md；數學模型必須依該文件驗算倍率上限，並在數學文件明記。
  • Link 資格一律由系統依 Profile 與 bet_tier_amount 判定；link_enabled = false 時不得只把派彩改成 0，結果中不得出現已觸發但不派彩的 Link 事件或演出（同 Omniplay 數學模型規範第 2.3.1 節）。

3. 檢查清單

  • ☐ 新手（含 BF／SF）與低注的 Link RTP 為 0%，且結果中無已觸發但不派彩的 Link 事件。
  • ☐ 倍率上限已依天花板說明驗算（BG、FG、系統賠付上限）並記錄。

Landbase 轉製 數學模型規範

本頁說明 Landbase 轉製遊戲的數學調性、RTP 配置、Link 彩金與數學模型的調整。新手體驗與系統限制見系統機制；未覆寫者沿用 Omniplay 數學模型規範.md（見導覽）。

1. 數學調性

  • 目前沒有明確方向，由負責人自由發揮（待討論）。
  • 自由發揮不代表免記錄。負責人決定調性後，必須在數學模型的 Game Description 工作表與 game_rule.md 寫明：
    • 以原機數學為底還是重新設計；若以原機為底，記錄原機 RTP（Game List 的「RTP 版本」欄，例：84%）與調整到線上目標 RTP 的方式（改輪帶、改 Paytable、Card System 或其他）。
    • 波動度／最大倍數目標與 Hit Rate 目標。
    • 是否啟用 Card System；啟用時依第 4 節。
  • 原機既有的 Bonus／Feature 玩法屬於 Game RTP 的一部分，不另拆 Bonus Game RTP（見第 2 節）。

2. RTP 配置

2.1 配置口徑

Total RTP = Link RTP + Game RTP + 新手體驗 RTP
  • 轉製遊戲不拆 Bonus Game RTP；試算表「轉製遊戲」欄的 Bonus／Game 為同一合併欄位，原機的 Bonus／Feature 派彩全部歸入 Game RTP。
  • 新手滾入彩池的 Increment 不計入新手 Total RTP；定義見第 3 節。
  • 其餘口徑（RTP ＝ Total Win ÷ 實際 Total Bet、產品顯示可四捨五入但計算用完整精度、各 Bet Mode 分母用該模式實際成本）沿用 Omniplay 數學模型規範第 1.4.1 節。

2.2 NB／EB RTP 配置

Player Profile押注層級判定金額Link RTPGame RTP新手體驗 RTPTotal (+機制)
新手不分層級全部0.00%95.00%2.00%97.00%
老手高注>= $22.00%95.00%0.00%97.00%
老手低注< $20.00%97.00%0.00%97.00%
  • 新手不分大小 Bet，只有一套 RTP：Link 0% ＋ Game 95% ＋ 新手體驗 2% ＝ 97%。
  • 老手的押注層級只分 < $2／>= $2 兩級，沒有 Omniplay 的小／中／大 Bet 三級與 > $100 門檻。
  • 老手 >= $2 的 Game RTP 比 < $2 低 2 個百分點，差額即 Link RTP，兩級 Total 相同。
  • 新手 Link RTP 皆為 0%；新手 >= $2 的 Increment 只滾入彩池、不可中彩（見系統機制的系統限制）。
  • 本表於 2026-10-05 調整，與試算表 2026/05/14 版不同；試算表更新後兩者須一致。

2.3 BF／SF RTP 配置

Player Profile押注層級判定金額Link RTPGame RTP新手體驗 RTPTotal (+機制)
新手不分層級全部0.00%96.50%0.00%96.50%
老手高注>= $22.00%94.50%0.00%96.50%
老手低注< $20.00%96.50%0.00%96.50%
  • BF／SF 的押注層級依 Omniplay 數學模型規範第 1.4.3 節，以 Feature 購買價格 ÷ Feature Price 倍數反推的基礎押注判定，不用購買總價。
  • BF／SF 的 Total RTP 為 96.50%（比 NB／EB 的 97% 低 0.5 個百分點），不含新手體驗。
  • 新手 BF／SF 與老手 < $2 相同：Link 0% ＋ Game 96.5% ＝ 96.5%；新手 BF 的 Link RTP 必為 0%。
  • 老手 >= $2 為 Link 2% ＋ Game 94.5% ＝ 96.5%；不是 Omniplay 的 Game 92.50% 固定值。

3. Link 彩金（Grand／Major）

Link 彩金為 Grand、Major 兩層累積彩池。配置跟該遊戲所在的賭場一致，不另訂（試算表 彩金參數 頁，2026/05/14）。

3.1 配置

賭場級距初始金額Startup%IncrementRTP
Online（小平台）Grand$100,0000.65%0.35%1.00%
Online（小平台）Major$20,0000.50%0.50%1.00%
OnlineGrand$500,0000.65%0.35%1.00%
OnlineMajor$100,0000.50%0.50%1.00%
  • 有 Link 的遊戲才依本表配置，沒有 Link 的遊戲不用此配置。
  • 賭場線上線下串連的配置不列入本表：若要讓某賭場的線上與線下（實體機台）彩金串在一起，線上的配置必須與該賭場線下一模一樣；而每款 Landbase 轉製遊戲在賭場的配置都不同，無法訂一套共用值。目前只有 MFB（Okada）一家賭場，所以真要串時先以 MFB 的配置為準（例：Grand $1,000,000／Startup 1.10%／Increment 0.20%／RTP 1.30%；Major $100,000／0.50%／0.20%／0.70%）；之後若不再有這需求就用不到，因此有要串時才依該遊戲、該賭場的配置另做。

3.2 欄位定義

欄位定義
初始金額彩池開出後重置的起始金額（Start Up Pool）
Startup%押注中用來補足初始金額的比例；Startup% = RTP − Increment
Increment押注中滾入彩池、讓彩池累積上漲的比例（試算表的 Inrc）
RTP該級距的彩金 RTP；RTP = Startup% + Increment
  • Grand ＋ Major RTP ＝ Link RTP 2.00%；表中兩種配置的 Increment 合計皆為 0.85%。
  • 平均開出金額：Average Jackpot Hit Value = 初始金額 ÷ Startup% × RTP。例：Online Grand ＝ $500,000 ÷ 0.65% × 1.00% ≈ $769,231。
  • 試算表只給初始金額、RTP 與 Increment，Startup% 依上式推得；試算表改版時三欄一起更新。
  • 新手 >= $2 的押注也會滾入 Increment，但新手不能中彩，所以新手的 Link RTP 為 0%。

3.3 規則

  • 「可滾 Inrc」表示該局押注會依 Increment 比例滾入彩池；「可拉 Link」表示該局有資格中 Grand／Major。兩者是不同的資格：
狀態押注可拉 Link可滾 Inrc
新手< $2否否
新手>= $2否是
老手< $2否否
老手>= $2是是
  • NB／EB 與 BF／SF 都適用上表；押注金額依 Omniplay 第 1.4.3 節判定（BF／SF 用購買價格反推的基礎押注）。系統限制另見系統機制。
  • Link RTP 與 Increment 由系統層依賭場設定，數學模型不得把彩金參數寫死在輪帶或 Paytable；模型只負責 Game RTP 與新手體驗，並在 Game Description 記錄採用的賭場與參數版本。
  • 數學模型必須定義哪些派彩歸入 Link、哪些歸入 Game，不得重複計算。

4. Card System 的層級調整

啟用 Card System 時，Oldhand 的押注層級只有兩套：

oldhand
├─ normal_bet    → low_bet／high_bet → weight_bg／weight_fg
├─ extra_bet     → low_bet／high_bet → weight_bg／weight_fg
├─ buy_feature   → low_bet／high_bet → weight_fg
└─ super_feature → low_bet／high_bet → weight_fg
  • low_bet 對應 < $2，high_bet 對應 >= $2；不得保留 medium_bet／big_bet 的空殼設定。
  • 區間工作表（Multiplier_Weight、Avg_Multi、Nature_Prob）的 Oldhand 欄位依低／高注命名，例如 NB_BG_Low／NB_BG_High；Newbie 欄位不變。
  • 倍率上限依系統機制的系統最大賠付反推，不直接套用 Omniplay 第 1.4.4 節的 20000x／1000x 預設；Newbie 的 30x／120x 上限沿用。
  • 是否啟用 Card System 隨第 1 節數學調性決定；未啟用時不得建立空白權重欄或 Card System 設定。

5. 命名補充

  • Landbase 轉製遊戲的 ParSheet ID 仍為 H<三位數字>1；同一數學供多個 Game ID 使用時（如 H0111 → 102001／102002），數學模型只建一份，Game ID 對應記錄於 Game Description 工作表與 Game List。

6. 檢查清單

  • ☐ 已確認數學調性並記錄於 Game Description（原機為底或重新設計、目標 RTP、波動度、是否啟用 Card System）。
  • ☐ RTP 配置採第 2 節（Link + Game + 新手體驗），且與試算表「轉製遊戲」欄當前版本一致，已記錄引用日期。
  • ☐ 押注層級只有 < $2／>= $2 兩級；Config、Simulator、Demogame 無小／中／大 Bet 殘留。
  • ☐ 採用的賭場與 Link 彩金參數版本已記錄，且與該賭場一致；數學模型未寫死彩金參數。
  • ☐ Omniplay 數學模型規範第 1.6 節其餘檢查項目全部通過。

Landbase 轉製 送驗規範

本頁說明 Landbase 轉製遊戲（Game ID 102xxx／105xxx）的送驗包內容與各文件要注意的地方。轉製遊戲的數學與文件來自 Landbase 原機團隊；本頁未提到的製作細節沿用 Omniplay 送驗文件規範.md。

本頁內容與送驗根目錄 送驗規範.md 的「Landbase 轉製遊戲」章相同，修改時兩邊同步。

1. 代號對應

Landbase 遊戲用 A0xx／S0xx／AS0xx 代號，轉線上後改用 H0xx ParSheet ID 與 6 碼 Game ID。

LandbaseParSheet IDGame ID遊戲
A030H009R105005Jin Feng Fei Wu 金鳳飛舞
A031H010R105006Hua Hao Yue Yuan 花好月圓
  • 同一套數學可對應多個 Game ID（H0071 → 105001／105003）。
  • 對應關係以 iGaming 遊戲代號一覽.xlsx 為準；查不到不得逕行送驗。
  • Landbase 本身若另出菲律賓版，會再立新代號（A009 → A028、A010 → A029），不要與線上版混用。

2. 送驗包內容與注意事項

文件檔名注意事項
Game Description{GameID}_Game Description.docx、{GameID}_Game Description_No Progressive.docx基本上都要兩份，只差彩金章節（No Progressive 規則見 Omniplay 送驗文件規範 2.5）；自既有核准模板重做為單一英文版，不得沿用 Landbase 的雙語檔（{ID}-GAME DESCRIPTION - CH.docx／- ENG.docx）；檔名改為 {GameID}_ 底線前綴，不用 Landbase 的連字號、全大寫

  • 歷史例外：102002（260427 批次）的檔名為 102002 Game Description.docx（空格）且無數學說明文件，屬早期交付，不作為新案依據。

3. 打包

送驗包只有一個 zip，不再另建 {GameID}_note/：送驗文件與 Landbase 轉來的模擬資產全部放進 {GameID}/，打包成 {GameID}.zip（另存 備份/{GameID}_YYMMDD.zip）。

{GameID}/
├─ {GameID}_Game Description.docx
├─ {GameID}_Game Description_No Progressive.docx
├─ {GameID}_Game Document Description.docx
├─ {GameID}_SHA1.txt
├─ PARsheet/
├─ flowcharts/
└─ simulation/
   ├─ A0xx-Way Game.ipynb
   ├─ BallTable.xlsx / StripTable.xlsx / GameFeature.xlsx / Pays.xlsx

  • flowcharts/ 放流程圖（01_base_game.png、02_hs_phase1.png…）；A0xx-Way Game.ipynb 是 Landbase 原始模擬 notebook；common/ 放 DataExport.py、InputSettings.py。
  • LLF_Calculator (H5).xlsx 這類帶 (H5) 的計算器屬線上版專用，放 PARsheet/。
  • {GameID}_SHA1.txt 涵蓋 zip 內所有檔案（清單本身除外），每次打包前重產，且一起打包進 zip。
  • __pycache__/ 一律清掉：105005、105006、106004 的送驗包都曾夾帶編譯中間檔，那是機器與 Python 版本相依的產物，不該進認證範圍。
  • .ipynb 若與交付的 .py 內容不同步，兩者都不可交付；先確認哪一份是正式版。

4. 轉製後必須重新確認的內容

  • RTP 口徑：Landbase 的 RTP 可能不含彩金；轉線上後重新拆成 Game／Link 兩項（不拆 Bonus），Game List 的 BASE GAME RTP% 與報告的客戶計算 RTP 一致（排除 Link）。
  • 彩金敘述：Landbase 彩金機制與線上 OP Jackpot 不同，Game Description 的彩金章節須改寫為 OP Jackpot 版本，不可沿用。
  • 盤面與得分方式：Way Game／Line Game 的描述要與線上 Game Rule 一致。
  • 禁止內容：Landbase 文件可能含下列內容，送驗包所有文件（Game Description、Game Document Description、PARsheet）一律不得出現；以不分大小寫搜尋，含表格儲存格，找到即為錯誤，必須移除後才可送驗。

5. 檢查清單

  • ☐ Landbase 代號 → ParSheet ID → Game ID 的對應已自代號一覽確認。
