# 數值報告規範

卡片權重完成後（開發流程第 4 節卡片權重調性校準之後），產出數值報告（即本作與競品、前作的差異分析），比較本作與競品（及使用者指定的前作）的玩法指標，作為調性是否到位的依據。

**檔案與格式**

- 檔名 `其他/數值報告_<遊戲中文名>.md` ＋ 同名 `.html`（例：`數值報告_宙斯 2500`、`數值報告_超級鑽石`、`數值報告_錢來襲`），兩份內容一致；不另取其他檔名。舊名 `差異分析_<遊戲中文名>` 一律改為此名。
- 遊戲名稱一律用英文名（例：Super Diamond、Super Ace、Lucky Ace），不用 H0xx 代號。
- **大標題＝`<本作英文名> 數值報告`**（例：`Super Diamond 數值報告`），不寫「A vs B vs C」；比較對象改在「基本資訊」章交代。
- 章節（頁簽）名稱照下表「必要章節」的中文名，不加英文括號（例：寫「連消分布」，不寫「連消分布（Combo）」）。
- HTML 最上方放「← 返回 Demo」，連回 `../index.html`；從 Demo 點進來時改為回上一頁。Demo 的數值報告按鈕在同一分頁開啟，推上網頁後也能用瀏覽器上一頁返回。
- **新報告要收錄到 Omniplay 首頁**：數值報告區不會自動掃描，第一次產出並推上 GitHub 後，在 `AI 工作區/Jumbo_Output/catalog.js` 的「數值報告」區加一筆（title 遊戲中文名、kind "數值報告"、url 用 rhino-boss.github.io 完整網址、game 代號、desc 一行「本作 vs 競品：主要章節」、date 產出日期），同時把 index.html／all.html 的 `?v=` 快取版號加一碼，再推上 Jumbo_Release。
- HTML 版式同 `市場資訊/H5/遊戲資訊/` 的競品分析報告：每章一個頁簽、頁簽只排一列可橫拉但不顯示拉條；表格不得出現橫向拉條（儲存格自動換行）。
- **卡片版型**：HTML 產出後一律跑 `py -X utf8 專案需知/其他/_report_card_style.py <數值報告_xxx.html>`：淺灰底＋圓角卡片（深色模式為深灰卡片）、膠囊頁簽、襯線大標題，每節（`###`）一張卡片；倍率線型的圖例每一條線都可點選開關。可重複執行，重產 HTML 後再跑一次即可。
- 百分比表格套條件式橫條（同競品報告：同表共用刻度、最大值以強調色、合計列不畫）；表格內只放百分比，不附括號內的分子／分母。

**比較口徑**

- 本作與前作一律用 **Card-On**（正式 RTP／Variant、Oldhand）報表；競品用實機側錄資料。自然機率（Card-Off）只可作附加欄，不得當主比較欄。
- 模擬在模擬機執行（NB ≥ 10⁶ 局、BF ≥ 10⁵ 次），報表存 `Record/` 並在報告來源表列出檔名。
- 指標口徑與競品報告一致；口徑不同時（例：分母只算初始盤面）以競品口徑為準並在該節說明。

**必要章節**

| 章節 | 內容 |
|---|---|
| 1. 基本資訊（放在最前面） | 頁簽之外只留大標題。**開頭第一節為「比較對象」表**：固定三欄「類別｜遊戲｜為什麼比」、固定三列「競品／前作／同系列」；遊戲寫英文名＋廠商或版本（例：Money Coming（JILI）、Money Boost 1.0.0.2（原始版））；為什麼比用一句話說明比較目的；沒有的列遊戲欄填「—」並註明（例：目前沒有同系列作品。）。**報告抬頭資訊一律放在本章**：產出日期、比較口徑（本作／前作／競品各用哪種資料、Profile）、本作版本與主要設定摘要（盤面表與選表比例、補牌與倍數規則、賠率、FG 階梯、BF 價格、EB、自然率門檻、Max Win 等）、**資料來源表**（來源｜樣本數｜報表檔名）。**遊戲簡介 200 字內**：盤面、怎麼贏、特色機制、FG 怎麼觸發、BF 價格，寫到玩家看完就懂規則。**玩法深淺**（NB、BF 分列，與競品／前作／同系列並列）：RTP、標準差（NB 以押注計、BF 以購買價計）、**≥1000x／≥5000x／≥10000x 週期**（以底注計；NB 為每局、BF 為每次購買），並給一句「平／深」結論（看標準差與存活中位數，平均把數由 RTP 決定不具鑑別度）。**存活模擬**：1000 人各帶 1000 元、每把押 1 元玩 NB 至不夠下注，列平均、中位數、最早死 10%（P10）、最晚死 10%（P90）把數；以 Card-On 報表每局總得分分布（BG 非觸發局＋觸發局含觸發把）抽樣，註明抽樣方式。 |
| 2. 核心指標 | Total RTP、BG Hit Rate、FG Hit Rate（每轉）、FG 週期；有 Buy Feature 的遊戲加列 **BF 贏錢率**（見第 10 章） |
| 3. 金框比例 | 平均每盤金框數、每格金框率、有金框盤面占比、各輪金框率（BG／FG 分開） |
| 4. 金框使用率 | 被消到而翻牌的金框數 ÷ 初始盤面金框數（BG／FG 分開） |
| 5. 倍率線型 | NB-BG、NB-FG、BF 各兩張折線圖：主圖（縱軸 BG 0–1%、FG／BF 0–16%）＋**放大圖（縱軸 BG 0–0.1%、FG／BF 0–1%）**，每張都含競品、前作、本作（卡片後，實線）與**本作自然機率（Card-Off，卡片前，同色虛線，預設隱藏、點圖例才顯示）**；64 區間全標；縱軸固定（BG 0–1%、FG／BF 0–16%），**圖例可點選切換各線顯示／隱藏**（關閉的圖例淡化加刪除線）；附 FG／BF 門檻機率表（含本作自然欄）；**滑鼠游標移到圖上鎖定該區間**，畫垂直線並列出各線數值（隱藏的線不列）；**圖例只寫名稱＋版本**（例：Super Ace、Super Diamond v5.0.0.0、Super Diamond v5.0.0.0 自然），不加括號說明；**圖下不加說明**；**每個區間都畫點**，機率 0 的點在 0 的位置，整條線全部連起來（不斷開）且**線半透明**，超過縱軸上限的部分被圖框裁掉；**x 軸寫法** `0`、`0 < x <= 1`、`1 < x <= 2`…（整數不加小數點，有小數才寫）；**競品一律灰色**，本作用彩色 |
| 6. 連消分布 | BG 每局、FG 每轉的 0／1／2／3／4／5+ 次，含與競品的差（pp） |
| 7. 大鬼出現率 | BG 每局、FG 每轉；並註明本作 BG 幾局一次、FG 每場幾次 |
| 8. 符號消除分布 | 各符號 3／4／5 連的 Hit Rate 與 RTP（BG／FG 分開） |
| 9. WILD 倍數分布 | 有帶倍數 Wild 的遊戲才需要：各種 Wild（如小鬼、大鬼本體、分裂）分開列各倍數占比 |
| 10. BF 回收分布（贏錢率） | 有 Buy Feature 的遊戲才需要。口徑＝每次購買的總贏分 ÷ **購買價**（各遊戲自己的價格，例：競品 40.5x、本作 50x）；分段同競品報告：< 20%、< 40%、< 60%、< 80%、< 100%（賠錢）、**> 100%（贏錢率）**、> 150%、> 200%、> 300%、> 500%，並列 BF RTP。競品用側錄、本作／前作用 Card-On BF 報表；報表倍率區間沒切在門檻上時以相鄰區間估計並註明「約」 |
| 11. 得分區間與最大獎機率 | 由卡片權重 `config_9xx.js` 精算（非模擬）。每個 **RTP／Variant（A／B 版）× 押注模式（NB／EB／BF）× 新老手 × 押注層級（小／中／大 Bet；卡片不分層級時標「不分」）** 一列：BG 得分區間（有權重的最低～最高區間）、FG／BF 得分區間、**最大獎區間**（可開出的最高區間）、**最大獎機率**（每局；BF 為每次購買）與週期 |

沒有對應機制的章節（例如無金框、無大鬼）可省略，但要在報告開頭註明；頁簽編號一律從 1 依序連號，省略章節後也重新連號（不沿用本表編號）。指標未達使用者設定的對標目標時，於回報中列出差距與可調的槓桿，由使用者決定是否調整；調整後重跑 Card-On 並重出數值報告。
