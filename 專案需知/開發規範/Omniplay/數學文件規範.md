# 數學文件規範

**存放位置**（路徑以遊戲專案資料夾 `Slots/H0xx_遊戲名稱/` 為準）：

| 檔案 | 存放位置 |
|---|---|
| `game_help_draft.md`、`game_description.md` | 專案根目錄 |
| `{GameID}_Help.xlsx` | `文件/` |
| `{GameID}_Game Description.docx`（完整版） | `文件/`；送驗版放 `文件/{GameID}/` |
| PARsheet（主檔名加 `R`，底線後綴放在 `R` 之後） | `文件/PARsheet/` |

內容涵蓋：Help、Game Description、PARsheet、Game List（含取得 Letter 後更新 RTP）。數學模型本體見[數學模型規範.md](數學模型規範.md)；送驗版文件（Game Description DOCX、Math Document Description、數學模型送驗版）的命名、格式與禁止內容見[送驗文件規範.md](送驗文件規範.md)。

## 1. Help

### 1.1 必要交付檔案

每款遊戲必須同時提供下列兩份 Help 文件：

- `{GameID}_Help.xlsx`（例：`101014_Help.xlsx`）
- `game_help_draft.md`

其中 `game_help_draft.md` 為必要的 Markdown 版本，不得只交付 XLSX。

兩份文件的文字、規則、數值、表格內容、章節順序與語言版本必須完全一致；檔案格式造成的版面呈現差異不得改變或省略任何內容。任一份文件更新時，另一份必須在同一次修改中同步更新。

### 1.2 內容規則

- Help 必須依 `game_rule.md` 編寫，只整理玩家需要理解的玩法，不得新增、刪除或改變正式遊戲規則。
- Help 內的遊戲名稱、遊戲類型、Bet Mode、Paytable、Symbol、Feature、倍率、局數、觸發條件、Max Win 與 Jackpot 說明，必須與 Game Rule、數學模型及 Config 一致。
- OP Jackpot 的內容與格式必須參考 `H5企劃書_101014_Pinata Beat 1000_彩罐熱舞.xlsx`，不得自行省略 OP Jackpot 的必要規則或改用未核准的格式。
- OP Jackpot 參考檔位於 `Slots/H026_彩罐熱舞 1000/其他/H5企劃書_101014_Pinata Beat 1000_彩罐熱舞.xlsx`；若檔案移動，必須同步更新本規範中的參考路徑。
- `{GameID}_Help.xlsx` 與 `game_help_draft.md` 若有任何內容差異，該遊戲不得視為完成交付。
- **以 `game_help_draft.md` 為主**：先改 md，再由 md 產出 xlsx；兩者不一致時以 md 為準。
- OP Jackpot 的規則與章節照上方 H026 參考檔；英文句子用 H027（`Slots/H027_宙斯 2500/文件/101027_Help.xlsx`）已修正文法的版本（加 THE／A、`PROGRESSIVE BONUSES`、`IF THE PLAYER REVEALS {3} OF THE SAME JACKPOT SYMBOL…`），遊戲規則章英文同。

### 1.3 寫法統一（H045 定案）

同一種玩法跨遊戲用同一套說法：

| 項目 | 寫法 |
|---|---|
| 連消倍數 | 「連消倍數／CASCADE MULTIPLIER」（同 Demogame規範 §1.1 術語），不用「贏分倍數／WIN MULTIPLIER」 |
| Way 遊戲的中獎 | 「中獎組合／WINNING COMBINATION」，不用「連線」；**不寫** Line Game 的「同一路有多種組合只賠最高」 |
| 數量 | 「{N} 個或以上」／`{N} OR MORE` |
| 兩個符號並列 | 「[A] 與 [B]」／`[A] AND [B]`，不寫 `[A][B]` |
| 押注倍數 | 「基礎投注的 {N}X」／`{N}X THE BASE BET` |
| Scatter 副標題 | 「散佈符號／SCATTER SYMBOL」 |
| FG 加局與上限 | 加局用 `ADDITIONAL`；上限獨立一句「每次免費遊戲特色最多可進行 {N} 場免費遊戲」／`A MAXIMUM OF {N} FREE SPINS MAY BE PLAYED DURING EACH FREE GAME FEATURE.` |
| Buy Feature | 兩句簡寫（同 H028）：「玩家可支付 {N}x 總投注，直接購買一次免費遊戲進場機會。」「完成購買後，將直接觸發一次免費遊戲特色。」 |

有對應玩法時**必寫**：

- 連消遊戲的 FG 觸發／加局：以「所有連消結束後的最終盤面」判定。
- 金框：「金框符號與原符號的賠率相同」。
- 帶倍數 WILD：倍數怎麼相加、乘上連消倍數後**作用於本次所有中獎組合的得分**，並寫沒有倍數 WILD 時只乘連消倍數。
- Way 段：盤面規格「{R} 輪 × {N} 列」與「相同符號須出現在由最左至右連續相鄰的轉輪上」（寫「由最左至右」，不寫「由左至右」）。

**不寫**：Max Win、隱藏規則（例：最後一次翻牌無法連線時改顯示無倍數小鬼）、舉例算式、過去 Help 都沒有的操作句（例：「點擊開始啟動免費遊戲特色」「免費遊戲中投注與觸發時相同」）。

其他：

- 中英文必須對等，中文有的條件英文也要有（例：原地補牌寫 `IN PLACE`、連續轉輪寫 `CONSECUTIVE`）。
- 同一句不在兩章重複出現；兩條規則描述同一件事時不得互相矛盾（例：百搭寫「只由參與中獎的金框轉換產生」，不寫「金框被消除後產生」）。
- `game_help_draft.md` 的 `game_type` 與 `game_rule.md` §1 完全相同。

### 1.4 XLSX 版式

照 H027 `101027_Help.xlsx` 的樣式：

- A1:I2、A3:I3 合併（抬頭）；每章標題 B:I 合併；表頭 NO／項目／繁中（D:F）／英文（G:I）。
- 文字列中文 D:F、英文 G:I 合併，自動換行、置中；同一項多列時 NO（B）、項目（C）上下合併。
- 欄寬：C 欄 12、E～I 欄 20（D 29）。列高依字數設定，每行 15.75；估算時中文 D:F 每行約 27 字、英文大寫 G:I 每行約 40 字，**每格的字都要看得到**，單格儘量不超過 4 行，太長就拆成兩條。
- 賠率表：三個符號一組（`[M1] 5 - 125` 的寫法），組間空列高 7.95，B、C 上下合併。

### 1.5 交付檢查

- [ ] `{GameID}_Help.xlsx` 與 `game_help_draft.md` 均存在。
- [ ] 兩份 Help 的文字、規則、數值、表格、章節順序與語言版本完全一致。
- [ ] Help 與 `game_rule.md`、數學模型及 Config 的內容一致。
- [ ] OP Jackpot 已參考 `H5企劃書_101014_Pinata Beat 1000_彩罐熱舞.xlsx` 編寫並完成核對。
- [ ] 用語、必寫／不寫項目符合 §1.3；xlsx 版式符合 §1.4（每格的字都看得到）。

## 2. Game Description

Game Description 有兩份檔案，用途不同：

| 檔案 | 用途 | 位置 |
|---|---|---|
| `game_description.md` | 說明數學模型參數的使用方式，以及各參數如何對應實際遊戲功能 | 遊戲專案根目錄 |
| `{GameID}_Game Description.docx`（完整版） | Help 的 Word 版本，供內部與客戶閱讀；送驗版由它刪減而來 | `文件/` |

- DOCX **不放圖片**：Game Description 內一律不放任何圖片（符號圖、盤面圖、走線圖、示意圖）；需要舉例時，符號一律用代號文字表示（`M1`、`M2`…），不用圖片。

### 2.1 game_description.md

- 每款遊戲必須提供，不得只保留 DOCX、XLSX、簡報或口頭說明。
- 內容至少包含參數名稱、用途、使用模式、選表條件、限制與對應的數學模型／Config 欄位。
- 內容必須與數學模型的 `Game Description` 工作表及 Game Rule 一致；參數或選表邏輯更新時同步更新。

### 2.2 DOCX 完整版

- 內容與 Help 英文欄**完全相同，不移除任何項目**；Extra Bet、Buy Feature、Super Feature、>$2 門檻等送驗禁止的內容都要保留。
- 格式來源、填寫方式與結構依[送驗文件規範.md](送驗文件規範.md)第 2.1～2.3 節；送驗版的刪減規則見同文件第 2 節。
- Help 更新時，完整版與送驗版在同一次修改中同步更新。

### 2.3 交付檢查

- [ ] `game_description.md` 存在，與數學模型 `Game Description` 工作表及 Game Rule 一致。
- [ ] `文件/{GameID}_Game Description.docx` 存在，內容與 Help 英文欄完全一致、未刪任何項目。
- [ ] 送驗版除刪減處外與完整版一致。

## 3. PARsheet

PARsheet 是提供企劃、程式、測試、美術、營運或其他職能查閱的精簡規格文件，不是完整數學模型的副本。

- PARsheet 必須移除數學模型中的計算公式、中間推導、內部權重計算與不需要對外提供的工作資料。
- 只保留其他職能完成工作所需的必要資訊，例如遊戲基礎設定、盤面、得分方式、Paytable、Symbol、Bet Mode、Feature 條件、局數、倍率、Max Win、Jackpot 與產品限制。
- 所有輸出數值與規則必須和完整數學模型、Game Rule 及 Config 一致，不得為了簡化而改變定義或精度口徑。
- 完整數學模型更新時，必須同步確認 PARsheet 是否需要更新；PARsheet 不得保留已失效的規格。

### 3.1 PARsheet 產出方式

PARsheet 由 `Source/` 的完整數學模型逐份轉出，一律由 AI 執行（見[開發流程.md](../../開發流程/開發流程.md)），專案內不建立轉檔工具。

| 項目 | 規則 |
|---|---|
| 來源 | `Source/` 內每一份數學模型 XLSX 各轉一份：基礎數學（`H0xx1*.xlsx`）與每個 RTP／Variant 的倍率權重工作簿 |
| 位置 | `文件/PARsheet/` |
| 檔名 | 主檔名後加 `R`，`_Extra`／`_Bet100` 等底線後綴放在 `R` 之後，例：`H0271A.xlsx` → `H0271AR.xlsx`、`H027192A_Bet100.xlsx` → `H027192AR_Bet100.xlsx`、`H014192A_Extra.xlsx` → `H014192AR_Extra.xlsx` |
| 公式 | 全部改為計算後的數值；公式結果為空字串者改為空白格 |
| 格式 | 保留原檔的樣式、欄寬、合併儲存格、條件格式與工作表順序 |
| 工作表 | 全部照原檔保留，包括 `Overview`、`Parameter`、輪帶頁、`Multiplier_Weight`、`Avg_Multi`、`Nature_Prob`、`Detail`、`OP Jackpot`（2026-10-15 起 `Avg_Multi`、`Nature_Prob` 不再移除，供核對權重 × 平均倍率與自然機率） |
| 版本 | 與來源工作簿 `Overview!B3` 相同，不另編版號 |

轉出方式：

- 用 XML 修補 XLSX，不得用 openpyxl 開檔另存（會遺失樣式與條件格式）。
- 每個儲存格移除 `<f>`，保留快取的 `<v>`；字串結果改為 `inlineStr`；動態陣列的 `cm` 屬性一併移除。
- 刪除 `xl/calcChain.xml` 及其在 `[Content_Types].xml` 與 workbook rels 的登錄。
- 移除工作表時，同步刪除 workbook、rels、`[Content_Types].xml`、`docProps/app.xml` 內的登錄與相關 definedName。
- 來源 XLSX 必須是 Excel 最後存檔且已完成計算的版本；快取值缺漏時，先在 Excel 開啟重算存檔再轉。

交付前檢查：

- [ ] `文件/PARsheet/` 的檔案數等於 `Source/` 的 XLSX 數，檔名逐一對應並依上表加 `R`（底線後綴放在 `R` 之後）。
- [ ] 每份 PARsheet 逐格等於來源的計算結果（來源以「只讀值」開啟比對），差異為 0。
- [ ] PARsheet 內沒有任何公式。
- [ ] 工作表清單與來源完全相同（含 `Avg_Multi`、`Nature_Prob`）。
- [ ] `Overview!B3` 版號與來源一致。
- [ ] 跑 `其他/_check_xlsx_style.py`，ERROR 數不多於來源；基礎數學頁的空字串公式改成空白格後會被判成「空白格有框線」，屬預期。
- [ ] 來源模型每次改版，PARsheet 同步重出，不得留舊版。

## 4. Game List

Game List 用於彙整所有遊戲提供給企劃、開發、測試及其他職能查閱的共用資訊。

- 必須提供 Markdown 版本 `Slots/game_list.md`，不得只保留 XLSX 或其他格式。
- 每款正式遊戲至少記錄 Game ID、中英文名稱、遊戲類型、盤面／得分方式、支援的 Bet Mode、RTP／版本來源與必要 Feature 資訊。
- Game List 只放跨遊戲比較與識別所需資訊，不重複完整數學公式或整份 Game Rule。
- 遊戲新增、改名、玩法分類、Bet Mode、版本或重要 Feature 異動時，必須同步更新 `game_list.md`。

### 4.1 取得 Letter 後更新 RTP

- 送驗取得定稿 Letter 後，必須把 Letter 上的 RTP 更新到**雲端的 Game List**；雲端版是 Game List 的正式版本。
- 填入的值是 Letter 的 `CLIENT CALCULATED RTP`（排除 Link 成分），對應 Game List 的 `BASE GAME RTP%`；`TOTAL PAYOUT%` 須等於 `BASE GAME RTP% + TOTAL JACKPOT RTP%`。
- RTP 照 Letter 的數字原樣填，**不得四捨五入或取整**；差 0.01 就是不同。
- 一款有多個變體、但 Game List 一列裝不下時（例：102002 有彩金三變體為 93.99／94.00／94.00），先定好填值規則再填，不得自行挑一個數字。
- 雲端版更新後，本機副本（送驗根目錄的 `Game List_Online.xlsx`、`game_list.md` 的線上營運欄位）重新同步。

- [ ] 新取得的 Letter，其 RTP 已更新到雲端 Game List，且與 Letter 完全相同。
