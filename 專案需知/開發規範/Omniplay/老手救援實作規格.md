# 老手救援 實作規格

給 SPS 實作**中辦老手救援（C-2）**用。機制設計與模擬結果見 Omniplay 開發規範〈系統機制〉第 3 節；本文件只寫實作需要的規則、參數與紀錄。**數值皆為暫定**，上線值以 Config 為準，程式不得寫死。

| 項目 | 內容 |
|---|---|
| 機制版本 | C-2（數學模擬版本 c2-1.8） |
| 適用範圍 | 中辦；Oldhand 的 NB／EB |
| 不適用 | Newbie（新手期）、Buy Feature／Super Feature |
| 北辦 | 另有一套，救援池、累積數值與統計**全部分開**，不在本文件範圍 |

## 1. 機制摘要

- **以天為循環**：每天**台灣時間 04:00** 刷新，當日轉數、當日統計與救援池餘額全部歸零。
- **主救援**（當日第 35～405 轉）：每 40 轉一個觸發區間，每個區間隨機挑一轉判定；兩個條件都成立就用 Card System 在指定卡片倍率區間重骰。
- **延伸救援**（當日第 435～1,000 轉）：同樣每 40 轉一個區間，條件 2 改看往前 400 轉。
- **救援池**：每轉提撥押注的一定比例；發放前檢查餘額，不夠就不救。
- **參數依押注層級分開**：小／中／大 Bet 各一套參數；A／B 版靠不同 Config 檔分開。
- 救援結果由 Card System 產生，演出與自然得分無法區分；玩家無法預測判定轉。

## 2. 名詞與計算定義

| 名詞 | 定義 |
|---|---|
| 當日 | 台灣時間 04:00 起至隔日 04:00 前（UTC+8）。 |
| 當日轉數 | 玩家在該款遊戲當日的第幾轉，從 1 起算；04:00 歸零。 |
| 判定轉 `k` | 該區間抽中的那一轉（當日第 `k` 轉）。 |
| 得分 | 每轉最終得分，**含先前救援後的結果**（救援得分會計入後續統計）。 |
| 押注 | 每轉 Total Bet（實際押注）。 |
| 前 40 轉 RTP | 第 `k−40`～`k−1` 轉的 Σ 得分 ÷ Σ 押注；`k ≤ 40` 時從當日第 1 轉算起。 |
| 當日累積 RTP | 當日第 1～`k−1` 轉的 Σ 得分 ÷ Σ 押注。 |
| 往前 400 轉 RTP | 第 `k−400`～`k−1` 轉的 Σ 得分 ÷ Σ 押注。 |
| 救援成本 | 救援後最終得分 − 該轉自然得分（≥ 0）。 |

- **判定轉本身不納入任何統計**，所有 RTP 都只算到 `k−1`。
- 門檻比較一律為**嚴格小於**（`<`）。
- 所有 RTP 都以「得分 ÷ 押注」計算，跨不同押注金額的轉數直接加總。

## 3. 判定時程

| 階段 | 觸發點 `t` | 判定區間 | 區間數 |
|---|---|---|---:|
| 主救援 | 40、80、…、400 | `[t−5, t+5]`（35～45、75～85…395～405） | 10 |
| 延伸救援 | 440、480、…、1,000 | `[t−5, t+5]`（435～445…995～1,005） | 15 |

- 每個區間在 `[t−5, t+5]` 內**均勻隨機**抽一個整數作為判定轉；每人每天每區間只判定一次。
- 抽選在當日開始（或進入該區間前）完成，玩家無法得知。
- 玩家當日沒玩到抽中的那一轉 → 該區間不判定，不補判。
- **超過當日第 1,000 轉不判定**（最後一個區間只到第 1,000 轉）；當日第 1～34 轉、第 406～434 轉不判定。
- **新手期**：玩家仍在新手期（Newbie）時不判定老手救援；新玩家第一天的新手期為前 200 轉，所以第一天從第 235～245 轉區間開始判定（當日轉數照常從第 1 轉起算）。

## 4. 判定條件與救援倍數

### 4.1 主救援

兩個條件都成立才命中：

- 條件 1：前 40 轉 RTP `<50%`
- 條件 2：當日累積 RTP `<` 該區間門檻

| 觸發點 | 判定區間 | 條件 2 門檻 | 救援倍數（卡片區間） |
|---:|---|---:|---:|
| 40 | 第 35～45 轉 | `<25%` | (20, 25] |
| 80 | 第 75～85 轉 | `<30%` | (45, 50] |
| 120 | 第 115～125 轉 | `<35%` | (60, 70] |
| 160 | 第 155～165 轉 | `<40%` | (70, 80] |
| 200 | 第 195～205 轉 | `<45%` | (80, 90] |
| 240 | 第 235～245 轉 | `<50%` | (90, 100] |
| 280 | 第 275～285 轉 | `<55%` | (90, 100] |
| 320 | 第 315～325 轉 | `<55%` | (90, 100] |
| 360 | 第 355～365 轉 | `<60%` | (90, 100] |
| 400 | 第 395～405 轉 | `<65%` | (90, 100] |

### 4.2 延伸救援

| 觸發點 | 條件 1 | 條件 2 | 救援倍數（卡片區間） |
|---|---|---|---:|
| 440～1,000，每 40 轉 | 前 40 轉 RTP `<50%` | 往前 400 轉 RTP `<65%` | (90, 100] |

- 卡片倍率區間的定義與倍率分母見 Omniplay 開發規範〈數學模型規範〉第 1.8 節、第 2.5 節。

## 5. 救援執行

```flow
到達判定轉 :: 取該區間的門檻與救援倍數（依判定轉的押注層級）
檢查條件 :: 條件 1 前 40 轉 RTP；條件 2 當日累積 RTP（主救援）或往前 400 轉 RTP（延伸救援）
  + 兩個條件都成立 :: 命中，進入重骰
  - 任一不成立 :: 本區間結束，該轉照自然結果
重骰 :: Card System 在救援倍數的卡片區間內產生候選結果
計算救援成本 :: max(自然得分, 候選得分) − 自然得分
救援池檢查 :: 比較救援池餘額與救援成本
  + 餘額 ≥ 救援成本 :: 發放：最終得分取較高者，救援池扣除救援成本
  - 餘額不足 :: 不救援，該轉照自然結果
```

- **取較高者**：自然得分高於候選得分時，最終得分＝自然得分，救援成本為 0、不扣池（仍記為命中）。
- 救援只會往上補，不會讓玩家拿得比自然結果少。
- 救援後的最終得分計入後續所有 RTP 統計（第 2 節）。
- 不救援時不補發、不累積、不延到下一個區間。

## 6. 救援池

```text
提撥額     = 該轉 Total Bet × pool_rate（依該轉的押注層級）
救援池餘額 = 當日起始餘額 + Σ 當日提撥 − Σ 當日已發救援成本
```

| 規則 | 內容 |
|---|---|
| 範圍 | 中辦**單一救援池**（不分遊戲、不設個人池）；北辦的池分開，不流用。 |
| 提撥 | 每一轉 Oldhand NB／EB 押注依 `pool_rate` 提撥；暫定 **1%**。 |
| 刷新 | 每天台灣時間 04:00 餘額歸零；當日起始餘額暫定 0。 |
| 發放前檢查 | 每筆救援都要先檢查，餘額 < 救援成本就不救（硬性上限，當日發出總額不超過當日可用總額）。 |
| 併發 | 多名玩家同時命中時，扣款須為原子操作，餘額不得扣成負數。 |

## 7. 押注層級與版本

- **押注層級**依 Omniplay 開發規範〈數學模型規範〉第 1.7.1 節判定小／中／大 Bet（`< $2`、`$2～$100`、`> $100`）。
- **判定參數**（門檻、救援倍數）取**判定轉**當下的押注層級；**提撥比例**取每一轉自己的押注層級。
- 統計（前 40 轉、當日累積、往前 400 轉）**不分層級**，玩家當日所有 Oldhand NB／EB 轉數一起算。
- **A／B 版**以不同 Config 檔分開（例 `config_92A.js`／`config_92B.js`），檔案內不再分版本層。

| 參數 | 是否依層級分開 | 備註 |
|---|---|---|
| 條件 1 門檻（前 40 轉 RTP） | **分** | |
| 條件 2 的 10 段門檻 | **分** | |
| 救援倍數（10 段卡片區間） | **分** | |
| 延伸救援的條件與倍數 | **分** | |
| 提撥比例 `pool_rate` | **分** | 提撥進同一個救援池 |
| 觸發節奏（每 40 轉、前後 5 轉） | 共用 | 可在層級內覆寫 |
| 起判／停判轉（35／1,000） | 共用 | 可在層級內覆寫 |
| 每日刷新時間（04:00） | 共用 | 不可覆寫 |

- 啟用老手救援的 Config **必須同時提供小／中／大三套**，不得缺少或互相 fallback（與 Card System 權重相同規則）。
- 目前三套數值暫時相同（第 4 節），之後依各層級模擬結果分開調整。

## 8. Config 結構

```js
oldhand_rescue: {
  enabled: true,
  daily_reset_at: "04:00",            // 台灣時間（UTC+8），不可覆寫
  cadence: {                          // 共用，可在層級內覆寫
    interval: 40,                     // 每 40 轉一個觸發點
    jitter: 5,                        // 觸發點前後 5 轉隨機
    stop_spin: 1000                   // 超過當日第 1,000 轉不判定
  },
  oldhand: {
    small_bet: {
      pool_rate: 0.01,
      main: {
        short_window: 40,
        short_rtp_below: 0.50,        // 條件 1
        tiers: [                      // 10 段：觸發點、條件 2 門檻、救援倍數卡片區間 (min, max]
          { checkpoint: 40,  day_rtp_below: 0.25, reward: [20, 25] },
          { checkpoint: 80,  day_rtp_below: 0.30, reward: [45, 50] },
          { checkpoint: 120, day_rtp_below: 0.35, reward: [60, 70] },
          { checkpoint: 160, day_rtp_below: 0.40, reward: [70, 80] },
          { checkpoint: 200, day_rtp_below: 0.45, reward: [80, 90] },
          { checkpoint: 240, day_rtp_below: 0.50, reward: [90, 100] },
          { checkpoint: 280, day_rtp_below: 0.55, reward: [90, 100] },
          { checkpoint: 320, day_rtp_below: 0.55, reward: [90, 100] },
          { checkpoint: 360, day_rtp_below: 0.60, reward: [90, 100] },
          { checkpoint: 400, day_rtp_below: 0.65, reward: [90, 100] }
        ]
      },
      extended: {
        from_checkpoint: 440,
        to_checkpoint: 1000,
        short_window: 40,
        short_rtp_below: 0.50,        // 條件 1
        mid_window: 400,
        mid_rtp_below: 0.65,          // 條件 2：往前 400 轉
        reward: [90, 100]
      }
    },
    medium_bet: { /* 同 small_bet 結構 */ },
    big_bet:    { /* 同 small_bet 結構 */ }
  }
}
```

- 鍵名可依 SPS 慣例調整，但**結構與層級要一致**，並回傳給數學端核對。
- `reward` 為 Card System 卡片倍率區間 `(min, max]`。

## 9. 紀錄與報表

每次判定（不論命中與否）記一筆：

| 欄位 | 說明 |
|---|---|
| `date`、`office` | 當日（04:00 切日）、中辦／北辦 |
| `player_id`、`game_id`、`variant` | 玩家、遊戲、A／B 版 |
| `bet_tier`、`bet_mode`、`total_bet` | 判定轉的押注層級、NB／EB、押注 |
| `phase`、`checkpoint`、`judge_spin` | 主救援／延伸救援、觸發點、判定轉 |
| `short_rtp`、`cond2_rtp`、`cond2_threshold` | 條件 1 RTP、條件 2 RTP 與門檻 |
| `hit` | 是否命中（兩條件都成立） |
| `natural_win`、`candidate_win`、`final_win`、`cost` | 自然得分、候選得分、最終得分、救援成本 |
| `pool_before`、`paid`、`deny_reason` | 扣款前餘額、是否發放、不發原因（條件不符／餘額不足） |

每日彙總（依 `office` × `variant` × `bet_tier` 分開，**不可合併統計**）：

- 當日提撥、當日發放、日末餘額、不救率（餘額不足 ÷ 命中）。
- 各區間判定數、命中數、觸發率、發放金額。
- 用到救援的玩家數 ÷ 當日老手玩家數。
- RTP 增量（當日救援成本 ÷ 當日 Oldhand NB／EB 總押注）。

## 10. 驗收

- **單筆規則**：用固定得分序列逐筆驗證第 2～6 節（例：判定轉為第 38 轉、前 37 轉押注各 1、總得分 5 → 前 40 轉 RTP 與當日累積 RTP 都是 13.5%，兩條件成立，應在 (20, 25] 重骰）。
- **邊界**：判定轉剛好在 04:00 前後、玩家沒玩到判定轉、第 995～1,005 轉區間抽到 1,000 以後、自然得分高於候選、餘額剛好等於／小於成本、多人同時命中。
- **分層**：小／中／大 Bet 各自取對參數；缺任一層級的 Config 應報錯，不可 fallback。
- **RTP 對照**：壓測結果與數學端 Simulator 對照，容許誤差依〈壓測說明書〉。
