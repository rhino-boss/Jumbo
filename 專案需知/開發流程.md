# Slot 數學開發流程

本文件定義新 Slot 專案的**數學開發流程、製作順序、操作方式、階段產物與完成條件**。

實作欄位、命名、版本、Card System、Simulator、Demogame、Config 與報表格式等細節，統一依照本資料夾的各規範文件（總覽見 [_README.md](_README.md)）。本文件不重複定義實作規格；內容有差異時，以各規範文件為準。

適用範圍：`Slots/H0xx_遊戲名稱/` 下的新遊戲數學模型、既有模型改版，以及 RTP、Card System、Feature 或 Bet Mode 參數調整。

## 1. 過往專案整理後的標準做法

過往專案可看到數種演進中的做法：

- H013、H015、H019 使用 RTP Config、Simulator 與 Record 的基本流程。
- H016、H028 已拆分基礎 `config.js` 與 RTP／Variant Config，並保留 `Versions/`，較符合目前標準。
- H026 同時存在 92／94 與 A／B Variant，適合作為多模型組合的參考。
- 早期專案（H013～H027）曾使用 `xlsx_to_config.py`、`model_sync.py` 等轉檔腳本同步 Source 與程式資料；此做法已淘汰，Excel 與 Config 之間的轉換一律由 AI 執行，專案內不建立、不維護轉檔工具。

新專案採用以下統一原則：

1. `game_rule.md` 定義玩法，數學 XLSX／`Source/` 定義正式參數。
2. Config 必須由 Source 轉出（轉換由 AI 執行，不建立轉檔工具），不直接手改轉出的參數。
3. Simulator 與 Demogame 使用同一份 Config。
4. 先驗證 Card System Off 的自然機率，再驗證 Card System On。
5. 每次調參都依「Source → 版本 → Config → Simulator → Record → 對帳」完整重跑。
6. 舊專案若與目前命名、版本或報表格式不同，不直接複製舊格式；依現行規格建立。

## 3. 整體流程

六個大步驟，每一步的細項與進入下一步的條件見第 4 節：

```flow
確認規則與目標 :: Game Rule、數學目標、模型組合
建立數學模型 :: 基礎數學模型 → RTP／Variant／Card System 模型 → Source 與 Mapping 說明
轉檔與模擬程式 :: AI 轉出並驗證 Config → 實作 Simulator → 小場次 Debug 與單局驗證
自然機率與卡片權重 :: Card System Off 驗證 → 大場次自然機率報表（NB 10⁹ 局、BF 10⁸ 局）→ 依報表調整卡片權重
驗證與調參 :: Card System On 各 Mode／Profile 驗證 → 調參循環與大場次正式模擬 → Max Win、Retry、分布與單局驗證
對帳與交付 :: Simulator／Demogame 對帳 → 完成必要產出文件 → 凍結版本、整理 Record、交付
```

## 4. 製作順序與階段關卡

不得因為某個程式可以先寫就跳過前置規則。上一階段的完成條件成立後，才進入下一階段。

| 順序 | 階段 | 主要工作 | 產出 | 進入下一階段的條件 |
|---:|---|---|---|---|
| 1 | 開案與目標確認 | 確認 Game ID、盤面、判獎、Bet Mode、Feature、RTP 拆分、Link 資格、Hit Rate、Max Win、Profile、押注層級與 Variant；**與使用者確認數學模型組合**（預設 92A／92B／94A／94B 四版本，各含 Newbie／Oldhand 與對應押注區） | 已確認的 `game_rule.md`、數學目標表 | 核心規則、計算口徑與模型組合無待確認項目 |
| 2 | 基礎數學模型 | 建立 Symbol、Paytable、Reel／Weight、Table、Feature 流程與自然機率 | `Source/H0xx1.xlsx` | 自然機率流程可計算，理論上限已確認 |
| 3 | RTP／Variant 模型 | 建立 92／94、A／B、Card System 區間與權重 | `Source/H0xx1<RTP><Variant>.xlsx` | 每個正式組合都有目標與資料；不建立空白 Variant |
| 4 | Mapping 與轉檔 | 定義 XLSX 到 Config 的來源、型別、欄位與驗證 | 數學模型的 `Game Description` 工作表 | Config 可重建，錯誤資料會被擋下 |
| 5 | Config 產生 | 由 AI 依 Source 轉出基礎與 RTP／Variant Config，核對版本與資料 | `config.js`、`config_<RTP><Variant>.js` | Source、Config、版本逐項一致 |
| 6 | Simulator 實作 | 實作自然機率、Feature、Card System、批次、統計與報表 | `Simulator.py` | 固定 Seed 可重現，單執行緒 Debug 正確 |
| 7 | 小場次驗證 | 強制或指定 RNG 測試判獎、Feature、Retry、Max Win 與例外 | Debug Trace、測試紀錄 | 代表性案例逐項符合 Game Rule |
| 8 | 自然機率基準 | Card System Off 跑所有自然機率 Bet Mode，最終以大場次產出正式報表（NB 10⁹ 局、BF 10⁸ 局） | `Record/*card-off*.xlsx` 或規格化檔名 | RTP Breakdown、Hit Rate、Feature 與分布合理，大場次報表已產出 |
| 9 | 卡片權重調性校準 | 依自然機率大場次報表分配各得分區間的卡片權重，使分布、RTP 拆分與 FG 週期符合目標遊戲調性 | 更新後的 `Multiplier_Weight`（RTP／Variant XLSX）與 Config | 卡片權重已依報表校準完成，目標調性明確可驗證 |
| 10 | Card System 驗證 | 以校準後的數學調性，分 RTP、Variant、Profile、Oldhand 小／中／大 Bet、Bet Mode 跑 Card System On | `Record/*card.xlsx` | 權重占比、Link 資格與倍率上限正確，Retry Limit Exceeded 通過 |
| 11 | 調參與正式模擬 | 依差距修改 Source，重新轉檔、模擬、比較與升版 | 正式大場次 Record | 所有支援組合符合目標與統計誤差要求 |
| 12 | 極值與單局對帳 | 驗證 Max Win、封頂、理論可達路徑及代表性單局 | 極值紀錄、對帳案例 | Config、Simulator、Demogame 結果一致 |
| 13 | 版本凍結與交付 | 清理暫存、保存版本、報表、來源與變更說明，確認第 2 節必要產出文件齊備 | 完整專案目錄 | 本文件第 9 節全部通過 |

## 5. 各階段操作方式

### 5.1 開案與數學目標確認

1. 建立 `H0xx_遊戲名稱/` 專案資料夾。
2. 讀取並確認 `game_rule.md`。
3. **與使用者確認本專案的數學模型組合**——每款遊戲的數學模型都不一樣，不得逕自沿用他款設定。未特別說明時，預設組合為：
   - A／B 兩個 Variant × 92／94 兩個 RTP，乘開共 **4 個版本**（92A、92B、94A、94B）。
   - 每個版本都有 Newbie／Oldhand 兩種 Profile。
   - 各版本依其支援內容有對應的押注區（Oldhand 小／中／大 Bet 層級）。
4. 列出所有正式支援組合：RTP、Variant、Profile、Oldhand 小／中／大 Bet、NB／EB 或 BF／SF 模式類別、Bet Mode、Card System Off／On。
5. 為每個組合定義 Link／Bonus Game／Game RTP、Total RTP、Link 資格、Hit Rate、Feature Frequency、BG／FG Max Multiplier 與其他遊戲專屬指標。
6. 將未決定的判獎順序、倍率分母、Feature 上限與例外退回確認；未確認前不製作正式模型。

### 5.2 建立基礎數學模型

1. 先完成 Base Game，再依狀態順序完成 Feature。
2. 建立 Symbol、Paytable、Reel Strip／Weight、Table 與 Bet Mode。
3. 建立 BG、FG、Cascade、Multiplier、Retrigger、Jackpot 等流程。
4. 計算 RTP Breakdown 與理論 Max Win，不只計算 Total RTP。
5. 建立基礎數學 XLSX，版本依規格使用 1 碼。

### 5.3 建立 RTP／Variant 與 Card System

1. 只建立 5.1 與使用者確認過的 92／94、A／B 組合（未特別說明時為 92A、92B、94A、94B 四版本，各含 Newbie／Oldhand 與對應押注區）。
2. A／B 表示數學 Variant，不表示 Newbie／Oldhand。
3. 依 Profile、Oldhand 小／中／大 Bet 與 Bet Mode 建立 BG／FG 卡片區間及權重；NB／EB 以實際模式押注、BF／SF 以 Feature 基礎押注選擇層級。
4. 確認每張正權重卡片的區間可達，並定義 Retry 行為。
5. 建立 RTP／Variant XLSX，版本依規格使用四段格式。

### 5.4 轉檔與 Config 驗證

1. 在數學模型的 `Game Description` 工作表記錄每項 Config 資料的來源。
2. 由 AI 依 Source 與 Mapping 轉出 Config；專案內不建立、不維護 Excel↔Config 轉檔工具。
3. 執行欄位、型別、陣列長度、ID、Weight、Min／Max、版本與模式驗證。
4. 比較轉檔前後資料，確認 Config 可由 Source 重建且沒有非預期差異。
5. 轉檔錯誤時修正 Source 或 Mapping 後重新轉出，不直接修改 Config 大型陣列。

### 5.5 Simulator 開發與 Debug

1. 先完成自然機率核心，再加入 Card System 篩選與 Retry。
2. 讓 Simulator 直接讀取正式 Config，不另寫一份參數。
3. 建立固定 Seed、單執行緒與逐局 Trace 模式。
4. 建立強制／指定案例，驗證無獎、一般獎、Wild、Scatter、Feature、Retrigger、倍率與封頂。
5. 小場次確認正確後，再加入 Numba、多執行緒、BATCH_RUNS 與 Excel 報表。

### 5.6 模擬順序

模擬必須依下列順序執行：

1. 小場次、Card System Off：驗證流程與報表。
2. 中場次、Card System Off：確認自然機率 RTP 與分布。
3. 大場次、Card System Off：以 NB 10⁹ 局（BF 為 10⁸ 局）產出自然機率正式報表。
4. 卡片權重調性校準：依上一步報表分配各得分區間的卡片權重，使分布、RTP 拆分與 FG 週期符合目標遊戲調性；完成後才進入 Card System On。
5. 小場次、Card System On：確認抽卡、Profile、Oldhand 押注層級、Link 資格、倍率上限、Mode 與 Retry。
6. 中場次、Card System On：調整區間、權重與目標 RTP。
7. 所有正式組合的大場次模擬。
8. Max Win、低機率 Feature 與 Retry 邊界的專項驗證。

最低批次矩陣：

| 類型 | RTP／Variant | Profile | `bet_tier_amount` | Bet Mode | Card System |
|---|---|---|---|---|---|
| 自然機率基準 | 基礎 Config | 不適用 | 各門檻所需代表值 | 每個支援 Mode | Off |
| Newbie | 每個正式 RTP／Variant | Newbie | 不分層級，但仍記錄判定金額 | 每個支援的 NB／EB／BF／SF | On |
| Oldhand 小 Bet | 每個正式 `94x`／Variant | Oldhand | `< $2`，至少驗證 `$1.99` | 每個支援的 NB／EB／BF／SF | On |
| Oldhand 中 Bet | 每個正式 `92x`／Variant | Oldhand | `$2～$100`，至少驗證 `$2`、`$100` | 每個支援的 NB／EB／BF／SF | On |
| Oldhand 大 Bet | 每個正式 `92x`／Variant | Oldhand | `> $100`，至少驗證 `$100.01` | 每個支援的 NB／EB／BF／SF | On |

- NB／EB 的 `bet_tier_amount` 使用實際模式押注金額；BF／SF 使用 Feature 購買價格除以 Feature Price 倍數後的基礎押注。
- 若遊戲支援 EB 2x，至少驗證 base bet `$1` 會以 `$2` 判為中 Bet。
- 若遊戲支援 BF 75x，至少驗證購買 `$75` 判為小 Bet、購買 `$150` 判為中 Bet。

不存在的 Mode、Profile 或 Variant 不建立空批次，也不以全零結果冒充驗證完成。

### 5.7 調參循環

每一次調參都執行完整循環：

```text
確認差距與原因
    ↓
修改對應 Source XLSX
    ↓
依異動內容更新版本
    ↓
重新產生 Config
    ↓
執行轉檔與資料驗證
    ↓
先跑小場次確認流程
    ↓
再跑中／大場次確認統計
    ↓
保存新 Record 並與前版比較
```

調參時依序判斷：

1. 先確認程式與統計口徑是否錯誤。
2. 再檢查自然機率的 Paytable、Reel、Table、Feature。
3. 最後才調整 Card System 區間與權重。
4. 不得只為讓 Total RTP 接近目標而忽略 RTP Breakdown、Hit Rate、Feature Frequency、分布或 Retry。

### 5.8 對帳與交付

1. 選定可重現的代表性 RNG／Seed。
2. 逐項核對 Config、Simulator 與 Demogame 的盤面、判獎、Feature、倍率、Total Win、Coin In 與 Retry。
3. 完成所有正式組合的最新 Record。
4. 將正式 Config 與歷史版本關係寫入 `Versions/` 與 manifest。
5. 確認第 2 節必要產出文件全部齊備且為同一正式版本。
6. 清除暫存檔、舊測試輸出及不屬於正式交付的檔案。
7. 依第 9 節完成最終驗收。

### 5.9 數值報告（對標競品與前作）

卡片權重完成後（第 4 節卡片權重調性校準之後），產出數值報告（即本作與競品、前作的差異分析），比較本作與競品（及使用者指定的前作）的玩法指標，作為調性是否到位的依據。

**檔案與格式**

- 檔名 `其他/數值報告_<遊戲中文名>.md` ＋ 同名 `.html`（例：`數值報告_宙斯 2500`、`數值報告_超級鑽石`、`數值報告_錢來襲`），兩份內容一致；不另取其他檔名。舊名 `差異分析_<遊戲中文名>` 一律改為此名。
- 遊戲名稱一律用英文名（例：Super Diamond、Super Ace、Lucky Ace），不用 H0xx 代號。
- HTML 版式同 `市場資訊/H5/遊戲資訊/` 的競品分析報告：每章一個頁簽、頁簽只排一列可橫拉但不顯示拉條；表格不得出現橫向拉條（儲存格自動換行）。
- 百分比表格套條件式橫條（同競品報告：同表共用刻度、最大值以強調色、合計列不畫）；表格內只放百分比，不附括號內的分子／分母。

**比較口徑**

- 本作與前作一律用 **Card-On**（正式 RTP／Variant、Oldhand）報表；競品用實機側錄資料。自然機率（Card-Off）只可作附加欄，不得當主比較欄。
- 模擬在模擬機執行（NB ≥ 10⁶ 局、BF ≥ 10⁵ 次），報表存 `Record/` 並在報告來源表列出檔名。
- 指標口徑與競品報告一致；口徑不同時（例：分母只算初始盤面）以競品口徑為準並在該節說明。

**必要章節**

| 章節 | 內容 |
|---|---|
| 0. 核心指標 | Total RTP、BG Hit Rate、FG Hit Rate（每轉）、FG 週期 |
| 1. 金框比例 | 平均每盤金框數、每格金框率、有金框盤面占比、各輪金框率（BG／FG 分開） |
| 2. 金框使用率 | 被消到而翻牌的金框數 ÷ 初始盤面金框數（BG／FG 分開） |
| 3. 倍率線型 | NB-BG、NB-FG、BF 三張折線圖，每張都含競品、前作、本作；64 區間全標；縱軸固定（BG 0–1%、FG／BF 0–16%），超過上限的區間不繪製並在圖下列出；附 FG／BF 門檻機率表 |
| 4. 連消分布 | BG 每局、FG 每轉的 0／1／2／3／4／5+ 次，含與競品的差（pp） |
| 5. 大鬼出現率 | BG 每局、FG 每轉；並註明本作 BG 幾局一次、FG 每場幾次 |
| 6. 符號消除分布 | 各符號 3／4／5 連的 Hit Rate 與 RTP（BG／FG 分開） |
| 7. WILD 倍數分布 | 有帶倍數 Wild 的遊戲才需要：各種 Wild（如小鬼、大鬼本體、分裂）分開列各倍數占比 |

沒有對應機制的章節（例如無金框、無大鬼）可省略，但要在報告開頭註明。指標未達使用者設定的對標目標時，於回報中列出差距與可調的槓桿，由使用者決定是否調整；調整後重跑 Card-On 並重出數值報告。

## 7. 異動時的重跑範圍

| 異動 | 必做流程 |
|---|---|
| Paytable、Reel、Table、Feature、Bet Mode、判獎 | 更新基礎 XLSX與版本 → 同步受影響 RTP／Variant → 轉 Config → 全部受影響批次重跑 → Demogame 對帳 |
| Card System 區間或權重 | 更新受影響 RTP／Variant XLSX 第 2 碼 → 轉 Config → Card System On 批次重跑 → 檢查占比與 Retry |
| SCR | 更新受影響 RTP／Variant XLSX 第 3 碼 → 轉 Config → 重跑 SCR 相關批次 |
| 文件、說明或排版 | 依規格更新第 4 碼；若不影響執行結果，不沿用舊版號產生新正式報表 |
| Simulator 數學邏輯 | 修正程式 → 固定 Seed 回歸 → 小場次 → 所有受影響正式批次 → Demogame 對帳 |
| 報表或顯示邏輯 | 驗證統計來源未變 → 核對 Console 與 Excel → 依影響範圍重產報表 |

## 8. 禁止事項

- 未確認 Game Rule 就自行補猜核心數學規則。
- 直接修改由 XLSX 產生的 Config 參數來避開轉檔。
- 建立或保留 Excel↔Config、Config↔Excel 的轉檔工具；轉換一律由 AI 執行。
- Simulator、Demogame 與 Config 各維護一套參數。
- 只跑 Card System On，不保留自然機率基準。
- 只驗證 Total RTP，不驗證 RTP Breakdown、分布、Feature 與 Retry。
- Card System Retry 時重抽目標卡、重複扣款或污染場次統計。
- 未升版就覆寫正式 XLSX、Config 或 Record。
- 建立產品未使用的空白 B Variant、Mode 或 Profile。
- 直接複製舊專案的不相容命名、版本、報表欄位或遊戲專屬統計。
- 用全零欄位表示不存在或尚未驗證的功能。
