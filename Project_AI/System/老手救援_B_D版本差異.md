# 老手救援 B／D 版本差異整理

## 1. 版本定位

B 版與 D 版的共同目的，都是在玩家 RTP 過低時介入救援，避免玩家於遊戲過程中累積過大的損失。

兩者的主要差異如下：

- **B 版**：以玩家為單位，觀察跨遊戲的遊玩歷程，於隨機判定點計算 RTP，並透過 Free Game 將玩家動態救回目標 RTP。
- **D 版**：以單次模擬中的玩家為單位，每 150 轉固定檢查一次區間 RTP，再依固定門檻將檢查點當局得分改成指定分數。

---

## 2. 功能差異總表

| 比較項目 | B 版本 | D 版本（目前程式） |
|---|---|---|
| 功能目的 | 玩家輸到一定程度時，透過 FG 救回目標 RTP | 每 150 轉依區間 RTP，調整檢查點當局得分 |
| 啟用時間 | 新手期 200 轉結束後，再累積 100 轉作為基底，約第 301 轉後開始 | 第 150 轉開始判定 |
| 判定時間 | 在返還區間內隨機選擇判定回合 | 固定於第 150、300、450、600……轉判定 |
| 判定頻率 | 文件寫每 150 轉選一個回合，但範例看起來可能每 50 轉選一次 | 固定每 150 轉一次 |
| RTP 計算區間 | 往前抓 `100 + N` 轉，長度隨判定位置變動 | 固定計算最近 150 轉 |
| 觸發門檻 | 單一門檻：RTP `< 50%` | 多段門檻：35%、55%、90%；第三階段為 40%、46%、90% |
| 救援目標 | 動態計算返還金額，將玩家救回指定 RTP | 使用固定結果：0、1000、2000、3500 分 |
| 救援形式 | 贈送一個 Free Game | 直接覆蓋檢查點當局得分 |
| 救援金額 | 依目前輸贏與目標 RTP 動態計算 | 依 RTP 所在區間查固定獎勵表 |
| 卡片系統 | 從指定倍數區間挑選適合的 FG 結果 | 沒有卡片區間或 FG 選擇 |
| 高 RTP 限制 | 文件未另外區分 | 第三階段前 500 轉 RTP `> 100%` 時切換 Mini 獎勵 |
| 獎勵互斥 | 救援 FG 不可同時觸發 Jackpot、Grand 等其他獎勵 | 沒有排除其他獎勵，只會改寫當局總分 |
| 玩家資料範圍 | 以玩家為單位，所有遊戲的紀錄共同計算 | 每次模擬獨立，只使用目前產生的遊戲結果 |
| 資料持久化 | 後端需保存玩家的跨遊戲遊玩歷程 | 沒有資料庫或跨遊戲紀錄 |
| 對後續判定的影響 | 救援結果應納入玩家後續 RTP | 先前改寫的救援結果會影響後續 RTP 判定 |

## 3. B 版機制

### 3.1 功能目的

從 RTP 的角度觀察玩家的遊戲歷程。當玩家累積損失達到一定程度時，透過 Free Game 將玩家救回不會輸太多的狀態，以延長玩家的遊戲體驗。

### 3.2 數值設定

| 參數 | 設定 |
|---|---|
| 新手期 | 200 次 Spin |
| 老手基底期 | 新手期結束後再進行 100 次 Spin |
| 適用時間 | 約第 301 次 Spin 後 |
| 返還區間 | 150 次 Spin |
| RTP 計算區間 | 往前計算 `100 + N` 次 Spin |
| 觸發門檻 | RTP `< 50%` |
| 文件所述返還目標 | RTP `55%` |
| 救援方式 | 贈送一個 Free Game |

### 3.3 判定流程

```text
新手期200轉結束
→ 再進行100轉作為老手基底
→ 進入返還區間
→ 在區間內隨機選擇判定回合
→ 往前抓取100+N轉，計算玩家跨遊戲RTP
→ 若RTP < 50%，則觸發救援
→ 計算需要返還的金額
→ 從卡片系統的指定倍數區間選擇FG結果
→ 執行救援FG，且不得同時觸發其他獎勵遊戲
```

### 3.4 文件範例

以第 351～450 轉為例：

1. 在第 351～400 轉之間隨機選出判定點 `N1`。
2. 假設 `N1 = 370`，則 `N = 20`。
3. 玩家進行至第 370 轉時，往前統計 `100 + 20 = 120` 轉的 RTP。
4. 若 RTP `< 50%`，依返還公式計算救援金額並觸發 FG。
5. 在第 401～450 轉之間再隨機選出判定點 `N2`。
6. 假設 `N2 = 411`，則 `N = 11`，往前統計 111 轉的 RTP。
7. 重複相同判定流程。

> 文件註明此流程為概念說明，實際後端流程可能略有差異。

### 3.5 FG 倍數區間

救援結果從卡片系統所定義的倍數區間中擷取，目前列出的區間為：

```text
(15x, 20x]
(20x, 25x]
(25x, 30x]
(30x, 35x]
(35x, 40x]
(40x, 45x]
(45x, 50x]
(50x, 60x]
(60x, 70x]
(70x, 80x]
(80x, 90x]
(90x, 100x]
```

### 3.6 特殊規則

- 救援機制觸發時，不可同時觸發其他獎勵遊戲，例如 Jackpot Game。
- 以「龍意發」為例，救援期間不會出現 15 顆滿盤觸發 Grand 的機率。
- 新手期結束後，會先累積 100 場作為老手救援的計算基底。
- 機制以玩家為單位，玩家在所有遊戲中的遊玩紀錄，都會納入觸發判斷所使用的 RTP 計算。

## 4. D 版機制

D 版目前實作於 `Project_AI/System/老手救援.py`。

### 4.1 判定流程

```text
抽取每局的一般得分與JP得分
→ 第150轉檢查第1～150轉RTP
→ 第300轉檢查第151～300轉RTP
→ 第450轉開始，每150轉檢查最近150轉RTP
→ 依RTP區間取得固定救援分數
→ 將檢查點當局的原始得分替換為救援分數
```

### 4.2 第一、二階段

第一階段於第 150 轉判定，第二階段於第 300 轉判定。

| 區間 RTP | 設定得分 |
|---:|---:|
| `< 35%` | 3500 |
| `35%～< 55%` | 1000 |
| `55%～< 90%` | 0 |
| `≥ 90%` | 不處理 |

### 4.3 第三階段一般模式

第三階段從第 450 轉開始，之後每 150 轉判定一次。

| 區間 RTP | 設定得分 |
|---:|---:|
| `< 40%` | 3500 |
| `40%～< 46%` | 2000 |
| `46%～< 90%` | 0 |
| `≥ 90%` | 不處理 |

### 4.4 第三階段 Mini 模式

進入第三階段時，程式會檢查判定回合之前最多 500 轉的 RTP：

- 前 500 轉 RTP `> 100%`：使用 Mini 獎勵。
- 前 500 轉 RTP `≤ 100%`：使用一般第三階段獎勵。

Mini 模式的門檻仍為 40%、46%、90%，但獎勵改為：

| 區間 RTP | 設定得分 |
|---:|---:|
| `< 40%` | 3500 |
| `40%～< 46%` | 0 |
| `46%～< 90%` | 0 |
| `≥ 90%` | 不處理 |

因此 Mini 模式只有 RTP `< 40%` 時，才會提供正向救援分數。

## 5. 兩版核心差異

### 5.1 固定補分與動態補足

- B 版依玩家目前 RTP 與目標 RTP 的差距，動態計算應返還金額。
- D 版不計算實際差額，只依 RTP 區間套用固定分數。

### 5.2 Free Game 與直接改寫結果

- B 版透過 Free Game 提供救援，並需要從卡片倍數區間選擇適合結果。
- D 版沒有實際產生 Free Game，而是直接改寫指定回合的得分。

### 5.3 隨機判定與固定判定

- B 版在返還區間內隨機選擇判定回合。
- D 版固定於每 150 轉的區間終點判定。

### 5.4 浮動視窗與固定視窗

- B 版使用 `100 + N` 轉的浮動 RTP 計算區間。
- D 版使用固定 150 轉的 RTP 計算區間。

### 5.5 跨遊戲與單次模擬

- B 版以玩家為核心，所有遊戲紀錄都要納入計算。
- D 版只處理目前模擬產生的局數，沒有跨遊戲或歷史資料。

## 6. B 版待確認事項

### 6.1 返還目標與公式不一致

文件寫明返還目標為：

```text
RTP = 55%
```

但目前提供的公式是：

```text
返還金額 = (0.95 - Total Win / Total Bet) × Total Bet
```

公式中的 `0.95` 代表將 RTP 補到 95%，與文件所述的 55% 不一致。

如果目標確定為 55%，公式應為：

```text
返還金額 = (0.55 - Total Win / Total Bet) × Total Bet
```

亦可化簡為：

```text
返還金額 = 0.55 × Total Bet - Total Win
```

範例：

```text
Total Bet = 12,000
Total Win = 4,800
目前RTP = 4,800 ÷ 12,000 = 40%

返還金額 = 0.55 × 12,000 - 4,800
         = 1,800
```

救援後總贏分為 6,600，RTP 為 55%。

### 6.2 返還區間與判定頻率不一致

文件寫明：

```text
每一個150把返還區間，從中挑出一個判定回合。
```

照此描述，若返還區間為第 301～450 轉，理論上整個區間只應選擇一個判定點。

但範例分別在下列區間選擇判定點：

- 第 351～400 轉選擇一次。
- 第 401～450 轉再選擇一次。

範例呈現的行為比較接近「每 50 轉選擇一個判定點」。因此仍需確認：

1. 真正的判定頻率是每 150 轉一次，還是每 50 轉一次？
2. 第 301～350 轉是否也會選擇一個判定點？
3. `N` 是以每個 50 轉子區間的起點計算，還是以完整 150 轉返還區間的起點計算？

### 6.3 卡片倍數與精確返還金額的關係

B 版先計算精確返還金額，但實際 FG 結果只能從既有卡片倍數區間中選擇，因此仍需確認：

- 應選擇最接近返還金額的區間，還是不得低於目標的區間？
- FG 實際結果高於或低於目標金額時，是否需要再次補償？
- 若返還需求低於 15x 或高於 100x，應如何處理？

---

## 7. 結論

B 版是一套完整的後端玩家保護機制，包含：

- 玩家層級的跨遊戲紀錄。
- 隨機判定時間。
- 浮動 RTP 計算視窗。
- 動態返還金額。
- Free Game 與卡片區間選擇。
- Jackpot、Grand 等獎勵互斥。

D 版則偏向獨立的數學模擬工具，主要特性為：

- 固定每 150 轉判定。
- 固定 150 轉 RTP 視窗。
- 固定獎勵表。
- 直接替換當局得分。
- 不包含真正的 Free Game、跨遊戲紀錄或獎勵互斥流程。

因此，若要將目前 D 版程式改為 B 版，不能只調整 RTP 門檻與獎勵參數，還需要重新設計判定排程、玩家歷史資料、動態返還、卡片選擇、Free Game 觸發及獎勵互斥等流程。
