## 2. 新手體驗

### 2.1 A 版

版本日期：2025-10-15

來源頁次：PDF 第 6～8 頁

#### 2.1.1 功能目的

推廣遊戲並協助新玩家理解遊戲特色。期望大部分玩家遊玩至第 50 場遊戲時，至少已經體驗並了解 Free Game、Mini Game 等遊戲特色，以及遊戲的主要得分方式。

#### 2.1.2 適用條件

玩家必須同時符合以下條件：

- 遊玩局數位於第 21～50 把。
- 當下押注 `Bet < 20`。
- 玩家尚未體驗過遊戲特色 Free Game。
- Buy Feature 不列入「已體驗 Free Game」的判定條件。

#### 2.1.3 體驗內容

- 系統直接贈送玩家一場 Free Game。
- Free Game 的目標倍數區間為 `(15x, 20x]`。
- 倍數區間計算需考慮 Scatter Pay。

#### 2.1.4 成本限制

- 所有遊戲合計的單日投入成本為 50 萬。
- 當玩家使用體驗功能所產生的成本超過此數字後，系統關閉新手體驗功能。

#### 2.1.5 執行流程

1. 系統在玩家第 21～50 把中隨機選擇一個判定回合。
2. 玩家進行至該回合時，檢查是否曾經觸發 Free Game；由救援機制觸發的 Free Game 也算已體驗。
3. 符合條件時，直接贈送一場平均倍數位於 `(15x, 20x]` 的 Free Game。

#### 2.1.6 特殊規則

- 新手體驗與新手救援不可在同一回合觸發；若兩者隨機到相同回合，必須避開。
- 新手體驗不會觸發 Mini Game。
- 系統會計算玩家從開始遊玩到觸發回合之前的平均押注，不包含觸發當下這一把。
- 若觸發當下的押注高於先前平均押注，取消本次新手體驗，以避免玩家透過提高單次押注套利。
- 使用 Extra Bet 時，以 Extra Bet 的 Total 作為倍數及金額計算基準。例如 Extra Bet 為 Bet 1 的 8 倍時，體驗金額使用 `8 × (15～20)` 計算。

#### 2.1.7 Scatter Pay 處理

若遊戲的 Free Game 觸發本身帶有 Scatter Pay，卡片系統選擇結果時需要將 Scatter Pay 納入考量。

原始文件範例：

1. 系統預計提供 19 倍的體驗結果。
2. Free Game 觸發時會先支付 3 倍 Scatter Pay。
3. 卡片系統以 `19 - 3 = 16` 倍尋找 `(15x, 20x]` 的遊戲結果。
4. 若卡片系統最後輸出 19 倍，再加上 3 倍 Scatter Pay，玩家實際獲得 22 倍。

因此，實際總倍數可能超出原先設定的 20 倍上限。

#### 2.1.8 待確認事項

- Free Game 使用卡片系統產生結果時，後端無法直接在返還金額中精確處理 Scatter Pay。
- 成本估算方式需要額外納入 Scatter Pay。
- 文件的功能目的提到希望玩家理解 Mini Game，但此版本特殊規則明定新手體驗不會觸發 Mini Game。

## 3. 老手救援

### 3.1 A 版

版本日期：2025-10-15

來源頁次：PDF 第 19～21 頁

#### 3.1.1 功能目的

避免玩家長時間處於低 RTP 狀態。當玩家累積損失達到一定程度時，系統透過 Free Game 或一把高分 Base Spin，返還部分玩家輸掉的金額，以改善玩家體驗。

#### 3.1.2 數值設定

| 參數 | 設定 |
|---|---|
| 適用期間 | 老手期，第 200 轉後 |
| 偵測單位 | 每 100 把 |
| RTP 計算資料 | 當下 100 把加上前 100 把，共 200 把 |
| 觸發門檻 | RTP `< 30%` |
| 返還比例 | 玩家損失金額的 25% |

#### 3.1.3 返還金額

```text
返還金額 = (Total Bet - Total Win - Scatter Pay) × 25%
```

有 Scatter Pay 的遊戲需要進行特殊處理。

#### 3.1.4 返還倍數區間

```text
(15x, 20x]
(20x, 25x]
(25x, 30x]
(30x, 35x]
(35x, 40x]
(40x, 45x]
(45x, 50x]
(50x, 60x]
(60x, 70x]
(70x, 80x]
(80x, 90x]
(90x, 100x]
```

這些區間取自卡片系統所定義的倍數區間。

#### 3.1.5 執行流程

以第 351～450 把為例：

1. 將區間切成 351～360、361～370……441～450 等 10 把子區間。
2. 從每個子區間挑選一個判定 Spin。
3. 玩家進行至選定 Spin 時，抓取前 100 把與當下 100 把的 Total Win、Total Bet，共計 200 把資料。
4. 計算 RTP，判斷是否低於 30%。
5. 若符合條件，以玩家損失金額的 25% 計算返還金額。
6. 判定返還金額所屬的倍數區間。
7. 使用卡片系統重骰，直到 Spin 結果落入選定區間。

#### 3.1.6 跨遊戲資料規則

- 機制以玩家為單位。
- 所有遊戲的遊玩紀錄都會納入 RTP 計算。
- 例如玩家先在遊戲 A 玩 50 把，再到遊戲 B 玩 50 把，系統會合併這 100 把作為偵測資料。
- 新手期結束後，先額外累積 50 場作為判斷基底。

#### 3.1.7 特殊規則

- 救援觸發時，不得同時觸發其他獎勵遊戲，例如 Jackpot Game。
- 以「龍意發」為例，救援期間不會出現 15 顆滿盤觸發 Grand 的結果。

### 3.2 B 版

版本日期：2025-10-15

來源頁次：PDF 第 22～26 頁

#### 3.2.1 功能目的

從 RTP 角度觀察玩家的遊戲歷程。當玩家累積損失達到一定程度時，透過 Free Game 將玩家救回不會輸太多的狀態，以延長玩家的遊戲體驗。

#### 3.2.2 數值設定

| 參數 | 設定 |
|---|---|
| 適用期間 | 老手期 100 次 Spin 後，即第 200＋100 轉後 |
| 返還區間 | 150 次 Spin |
| RTP 計算區間 | `100 + N` 次 Spin |
| 觸發門檻 | RTP `< 50%` |
| 返還目標 | RTP `55%` |

#### 3.2.3 機制說明

- 每一個 150 把返還區間中，選擇判定回合。
- 每次判定時，往前抓取 `100 + N` 把計算 RTP。
- 若 RTP 低於 50%，贈送一個 Free Game，將玩家 RTP 救回目標值。

#### 3.2.4 原始返還公式

```text
返還金額 = (0.95 - Total Win / Total Bet) × Total Bet
```

#### 3.2.5 返還倍數區間

```text
(15x, 20x]
(20x, 25x]
(25x, 30x]
(30x, 35x]
(35x, 40x]
(40x, 45x]
(45x, 50x]
(50x, 60x]
(60x, 70x]
(70x, 80x]
(80x, 90x]
(90x, 100x]
```

這些區間取自卡片系統所定義的倍數區間。

#### 3.2.6 執行流程

以第 351 把後為例：

1. 在第 351～400 把中隨機選擇判定點 `N1`。
2. 假設 `N1 = 370`，則 `N = 20`。
3. 玩家進行至第 370 把時，往前統計 `100 + 20 = 120` 把的 RTP。
4. 若符合觸發條件，依返還公式計算並返還玩家金額。
5. 在第 401～450 把中隨機選擇下一個判定點 `N2`。
6. 假設 `N2 = 411`，則 `N = 11`，往前統計 111 把的 RTP。
7. 後續持續重複相同流程。

原始文件註明，此流程為概念說明，實際後端流程可能略有差異。

#### 3.2.7 跨遊戲資料規則

- 機制以玩家為單位。
- 玩家在所有遊戲中的遊玩紀錄，都會納入觸發判斷所使用的 RTP 計算。
- 新手期結束後，先累積 100 場作為老手救援的計算基底。

#### 3.2.8 特殊規則

- 救援觸發時，不得同時觸發其他獎勵遊戲，例如 Jackpot Game。
- 以「龍意發」為例，救援期間不會出現 15 顆滿盤觸發 Grand 的結果。

#### 3.2.9 已知問題與待確認事項

- 文件的返還目標寫 RTP 55%，但返還公式中的 `0.95` 代表補到 RTP 95%，兩者不一致。
- 文件寫每 150 把選擇一個判定回合，但範例分別在 351～400 與 401～450 各選一次，判定頻率需要確認。
- Extra Bet 為 8 倍時，救援返還上限理論上應為 800 倍，但實際上限只有 100 倍。
- 原始討論紀錄指出，8 倍押注玩家占比不高，因此上述上限問題暫不修改。
- 需要確認老手期玩家的平均遊玩把數。

- 新手期結束後，先累積 100 場作為老手救援的計算基底。

#### 3.3.8 特殊規則

- 救援觸發時，不得同時觸發其他獎勵遊戲，例如 Jackpot Game。
- 以「龍意發」為例，救援期間不會出現 15 顆滿盤觸發 Grand 的結果。

#### 3.3.9 待確認事項

- 數值設定區寫觸發門檻為 50%、返還目標為 60%。
- 功能介紹區寫觸發門檻為 85%、返還目標為 95%。
- 上述兩組門檻與目標互相衝突，需確認正式採用值。
- 「返還區間 50 次 Spin－100／200」中的 100／200 定義不明。
- 「返還至 RTP 60%－8%／16% 使用率」中的使用率定義與適用條件不明。
- 需要確認老手期玩家的平均遊玩把數。

### 3.4 D 版

來源：`Project_AI/System/老手救援.py` 現行程式實作

#### 3.4.1 功能目的

D 版以固定週期檢查玩家的區間 RTP。當區間 RTP 落入指定門檻時，程式將判定回合的原始得分替換成設定好的救援分數。

目前程式為獨立模擬工具，沒有串接玩家資料庫、跨遊戲紀錄或真正的 Free Game 流程。

#### 3.4.2 基礎遊戲模型

- 每局投注基準視為 100 分。
- 每局先依倍率權重抽出一般得分。
- 再獨立抽取 Jackpot 得分。
- 一般得分與 Jackpot 得分相加，形成當局原始得分。
- 依現行權重計算，基礎理論 RTP 約為 `96.006264%`。
- 預設模擬每位玩家 3000 轉。

#### 3.4.3 第一階段

- 判定回合：第 150 轉。
- RTP 區間：第 1～150 轉。

| 區間 RTP | 設定得分 |
|---:|---:|
| `< 35%` | 3500 |
| `35%～< 55%` | 1000 |
| `55%～< 90%` | 0 |
| `≥ 90%` | 不處理 |

#### 3.4.4 第二階段

- 判定回合：第 300 轉。
- RTP 區間：第 151～300 轉。

| 區間 RTP | 設定得分 |
|---:|---:|
| `< 35%` | 3500 |
| `35%～< 55%` | 1000 |
| `55%～< 90%` | 0 |
| `≥ 90%` | 不處理 |

#### 3.4.5 第三階段一般模式

- 判定回合：第 450、600、750……轉。
- 判定週期：每 150 轉一次。
- RTP 區間：每個判定點所屬的最近 150 轉。

| 區間 RTP | 設定得分 |
|---:|---:|
| `< 40%` | 3500 |
| `40%～< 46%` | 2000 |
| `46%～< 90%` | 0 |
| `≥ 90%` | 不處理 |

#### 3.4.6 第三階段 Mini 模式

每次進入第三階段判定時，程式會檢查判定回合之前最多 500 轉的 RTP：

- 前 500 轉 RTP `> 100%`：使用 Mini 獎勵。
- 前 500 轉 RTP `≤ 100%`：使用第三階段一般獎勵。

Mini 模式的 RTP 門檻仍為 40%、46%、90%，獎勵設定如下：

| 區間 RTP | 設定得分 |
|---:|---:|
| `< 40%` | 3500 |
| `40%～< 46%` | 0 |
| `46%～< 90%` | 0 |
| `≥ 90%` | 不處理 |

因此，Mini 模式只有在區間 RTP `< 40%` 時會提供正向救援分數。

#### 3.4.7 執行流程

1. 程式先產生不含救援的每局原始結果。
2. 複製原始結果，建立含救援版本。
3. 依第 150、300、450、600……轉的排程進行 RTP 判定。
4. 依 RTP 所屬區間取得設定得分。
5. 將判定回合的原始得分替換為設定得分。
6. 記錄每位玩家的救援次數及救援明細。
7. 後續 RTP 計算使用已套用先前救援的結果。

救援明細記錄格式為：

```text
(判定回合, 階段, 判定時RTP%, 設定得分)
```

#### 3.4.8 統計輸出

程式可統計：

- 各玩家救援次數。
- 各階段可觸發次數與實際觸發次數。
- 各救援分數的使用次數與占比。
- 平均、最大及最小救援次數。
- 套用救援前後的整體 RTP。
- 從第 16 局開始計算的打平次數。
- 救援對總得分的實際貢獻。

#### 3.4.9 現行程式行為注意事項

- 救援分數會覆蓋判定回合原始得分，不是額外加上去。
- 若原始得分高於救援分數，救援後總得分可能反而下降。
- 設定得分為 0 時，程式仍視為已觸發救援，會將當局得分改成 0 並增加救援次數。
- 判定區間 RTP 包含判定回合尚未改寫前的原始得分。
- 第三階段所稱的「前 500 轉」不包含當前判定回合；第 450 轉時實際只有前 449 轉可供計算。
- 第一階段與第二階段使用 `n_rounds > 150`、`n_rounds > 300` 的條件，因此模擬局數剛好為 150 或 300 時不會執行該階段。
- 第三階段模擬與統計函式對剛好第 450 轉的邊界條件不一致。

## 4. 名詞說明

| 名詞 | 說明 |
|---|---|
| Bet | 玩家單次遊戲的押注金額。 |
| Total Bet | 指定統計區間內的累計押注金額。 |
| Total Win | 指定統計區間內的累計得分或派彩金額。 |
| RTP | `Total Win ÷ Total Bet`，用於表示玩家在指定區間內的返還比例。 |
| Spin／把／轉 | 一次遊戲回合。本文依來源內容交替使用。 |
| Free Game／FG | 免費遊戲功能。部分版本透過贈送 Free Game 提供體驗或救援。 |
| Mini Game／Mini Bonus | 遊戲中的小型獎勵功能；各版本文件中的名稱及對應關係需依實際遊戲定義。 |
| Buy Feature | 玩家付費直接購買遊戲特色的功能。部分版本不將 Buy Feature 視為自然體驗紀錄。 |
| Scatter Pay | Scatter 符號觸發特色前所支付的得分，可能使實際總倍數超出卡片目標區間。 |
| Extra Bet | 額外押注模式。計算體驗或救援金額時，需使用對應的實際投注總額。 |
| 卡片系統 | 依倍數區間抽選或重骰遊戲結果的系統。 |
| Jackpot Game | 彩金獎勵遊戲。救援機制觸發時通常不得同時觸發。 |
| Grand | Jackpot 的高階獎項。來源文件以 15 顆滿盤觸發 Grand 作為互斥範例。 |
