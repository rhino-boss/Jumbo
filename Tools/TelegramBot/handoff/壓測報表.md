## 三、壓測數據整理

機器人吃**兩種**完全不同的輸入，走兩條路：

### 3.1 RTP Validator 逐分支 TXT（走檔案上傳）→ 產出 xlsx

- 進入點：`document_handler` L1857，接受 `.zip` / `.rar` / `.txt`
- 解壓：支援巢狀壓縮，最深 `MAX_ARCHIVE_DEPTH = 10`；rar 需要外部 7z（`SEVENZIP_CANDIDATES` L83）
- 多檔會先等 `ARCHIVE_BATCH_DELAY_SECONDS = 2` 秒收集成一批再處理（`process_archive_batch_after_delay` L949）
- 解析欄位：`VALIDATOR_HEADER_PATTERNS` L89

| 欄位 | 來源 regex |
|---|---|
| GameID / optionID / Coin in / TotalSpin | 同名欄位 |
| TotalRtp (including JP/bonus) / avgPeriod | 同名欄位 |
| BaseGameRtp / ScatterRtp / FreeGameRtp | 同名欄位 |
| BonusJP Rtp / LinkJP Rtp | 大小寫都收（`Rtp` 與 `RTP`） |
| `pool[n] rtp` | `pool\[(\d+)\].*?rtp\s*=\s*([0-9.]+)` |
| 最大倍數 BG／FG／B2F | `extract_max_multiplier_fields` L477 |

- **`RTP Game` 是算出來的，不是讀出來的**：`calculate_game_rtp` L527 = `BaseGameRtp + FreeGameRtp`，**不含 Scatter**
- 同設定多筆會依 `AVERAGE_GROUP_FIELDS` L142 取平均（`build_average_validator_rows` L767）
- 輸出欄位順序：`VALIDATOR_OUTPUT_COLUMNS` L107
- 檔名：偵測到壓測標記時存成 `{timestamp}_{stem}_壓測.xlsx`，否則一般檔名
- 壓測標記判定：`has_stress_test_summary` L519 —— 文字裡有 `Taste (Newbie) TotalWin=` 或 `Relief (Veteran) TotalWin=`

### 3.2 Formal RTP Report（走文字訊息）→ 產出 TG 表格 ＋ 更新進度

- 進入點：`main_handler` L2373 → `parse_rtp_report` L983
- 觸發條件：文字同時含 `Formal RTP Report` 與 `Scenario RTP`
- 解析出來的結構：

```
檔頭： Report ID / Generated At / machineType(=Game ID) / extraBet(=BetType) / Bet / OldHand Init
Scenario RTP 段： 每列一個時間切片，底下三行 - Game RTP / - Jackpot RTP / - Bonus Game RTP
SettingID RTP 段： SettingID N （名稱），底下同樣三行
SettingID Trigger Count 段： 解析到這裡就 break，內容沒讀
```

- 輸出：`format_rtp_report_summary` L1284 產生 HTML 表格，由 `send_rtp_report_summary` L1467 送出

## 四、判斷壓測成功的規則（完整）

全部在 `format_rtp_report_summary` L1284~1466。

### 4.1 五個時間切片欄

`SCENARIO_COLUMN_SPECS` L1168，`classify_scenario_row` L1177 做標籤對應：

| 欄 key | 顯示 | 來源標籤（去空白後比對） | 是否判定 |
|---|---|---|---|
| `overall` | 整體 | 含「整體RTP」 | 只判 `0 ≤ x < 100%` |
| `first_50` | ~50 | 含「前50次Spin」 | 只判 `0 ≤ x < 100%` |
| `first_200` | ~200 | 含「前200次Spin」或「前100次Spin」 | 只判 `0 ≤ x < 100%` |
| `old_before_200` | OG ~200 | 含「RTP」且有 `<=200` `≤200` `<=100` `≤100` | **依目標判定** |
| `old_after_200` | OG 200~ | 含「RTP」且有「以後」或 `>200` `>100` | **依目標判定** |

前三欄的判定在 `game_values_pass` L1250：只檢查 index 0~2 落在 `0 ≤ x < 100`，真正比目標的是 index 3、4。

### 4.2 模式判定

| 變數 | 判定方式 | 位置 |
|---|---|---|
| `bet_type` | `extraBet` 開頭的數字 | `extract_bet_type` L1138 |
| `is_bf` | `bet_type ∈ {"3","4"}` | L1294 |
| `is_old_hand` | `OldHand Init == "enabled"`；欄位缺就退回「任一 Jackpot RTP > 0」 | L1296~1301 |
| `is_low_bet` | **一般模式直接 `Bet < 2`**，不乘模式倍率 | L1307（程式註解有明寫） |
| BF 的低押注 | `Bet ÷ 模式倍率 < 2` | `is_special_low_bet` L1327 |

`BET_TYPE_TO_STRESS_MODE` L63：`0→NB, 1→EX1, 2→EX2, 3→BF, 4→SF`

### 4.3 Game RTP 目標與容差

容差一律 **±1.0pp**（`game_values_pass` 的 tolerance 參數）。

| 條件 | OG ~200 目標 | OG 200~ 目標 |
|---|---:|---:|
| BF/SF | 92.5% | 92.5% |
| 非 BF、新手 | 93% | 低押注 94% / 高押注 92% |
| 非 BF、老手 | 低押注 94% / 高押注 92% | 低押注 94% / 高押注 92% |

### 4.4 Link（Jackpot RTP）目標與容差

容差規則特殊，在 L1372：**目標 0% 時容差 0（必須精確等於 0）**，非 0% 才套 ±1.5pp。
前三欄 `skip_indexes = {0,1,2}` 不判。

| 條件 | OG ~200 | OG 200~ |
|---|---:|---:|
| 非 BF、新手 | 0% | 低 0% / 高 2% |
| 非 BF、老手 | 低 0% / 高 2% | 低 0% / 高 2% |
| BF 低押注 | 0% | 0% |
| BF 高押注 | 老手 2% / 新手 0% | 2% |

### 4.5 Bonus（Bonus Game RTP）目標與容差

容差 **±0.5pp**，前三欄同樣 skip。

| 條件 | OG ~200 | OG 200~ |
|---|---:|---:|
| 非 BF | 2% | 2% |
| BF 低押注 | 4% | 4% |
| BF 高押注 | 老手 2% / 新手 4% | 2% |

### 4.6 新手體驗／老手救援

`get_setting_game_rtp` L1203：

- **新手體驗** = SettingID **2, 4, 5, 6, 7, 8** 的 Game RTP **加總**
- **老手救援** = SettingID **3** 的 Game RTP
- 兩者目標都是 **1%**、容差 **±1.0**（即 0%~2%）
- BF 報表不顯示「新手體驗」列

SettingID 名稱對照（`normalize_row_label` L1090）：
`一般→沒有機制`、`新手救援`、`老手救援`、`新手體驗 D→新手體驗 FG`、`新手 mini game 體驗 D→新手體驗 JP`

### 4.7 「壓測成功」的定義

`stress_report_core_passed` L1709：

> 用 regex 去抓 `format_rtp_report_summary` 產生的 HTML，
> **Game、Link、Bonus 三列的結果欄都必須是 ✅** 才算通過。

注意兩點：
1. **新手體驗／老手救援那兩列不列入 core passed 判定**，只是顯示。
2. 這個函式是「重新產生 HTML 再用 regex 解析回來」，不是直接拿布林值 —— 實作上有點繞，改表格格式會連帶弄壞判定。

## 五、壓測狀態紀錄

### 5.1 位置與格式

`STRESS_PROGRESS_FILE = BASE_DIR / "stress_test_progress.json"`（L57）
→ VM 上就是 `/opt/tgbot/stress_test_progress.json`（依 BASE_DIR 而定，BASE_DIR = .py 所在目錄）

格式：

```json
{
  "<Game ID>": {
    "<mode>:<size>:<hand>": {
      "report_id": "...",
      "time": "...",
      "bet": "..."
    }
  }
}
```

讀寫：`load_stress_progress` L1594 / `save_stress_progress` L1605（先寫 `.json.tmp` 再 replace，原子寫入）

### 5.2 自動更新流程

`update_stress_progress_from_report` L1732，在 `main_handler` 解析完報表後呼叫：

1. `stress_report_core_passed` 不通過 → 回 None，**不記錄**
2. 由 `machineType` 找遊戲、`extraBet` 找模式、`Bet` 配 `get_stress_bet_boundaries` 判小／中／大
3. 新老手由 `is_stress_report_old_hand` L1722 判定
4. 組出 `item_key = f"{mode}:{size}:{hand}"`，必須在 `build_stress_test_items` 的清單裡才記
5. 已存在就覆寫，回傳「已更新」或「已覆寫」訊息

### 5.3 查看進度

`/stress_test` → 選遊戲 → `format_stress_test_list` L1683
顯示 `進度：n/總數`，每個測項前面 ✅ 或 ⬜，依模式分組。

## 九、已知問題與踩雷

### 🔴 9.1 `game_list.md` 的押注欄位格式已經改掉，壓測功能會整個失效

**這是目前最嚴重的問題。**

程式讀押注倍率的方式（`STRESS_MODE_TO_COLUMN` L70 + `load_stress_games` L1496）：

```python
STRESS_MODE_TO_COLUMN = {
    "NB": "押注-NB", "EX1": "押注-EX1", "EX2": "押注-EX2",
    "BF": "押注-BF", "SF": "押注-SF",
}
...
"bets": {mode: row.get(column, "").strip() for mode, column in STRESS_MODE_TO_COLUMN.items()}
```

但 `game_list.md` 現在的表頭是：

```
| Game ID | ParSheet ID | 遊戲英文名稱 | 遊戲中文名稱 | 遊戲類別 | 押注 (NB/EX1/EX2/BF/SF) | RTP 版本 | 標準差 | ... |
```

**五個分欄已經合併成單一欄 `押注 (NB/EX1/EX2/BF/SF)`**，值長這樣：`NB 1 / BF 75`。

後果：`row.get("押注-NB")` 全部回空字串 → `parse_stress_multiplier` 回 None → 每個模式都被跳過
→ `build_stress_test_items` 回空清單 → `/stress_test` 對每個遊戲都顯示
「game_list.md 沒有寫 NB、EX1、EX2、BF 或 SF 的押注設定，請先更新。」
→ `update_stress_progress_from_report` 也會在 L1753 回 None，**進度永遠不會被記錄**。

修法：改 `load_stress_games`，從單一欄位解析 `NB 1 / BF 75` 這種字串
（切 `/`，每段再切空白取模式名與倍率）。

### 🔴 9.2 `game_list.md` 的 fallback 路徑已失效

`BASE_DIR.parent.parent / "Project" / "Slots" / "game_list.md"` —— 專案資料夾已重整，

### 🟡 9.3 目標值寫死，新的 RTP 家族會全部判失敗

程式把 92／93／94／92.5 寫死在 `format_rtp_report_summary` 裡。

例如 H028（Game ID 101016）有 **88B / 90B / 92A / 94A 四個 RTP 家族**，
降版組的 Oldhand Game RTP 是 **88% 與 90%**。這些報表丟進機器人會全部判 ❌。

建議把目標值改成從遊戲設定查，而不是寫死。

### 🟡 9.4 固定容差與壓測說明書的統計判定衝突

`工作區\壓測說明書.md` 裡使用者已經拍板「判定全面改成 95% 信賴區間」：

```
SE = σ / √N
|實測 − 目標| ≤ 1.96 × SE  →  通過
```

機器人目前還是固定容差（Game ±1.0、Link ±1.5、Bonus ±0.5）。實測對照：

| 項目 | 固定容差 | 相當於幾個標準誤 |
|---|---|---|
| Game | ±1.0pp | 3.4 ~ 7.0 |
| Bonus | ±0.5pp | 22 ~ 31（等於沒檢查） |
| Link（低押注） | ±1.5pp | 4.1 |
| Link（高押注） | ±1.5pp | 155 |

要改成 CI 需要 σ 與各 pool 的命中次數。**`Formal RTP Report` 裡有沒有這兩樣目前未確認** ——
RTP Validator 的 TXT 有 `pool[n] hit`，同批的 `log_*.txt` 有 `std`。
若 Formal Report 沒有，機器人要能同時吃兩種檔才能做統計判定。

### 🟡 9.5 `Game RTP` 口徑不一致

`calculate_game_rtp` L527 只加 `BaseGameRtp + FreeGameRtp`，**不含 Scatter**。
但 Validator TXT 的 `TotalRtp (excluding JP/bonus)` 是含 Scatter 的。
無 Scatter Pay 的遊戲兩者一致；**有 Scatter Pay 的遊戲會差一截**
（實測 Game ID 101027 的 ScatterRtp 約 0.70%，ExtraBet 下約 1.76%）。

### 🟡 9.6 `si_tb` 類的欄位說明不可盡信

歷史上遇過原始檔的欄位說明標錯（把「付費 spin 起始標記」標成「是不是 Bought Game」、
`si_st` 實際值是 `1/4/21/22` 而非文件寫的 `1/2/21/22`）。
接資料時要用筆數交叉驗證，不要照著欄位說明直接用。

### 🟡 9.7 `stress_report_core_passed` 的實作很脆弱

它是把 `format_rtp_report_summary` 產生的 HTML 再用 regex 解析回來拿 ✅／❌。
**只要動到表格的 HTML 結構，判定就會壞掉而且不會報錯**（regex 抓不到就一律當失敗）。
建議重構成讓 `format_rtp_report_summary` 同時回傳結構化結果。

- rar 解壓依賴外部 7z，`SEVENZIP_CANDIDATES` 列的路徑在 VM 上要確認裝了。

- 群組的 @ 窗口 180 秒內會「默默處理」符合條件的訊息，使用者可能不預期。
