`poolCount: 4` + 兩組 `poolInitValue`（GRAND / MAJOR / MINOR / MINI 的典型四層結構）強烈暗示**這遊戲有 Jackpot 彩金池**，而且 Buy Feature 進場時池值不同。但 `Game_Specification` 的 Game Notes、STAR METER、FREE SPINS、BUY BONUS 全部章節都沒有任何一個字提到彩金。

對照 H026：H026 的模型說明有專章 `1-8 OP Jackpot`，並在 Overview 明確拆出 `Bonus RTP` / `Link RTP` / `Total RTP` 與 `Hit JP Symbol appear rate`。H029 的 RTP_Summary **只有 Game RTP 一項，沒有任何彩金 RTP 拆解**。

> **需要對方確認：** 這四個獎池是實際啟用、還是引擎樣板留下的死參數？如果啟用，Total RTP 就不是 0.925，送驗數字會對不上。

### 1.2 FG 場次上限沒寫

`freeGameExtendSetting.maxRound = 50`。

`Game_Specification` 寫了三種 FG 的初始場次（6 / 8 / 7）與各種加場條件，但**完全沒提「單次 FG 最多 50 場」的硬上限**。這在 Multiplier Ladder 模式尤其關鍵——該模式光是階梯就會給 3+1+2+2+2 = 10 場，再加 `+1 FS` 符號，很容易撞到上限。

對照 H026：`game_rule.md` §7.2 明確寫「單次進入 FG 後包含 retrigger 在內，最多進行 50 場」。

### 1.3 Max Win / 封頂規則沒寫

## 二、模型／文件之間的矛盾與錯誤

### 2.1 嚴重：JSON 版本字串是別款遊戲

```
executeSetting[0][0].version = "H004191:1.0.0.0"
```

遊戲代號是 **JHS104001 / GameType 104001**，但 version 欄寫的是 **H004191**。這是從 H004 複製設定檔後沒改版本號。送驗時版本欄位對不上會直接被退。

### 2.2 嚴重：`DongDongKongData.xlsx` 的 RTP_94 / RTP_96 是別款遊戲的模板

| 項目 | RTP_92（本作） | RTP_94 / RTP_96 |
| --- | --- | --- |
| Base Game Total RTP | 61.72 | 47.19 / 47.17 |
| Free Game 結構 | 三種模式（A/B/C）＋ Gamble ＋ Buy | 單一 FG，無模式選擇 |
| Bonus Hits 標籤 | 無 | `8 FG Hits`（本作是 6/8/7 場，不是「8 FG」） |
| Max Win | — | 100000（RTP_92 對應的模型表寫 96000） |

RTP_94 / RTP_96 兩張分頁的結構與本作完全不符，應是沿用其他遊戲的模板未更新。**目前也只有 `DongDongKong_92.xlsx` 一份模型檔，沒有 94 / 96 的模型檔。**

> **需要確認：** 94% / 96% 版本是還沒做，還是做了但沒放進來？

### 2.3 兩份檔案的 RTP 數字對不上

| 模式 | `DongDongKong_92.xlsx` RTP_Summary | `DongDongKongData.xlsx` RTP_92 | 差異 |
| --- | --- | --- | --- |
| Mystery Symbol (Normal) 總 RTP | 92.5906 | 92.6303 | 0.040 |
| Multiplier Ladder (Normal) 總 RTP | 92.3474 | 92.3464 | 0.001 |
| Expanding Wild (Normal) 總 RTP | 92.6192 | 92.6334 | 0.014 |
| Mystery Symbol FG RTP | 30.875 | 30.9149 | 0.040 |
| Expanding Wild FG RTP | 30.9036 | 30.918 | 0.014 |

檔案日期：`DongDongKongData.xlsx` = 7/30，`DongDongKong_92.xlsx` = 8/5。應是模型更新後 Data 檔沒同步。**送驗前必須統一，以哪一份為準要明確。**

### 2.4 RTP_Summary 上方摘要的 Hit Rate 標籤貼錯

```
第 6 列：Free Game Feature 3 [SCATTER] Hit Rate  →  38375.2
第 7 列：Free Game Feature 4 [SCATTER] Hit Rate  →  （空白）
```

但同表下方明細寫：

```
FG Feature Hit Rate            231.7
FG Feature Upgraded Hit Rate   38375.2   (high deviation)
```

3 個 Bonus 觸發（一般版）的週期是 **231.7**，4 個 Bonus（升級版）才是 **38375.2**。摘要區把 38375.2 標成「3 [SCATTER]」，且「4 [SCATTER]」留空。**標籤錯置，需修正。**

### 2.5 玩家選不同 FG 模式，RTP 不同

| 模式 | Normal 總 RTP | Gamble 總 RTP | Buy Normal | Buy Gamble |
| --- | --- | --- | --- | --- |
| Mystery Symbol | 0.925906 | 0.925212 | 0.925326 | 0.925038 |
| Multiplier Ladder | 0.923474 | 0.925739 | 0.924974 | 0.925039 |
| Expanding Wild | 0.926192 | 0.925008 | 0.925555 | 0.924459 |

最高 0.9262 與最低 0.9235 差 **0.27%**，而 Overview 的 `Return To Player` 只寫單一值 `0.925`。文件沒有任何說明解釋「玩家的模式選擇會影響 RTP」以及這個容差是否可接受。這在送驗時是一定會被問的點。

### 2.6 `Game Notes` 的 bet 說明與模型不符

```
Game Type: 4,096 ways in Main Game. 10 credit bet.
```

但 `Overview → Base Bet = 100`，JSON `betSpec.baseBet = 100`，且 payTable 是以 100 為基準（`Multiplying with Base Bet` 那張表 = 原始表 × 100）。**「10 credit bet」與模型不符**，應為 100（或是文字沒更新）。

`4,096 ways` 本身正確：`screenRow 4 × screenColumn 6` → 4⁶ = 4096 ✅
FG A 擴列後 4 × 7⁴ × 4 = 38416 ✅ 與 `Game_Specification` 第 76 列一致。

### 2.7 賠率表重複且有錯字

`Game_Specification` 右側同時有兩張 Pay Table（一張原始值、一張 ×Base Bet），沒有標示哪張是正式送驗用表。

左側 Oddstable `Pic 3 / 4 of a kind` 的值寫成 **`.1.5`**（多一個點），應為 `1.5`（右表 Pic C 4 連 = 1.5 可佐證）。
