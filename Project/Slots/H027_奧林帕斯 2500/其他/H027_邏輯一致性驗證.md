# H027 邏輯一致性驗證

驗證日期：2026-08-06

## 整體判定

目前 `index.html`、`config_92A.js`、`xlsx_to_config.py`、`config_to_xlsx.py`、`Simulator.py` 與 `H0271.xlsx` 的資料流及主要玩法邏輯一致，雙向轉換檢查通過，index 可由瀏覽器正常載入並進入 Ready 狀態。

Normal Bet 以卡片系統關閉執行 5,000 萬局，RTP 為 **107.2009%**；xlsx 內競品樣本參考值為 **106.8860%**，差 **+0.3148 個百分點**。總 RTP 接近，但 BG／FG 組成及 Hit Rate 尚未完全貼近競品，因此目前判定為「可測試，但仍有數學校準差異」，不能把 106.8860% 視為每次模擬必然得到的固定結果。

## 已修正問題

| 問題 | 原因 | 修正 |
| --- | --- | --- |
| ID 欄顯示錯誤或 `####` | 本機 Excel 不支援 `XLOOKUP`，實際重算為 `#NAME?`；欄寬也不足 | 兩個轉換工具統一改用 `VLOOKUP`，ID 欄寬改為 7，Weight 欄寬改為 11，並用 Excel 完整重算 |
| 模擬 RTP 約 50%，與競品 106% 差距很大 | 原輪帶只對齊單格符號比例，隨機打散後失去 Count Anywhere 所需的符號聚集關係 | 輪帶產生改為可重現的部分聚集排列，同時保留符號數量與 Scatter 規則 |
| xlsx 轉 config 會遺失 C3 各輪差異 | 只輸出單一 `weights` | 增加 `weights_by_reel`；index 與 Simulator 都依 reel 讀取 |
| 缺少 config 轉 xlsx | 無法驗證反向轉換 | 新增 `Source/config_to_xlsx.py` 與 `Source/update_xlsx.bat` |
| Simulator BF debug 表號寫死 | 寫死 table 8，但目前只有 7 組表 | 改用 `BF_TABLE_ID` |
| index 與 Simulator 卡片系統狀態不同 | index 未執行卡片過濾，但 Simulator 預設開啟 | Simulator 預設改為關閉；卡片參數仍保留供後續使用 |
| FG 結束累積倍數分析過高 | 競品 `apv` 是累積值，舊分析誤當增量加總 | 改取該場 FG 最大累積 `apv`；平均 21.10x、最大 33.00x |

## RTP 驗證

| 指標 | 競品樣本／xlsx 參考 | H027 5,000 萬局 | 差異 |
| --- | ---: | ---: | ---: |
| Total RTP | 106.8860% | 107.2009% | +0.3148pp |
| BG RTP | 75.9569% | 74.8680% | -1.0889pp |
| FG RTP | 30.9291% | 32.3328% | +1.4037pp |
| BG Hit Rate | 28.72% | 31.2967% | +2.58pp |
| FG Hit Rate | 43.81% | 30.1548% | -13.66pp |
| FG Trigger Rate | 0.2827% | 0.2955% | +0.0128pp |
| FG 平均得分 | 111.27x | 109.43x | -1.84x |

另外一次獨立 1,000 萬局結果為 107.3630%。這表示高波動 FG 會讓有限樣本結果上下變動；比對 RTP 時應固定卡片狀態、Bet Mode、config 版本與局數，並優先使用 5,000 萬局以上樣本。

先前使用舊輪帶的 1,000 萬局紀錄約為 50.1267%，不是目前 config 的結果，不能拿來與新版 106% 目標直接比較。

## 尚未定案／限制

- 106.8860% 是競品 7,075 局付費樣本的觀察值，不是已核准的正式 RTP target。
- 目前總 RTP 接近競品，但 FG RTP 偏高、BG RTP 偏低，兩者抵銷後才得到接近的 Total RTP。
- BG／FG Hit Rate 尚未貼近競品，表示盤面聚集程度仍可繼續調整。
- Extra Bet 專用輪帶／卡片、正式 RTP target、C3 出現池與機率仍是數學待定項目；目前只能確認程式間一致，不能確認最終數值正確。
- 卡片系統資料仍存在 config，但 index 未使用，所以一致性驗證一律以 card system off 為基準。
