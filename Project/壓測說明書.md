## 2. 壓測的定位

### 2.1 壓測與其他驗證工具的分工

| 工具 | 產出 | 驗證對象 |
|---|---|---|
| 數學模型 XLSX | 理論 RTP、倍率權重 | 模型本身的理論值 |
| Simulator（`slot_development_specification` 第 3 章） | 單一 Config／Bet Mode／Profile 的大場次報表 | 單一組合的 Game RTP、Feature 觸發率、Card System |
| **壓測（本文件）** | 固定玩家數 × 固定把數的雲端報表 | **玩家實際歷程下的混合 RTP**，含新老手切換與機制介入 |
| `System/simulator_system.py` | 多分頁玩家模擬報表 | 機制本身（新手 D／老手 C）的觸發率、Pool 上限、RTP 增量 |

壓測與 Simulator 的關鍵差異：Simulator 每批固定一個 Profile（Newbie 或 Oldhand），壓測則是
**同一位玩家從第 1 轉跑到第 N 轉**，中途會由新手期切換到老手期，並且會被新手體驗與老手救援介入。
因此壓測的 RTP 不能直接跟單一 Profile 的目標值比，必須先算加權期望值（第 4 節）。

### 2.2 壓測規模

壓測以「玩家數 × 每位玩家把數」定義，總 Spin 數 = 兩者相乘，對應報表的 `Total Spin` 欄位。

範例：20,000 位玩家 × 每人 500 把 = `Total Spin` 10,000,000。

### 2.3 把數與可驗證階段對照

遊玩時期依 `iGaming 機制說明書` 第 3.3.3 節定義。每位玩家把數決定壓測能驗到哪些階段：

| 每人把數 | 新手期 1～200 | 老手 A 201～300 | 老手 B 301～400 | 老手 C 401～500 | 老手 D 501+ | 新手／老手轉數比 |
|---:|:---:|:---:|:---:|:---:|:---:|---|
| 200 | ✓ | — | — | — | — | 200 : 0 |
| 300 | ✓ | ✓ | — | — | — | 200 : 100 |
| 400 | ✓ | ✓ | ✓ | — | — | 200 : 200 |
| **500** | ✓ | ✓ | ✓ | ✓ | — | **200 : 300** |
| 1000 | ✓ | ✓ | ✓ | ✓ | ✓ | 200 : 800 |

- 老手 D 含長期 RTP（前 500 轉）條件，只有把數 > 500 才驗得到。
- 把數愈大，老手期權重愈高，加權期望值愈接近純 Oldhand 目標。
- 選定把數後必須記錄下來；沒有把數就無法計算加權期望值，報表本身不含此資訊。

## 3. 壓測設定矩陣

### 3.1 Bet 分級與金額換算

報表的 `Coin in` 是內部押注單位，換算為實際押注金額需乘上該遊戲的換算率：

```text
實際押注 = Coin in × 換算率
```

換算率由各遊戲規格提供（101014 為 `0.002`）。分級門檻：

| 分級 | 實際押注 | Game RTP 版本 | 可拉 Link 彩金 | 上限倍數 |
|---|---|---|:---:|---|
| 小 Bet | `< $2` | 94 版 | ✗ | 依數學文件「倍率線型」 |
| 中 Bet | `>= $2` | 92 版 | ✓ | 依數學文件「倍率線型」 |
| 大 Bet | `> $100`（預設，各遊戲可不同） | 92 版 | ✓ | 2000x（預設，各遊戲可不同） |

- 分級看的是**實際總押注**，不是基礎押注。Extra Bet 加倍後跨級時，以加倍後的金額分級。
  例如基礎 $1（小 Bet）在 Extra Bet 2× 後為 $2，即歸為中 Bet，並取得 Link 資格。
- 大 Bet 門檻與上限倍數為產品限制，必須逐款遊戲確認，不得沿用預設值。

### 3.2 必跑組合

| 維度 | 必跑內容 |
|---|---|
| Bet 分級 | 小 / 中 / 大 各至少一組 |
| Bet Mode | 每個分級的 Normal Bet 與 Extra Bet 各一組 |
| Buy／Super Feature | 若遊戲支援，另外驗 92.50% 目標 |
| 機制 | 機制開一組；需要量化機制增量時，另跑同參數的機制關一組 |
| 重複次數 | 每組至少 2 次（見第 7 節樣本量） |

未跑的組合必須在報告中列出並註明原因，不得以「沒問題」帶過。

## 4. 設定基準值與加權期望值

### 4.1 Game RTP 目標

取自 `slot_development_specification` 第 1.4 節；各遊戲若不同以遊戲規格為準。

| Config 家族 | Newbie | Oldhand | Buy／Super Feature |
|---|---:|---:|---:|
| `92x`（中 Bet、大 Bet） | 93.00% | 92.00% | 92.50% |
| `94x`（小 Bet） | 93.00% | 94.00% | 92.50% |

### 4.2 加權期望值

壓測混合新老手，期望值按實際轉數比加權：

```text
加權目標 = (新手轉數 / 總轉數) × Newbie 目標
         + (老手轉數 / 總轉數) × Oldhand 目標
         + 機制增量
```

每人 500 把（200 新手 + 300 老手，即 0.4 / 0.6）的結果：

| 分級 | Config 家族 | 加權基準 | 機制增量 | 機制開期望值 | 機制關期望值 |
|---|---|---:|---:|---:|---:|
| 小 Bet | `94x` | `0.4×93 + 0.6×94` = **93.60%** | +2.0pp | **95.60%** | **93.60%** |
| 中 Bet | `92x` | `0.4×93 + 0.6×92` = **92.40%** | +2.0pp | **94.40%** | **92.40%** |
| 大 Bet | `92x` | `0.4×93 + 0.6×92` = **92.40%** | +2.0pp | **94.40%** | **92.40%** |

把數改變時只需重算權重，例如每人 400 把為 `0.5 / 0.5`，中 Bet 加權基準變為 `0.5×93 + 0.5×92 = 92.50%`。

### 4.3 機制增量

| 機制 | 目標 | 容許範圍 |
|---|---:|---|
| 新手體驗 | 1% | 0%～2% |
| 老手救援 | 1% | 0%～2% |
| 合計 | 2% | 0%～4% |

兩個機制都以贈送 Free Game 的形式發出，派彩落在 `RTP FG` 內，因此**已包含在 `RTP Game` 欄位**，
不是額外一欄。這是加權公式必須加上機制增量的原因。

### 4.4 比對欄位

**`RTP Game` 是唯一的主判欄位。** 不使用 `RTP Total`：

- `RTP Total` = `RTP Game` + `RTP JP Bonus` + `RTP JP Link`
- `RTP JP Link` 是跨遊戲彩金，10M spin 內是低頻高額的 0/1 事件，單筆標準差可達 0.8pp，
  單組差異可達 ±1.7pp，會完全蓋掉要驗的訊號。
- `RTP JP Bonus` 與 `RTP JP Link` 另以理論值分別檢查（第 6.5 節）。

## 5. 壓測報表欄位對照

### 5.1 現行格式（2026-07-27 22:41 起，21 欄）

| 欄位 | 說明 | 判定用途 |
|---|---|---|
| `source_txt` | 來源檔名 | 追溯；同一設定的多次執行以此區分 |
| `資料夾名稱` | 設定組合編碼 | 判斷 Profile／機制設定（見 5.3） |
| `Game ID` | 遊戲代號 | 確認報表對應正確遊戲 |
| `Option ID` | 選項代號 | 同一遊戲的不同選項 |
| `Coin in` | 內部押注單位 | × 換算率後判 Bet 分級 |
| `Total Spin` | 總 Spin 數 | = 玩家數 × 每人把數；檢查樣本量 |
| `JP 週期` | 彩金平均間隔 | 彩金觸發頻率檢查 |
| `RTP Total` | 全含 RTP | 參考，不作主判 |
| `RTP JP Link` | Link 彩金 RTP | 小 Bet 須為 0；其餘比理論值 |
| `RTP JP Bonus` | Bonus 彩金 RTP | 比理論值 |
| **`RTP Game`** | 基礎遊戲 RTP（BG + SC + FG） | **主判欄位** |
| `RTP BG` | Base Game RTP | BG／FG 結構檢查 |
| `RTP SC` | Scatter Pay RTP | 若遊戲無 SC Pay 應為 0 |
| `RTP FG` | Free Game RTP | BG／FG 結構檢查；機制派彩落在此 |
| `最大倍數 BG` | BG 實際開出最大倍數 | 對照 BG Trigger Cap |
| `最大倍數 FG` | FG 實際開出最大倍數 | 對照上限倍數 |
| `最大倍數 B2F` | BG 進 FG 的實際最大倍數 | 對照 BG Trigger Cap |
| `pool[1] rtp` ～ `pool[4] rtp` | 彩金各獎級 RTP，`pool[1]` 最大、`pool[4]` 最小 | 獎級分布檢查；空白代表該次無人中獎 |

三個「最大倍數」欄位都是**實際開出值**，不是設定上限。

### 5.2 歷代格式差異

| 期間 | 欄位命名 | 資料夾名稱格式 |
|---|---|---|
| ～2026-07-27 22:29 | `TotalRtp (including JP/bonus)`、`BaseGameRtp`、`ScatterRtp`、`FreeGameRtp`、`BonusJP Rtp`、`LinkJP Rtp`、`avgPeriod` | `JHS{GameID}_{NoExtraBet｜ExtraBet_PowerUp｜ExtraBet_BuyFreeGame}_Null_{CoinIn}_WTIdx_{0-3}` |
| 2026-07-27 22:41 起 | 現行 21 欄（`RTP Total`／`RTP Game`／`最大倍數 BG·FG·B2F`／`JP 週期`） | 同上 |
| 2026-08-17 起 | 現行 21 欄 | `JHS{GameID}_type{n}_mod{a}-{b}_taste{c}-def{d}_{CoinIn}`，`WTIdx` 取消 |

比對不同期間的報表時，先確認欄位名稱對應：舊格式的 `BaseGameRtp + ScatterRtp + FreeGameRtp`
才等於現行的 `RTP Game`。

### 5.3 資料夾名稱編碼

新格式 `JHS{GameID}_type{n}_mod{a}-{b}_taste{c}-def{d}_{CoinIn}` 各段含意**待確認**（第 11 節）。
目前可從資料觀察到的事實：

- 同一份報表可同時含多個設定組，例如 `mod0-2_taste0-def2` 與 `mod1-2_taste1-def3`。
- 不同設定組的 `最大倍數 BG` 與 `最大倍數 B2F` 上限不同（觀察到 100 與 70 兩種），
  對應 `slot_development_specification` 第 2.3 節的 BG Trigger Cap，屬於 Profile／卡片設定差異。
- **資料夾名稱看不出機制開關。** 判斷機制是否開啟目前只能靠檔名或執行紀錄，
  或以第 6.6 節的反推法驗證。

## 6. 判定流程

### 6.1 Step 1：前置檢查

- [ ] `Game ID` 與 `Option ID` 對應到要驗的遊戲與選項。
- [ ] 已取得「每位玩家把數」與「玩家數」，且 `玩家數 × 把數 = Total Spin`。
- [ ] 已取得該遊戲的 `Coin in` 換算率、大 Bet 門檻、上限倍數。
- [ ] 已確認本份報表的機制開關狀態。
- [ ] 每個設定組至少有 2 次執行結果。

前置資料缺任何一項就不得出判定結論，只能出「資料不足」。

### 6.2 Step 2：分類每一列

對每一列計算 `實際押注 = Coin in × 換算率`，據此標上 Bet 分級與 Config 家族
（小 Bet → `94x`，中／大 Bet → `92x`）。
同 `資料夾名稱` + 同 `Coin in` 的多列視為同一組的重複執行，取平均後再判定。

### 6.3 Step 3：算加權期望值

依第 4.2 節公式，用實際把數算出每個分級的期望值。

### 6.4 Step 4：`RTP Game` 主判

```text
差異 = 實測 RTP Game − 加權期望值
```

| 差異絕對值 | 判定 |
|---|---|
| `<= 0.5pp` | 通過 |
| `0.5pp ~ 1.0pp` | 警示，需說明或增加執行次數 |
| `> 1.0pp` | 異常，須追查 |

- 判定以「同組多次平均」為準，不用單筆。
- 全體各組**同方向**偏移屬系統性問題（設定或口徑錯誤），即使幅度小也要追查；
  正負交錯且幅度在容差內則屬正常抽樣波動。

### 6.5 Step 5：硬檢查

不涉及容差、不符合就是錯：

| 檢查項 | 條件 |
|---|---|
| 小 Bet 不可拉 Link | 小 Bet 所有列的 `RTP JP Link` 必須為 0，且 `pool[1]`、`pool[2]` 必須空白 |
| 大 Bet 上限倍數 | 大 Bet 的 `最大倍數 FG`、`最大倍數 BG`、`最大倍數 B2F` 均不得超過該遊戲大 Bet 上限 |
| 中／小 Bet 上限倍數 | 不得超過該遊戲數學文件「倍率線型」定義的上限 |
| BG Trigger Cap | `最大倍數 B2F` 與 `最大倍數 BG` 不得超過同 Profile 的 BG Trigger Cap |
| Scatter Pay | 遊戲無 Scatter Pay 時 `RTP SC` 必須為 0 |
| RTP 拆解 | `RTP Game + RTP JP Bonus + RTP JP Link` 須等於 `RTP Total`（浮點誤差內） |
| 彩金 RTP | `RTP JP Bonus`、`RTP JP Link` 與各 `pool[n] rtp` 對照理論值 |
| BG／FG 結構 | 同一 Bet Mode 的 `RTP BG`／`RTP FG` 佔比應一致；Normal 與 Extra Bet 之間可以不同 |

### 6.6 Step 6：有無機制配對比較

需要量化機制增量時，跑同參數的機制開／機制關兩份報表，逐組配對相減。

配對比較的規則：

1. **只比 `RTP Game`，或比 `RTP Game + RTP JP Bonus`。** 不要比 `RTP Total`。
2. `RTP JP Link` 必須單獨列出，不併入判定。它在 10M spin 內是 0/1 事件，
   單組可造成 ±1.7pp 的帳面差異，與機制無關。
3. 機制增量的期望值是 +2.0pp（容許 0～4pp）。
4. 若兩份報表的 `RTP Game` 差異在 ±0.5pp 內，代表兩份的機制狀態相同 —
   這可以反過來當作「機制開關辨識」的檢驗手段。

## 7. 容差與樣本量

### 7.1 各欄位的波動幅度

以 10M spin、每組 2 次為基準的實測波動：

| 欄位 | 單筆標準差 | 說明 |
|---|---:|---|
| `RTP Game` | 約 0.47pp | 主判欄位；2 次平均後標準誤約 0.33pp |
| `RTP JP Bonus` | 約 0.16pp | 最穩定；各組差異通常在 ±0.04pp 內 |
| `RTP JP Link` | 約 0.78pp | 波動比平均值本身還大，單組差異可達 ±1.7pp |
| `RTP Total` | 約 0.63pp | 波動幾乎全部來自 `RTP JP Link` |

### 7.2 樣本量要求

- 每組至少 2 次執行，取平均。
- `RTP Game` 出現 0.5～1.0pp 警示時，補到 4 次以上再判。
- **`RTP JP Link` 不適用 2 次樣本判定。** 它是低頻高額事件，2 次抽樣的雜訊比訊號大一個量級；
  要判 Link 貢獻是否符合設定，須累積 10 次以上，或改用理論觸發率 × 獎項倍率驗算。

### 7.3 常見誤判

拿 `RTP Total` 直接比目標，會把 Link 的抽樣運氣誤判成設定錯誤。典型情境：
某組機制關的兩次執行都沒中 Link（`RTP JP Link = 0`），機制開的中了，
帳面上 `RTP Total` 差 1.5pp，但 `RTP Game` 只差 0.08pp — 實際上兩者設定相同。

## 8. 常見異常與處置

| 現象 | 可能原因 | 處置 |
|---|---|---|
| 全部分級的 `RTP Game` 同方向偏移約 +2pp | 機制派彩計入而期望值忘記加機制增量 | 依第 4.3 節補上機制增量後重判 |
| 全部分級同方向偏移，幅度非 2pp | Config 家族判斷錯、把數／權重算錯、換算率錯 | 回頭確認 Step 1～3 的輸入 |
| 單組偏移大、其他組正常 | 抽樣波動或該組設定單獨出錯 | 補跑該組至 4 次以上再判 |
| `RTP Total` 差異大但 `RTP Game` 一致 | Link 抽樣運氣 | 非異常，改看 `RTP Game`，並在報告註明 |
| 小 Bet 出現 `RTP JP Link > 0` | Bet 分級或 Link 資格設定錯 | 硬性錯誤，直接退回 |
| Extra Bet 跨級後的分級與預期不同 | 分級用了基礎押注而非實際總押注 | 依第 3.1 節以實際總押注分級 |
| `最大倍數 BG` 固定等於某整數且等於 `最大倍數 B2F` | BG Trigger Cap 每次都被頂到 | 屬正常；確認該值等於設定的 cap |
| 缺某個 Bet 分級 | 該面額未納入本批壓測 | 列入待跑，不得視為通過 |

## 9. 檢查清單

### 9.1 前置

- [ ] 已記錄玩家數、每位玩家把數，且與 `Total Spin` 一致。
- [ ] 已取得 `Coin in` 換算率、大 Bet 門檻、上限倍數。
- [ ] 已確認機制開關狀態。
- [ ] 小／中／大 Bet 各至少一組；每級的 Normal 與 Extra Bet 都有。
- [ ] 每組至少 2 次執行。

### 9.2 判定

- [ ] 每列已算出實際押注並標上 Bet 分級與 Config 家族。
- [ ] 已依實際把數算出加權期望值（含機制增量）。
- [ ] 各組 `RTP Game` 與期望值的差異已列表，且無 > 1.0pp 者。
- [ ] 偏移方向已檢查，未出現無法解釋的系統性同向偏移。
- [ ] `RTP JP Link` 已單獨列出，未併入主判。

### 9.3 硬檢查

- [ ] 小 Bet 的 `RTP JP Link` 全為 0，`pool[1]`／`pool[2]` 全為空白。
- [ ] 各分級的最大倍數均未超過對應上限。
- [ ] `最大倍數 B2F` 未超過 BG Trigger Cap。
- [ ] `RTP Game + RTP JP Bonus + RTP JP Link = RTP Total`。
- [ ] `RTP SC` 與遊戲是否有 Scatter Pay 一致。
