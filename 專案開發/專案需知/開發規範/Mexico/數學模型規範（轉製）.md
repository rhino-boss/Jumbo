# Mexico 數學模型規範（Landbase 轉製）

本頁說明墨西哥市場 Landbase 轉製遊戲的數學模型，目前適用 H0071、H0081、H0091、H0101，以及 2026-11-17 加入的 H5011、H5021（金來發）。玩家狀態、新手體驗、老手救援與系統限制見[系統機制](系統機制.md)。從菲律賓版轉成墨西哥版的步驟、規則與驗收，見[轉版指引](轉版指引.md)。

## 1. 數學模型

### 1.1 必要內容

- 數學調性目前**沒有明確方向，由負責人自由發揮**（待討論）。
- 原機既有的 Bonus／Feature 玩法屬於 Game RTP 的一部分，不另拆 Bonus Game RTP（見第 1.4 節）。

### 1.2 模型命名

- Landbase 轉製遊戲的 ParSheet ID 為 `H<三位數字>1`；同一數學供多個 Game ID 使用時（如 `H0111` → 102001／102002），數學模型只建一份，Game ID 對應記錄於 Game List。

### 1.3 押注選項

押注金額由三個參數相乘：

```text
押注金額 = 最小押分（credits）× Denom × Bet Multiplier
最小押分 = 100 credits；Denom = 0.002 → 1 倍押注 = 0.2
```

### 1.4 RTP 配置

```text
Total RTP = 新手體驗或老手救援 RTP + Link RTP + （Bonus + Game）RTP
```

- 轉製遊戲**不拆 Bonus Game RTP**：原機的 Bonus／Feature 派彩與固定倍數獎（Mini／Minor 等）全部歸入「Bonus＋Game」。
- RTP ＝ Total Win ÷ 實際 Total Bet；產品顯示可四捨五入，但計算用完整精度；各 Bet Mode 分母用該模式實際成本。
- 新手體驗與老手救援由系統層給出，數學模型只負責 Bonus＋Game RTP。

#### 1.4.1 NB／EB RTP 配置

| Player Profile | 系統機制 RTP | Link RTP | Bonus＋Game RTP | 合計 |
|---|---:|---:|---:|---:|
| 新手 | 新手體驗 2.00% | 該彩金配置的 Increment 合計 | 95.15% | 97.15%＋Increment |
| 老手無彩金 | 老手救援 1.00% | 0.00% | 96.50% | 97.50% |
| 老手有彩金 | 老手救援 1.00% | 2.00% | 94.50% | 97.50% |

- 新手拉不到 Grand／Major，但押注會滾入 Increment，所以新手的 Link RTP **隨彩金配置變動**，等於該配置 Grand 與 Major 的 Increment 合計（第 1.5.2 節）：Grand 10 萬組與 Grand 50 萬組都是 0.85%。Bonus＋Game RTP 不隨彩金配置調整。表中新手的合計以新手體驗 2% 計；H0071／H0081 沒有新手體驗，少 2 個百分點；H0091／H0101 沿用菲律賓版新手體驗，驗收值約 2.9%。
- 老手有彩金＝押注 `>= 0.4` 且該遊戲開啟 Link；老手無彩金＝押注 `< 0.4`，或該遊戲／賭場未開 Link。
- 上表的 Bonus＋Game 是轉製遊戲的指定值，合計比主流規範高（同一彩金配置下新手高 0.15 個百分點、老手高 0.50 個百分點），這是刻意的設定，不套用主流規範「Bonus 併入 Game」的 95%／96%／94%。
- 新手體驗 2% 只適用有新手體驗的遊戲（系統機制第 2 節）：H0091／H0101 沿用菲律賓版新手體驗設定；H0071／H0081 的舊機制已移除，沒有這 2%。

#### 1.4.2 Buy Feature RTP 配置

| 類別 | Link RTP | Bonus＋Game RTP | 合計 |
|---|---:|---:|---:|
| 新手 | 該彩金配置的 Increment 合計 | 95.65% | 95.65%＋Increment |
| 老手無彩金 | 0.00% | 96.50% | 96.50% |
| 老手有彩金 | 2.00% | 94.50% | 96.50% |

- Buy Feature 沒有新手體驗與老手救援。
- 新手購買 Feature 不得拉 Link（系統機制第 4 節），但押注不分高低都會滾入 Increment。新手版的 Bonus＋Game 維持 95.65%（比老手無彩金低 0.85 個百分點），兩組彩金配置的 Increment 合計都是 0.85%，所以合計都是 96.50%。

### 1.5 彩金配置

Link 彩金為 Grand、Major 兩層累積彩池。

#### 1.5.1 Link 資格

「可滾 Inrc」表示該局押注會依 Increment 比例滾入彩池；「可拉 Link」表示該局有資格中 Grand／Major。兩者是不同的資格：

| 狀態 | 押注 | 可拉 Link | 可滾 Inrc |
|---|---|---|---|
| 新手 | `< 0.4` | 否 | 是 |
| 新手 | `>= 0.4` | 否 | 是 |
| 老手 | `< 0.4` | 否 | 否 |
| 老手 | `>= 0.4` | 是 | 是 |

- 新手押注不分高低都滾 Increment（使用者 2026-11-19 確認；本專案自訂，菲律賓版轉製規範第 1.5.1 節的表寫的是新手 `>= $2` 才滾）。
- NB／EB 與 Buy Feature 都適用上表；押注金額依第 1.6 節判定。系統限制另見[系統機制](系統機制.md)。
- 數學模型必須定義哪些派彩歸入 Link、哪些歸入 Bonus＋Game，不得重複計算。
- 彩金參數的位置：H0071／H0081 在各數學檔的 `Jackpot Setting` 與 `05_MYF\MYF 彩金參數簡表 (H5).xlsx`；H0091／H0101 在 `04_LLF\LLF_Calculator (H5).xlsx` 與 `LLF_Calculator (H5_BF).xlsx`。LLF 檔內的池名是 Fortune／Grand，分別對應本規範的 Grand／Major。

#### 1.5.2 Link 彩金配置

| 組別 | 級距 | 初始金額 | Startup% | Increment | RTP | 平均開出金額 |
|---|---|---:|---:|---:|---:|---:|
| Grand 10 萬 | Grand | $100,000 | 0.65% | 0.35% | 1.00% | $153,846 |
| Grand 10 萬 | Major | $20,000 | 0.50% | 0.50% | 1.00% | $40,000 |
| Grand 50 萬 | Grand | $500,000 | 0.65% | 0.35% | 1.00% | $769,231 |
| Grand 50 萬 | Major | $100,000 | 0.50% | 0.50% | 1.00% | $200,000 |

- **2026-11-25 使用者：墨西哥彩金一律用 Grand 10 萬組（Grand $100,000／Major $20,000）**；Grand 50 萬組不用，下表與下方說明中的 50 萬組僅留作轉換過程的紀錄。
- **有 Link 的遊戲才依本表配置**。兩組在檔內的編號：H0071／H0081 為 Opt04～06（10 萬）、Opt01～03（50 萬）；LLF 為 ID02（10 萬）、ID01（50 萬）。原本的 100 萬組（H0071／H0081 的 Opt07～09、LLF 的 ID03）不用於墨西哥。
- 2026-11-16 使用者指示：Grand 100 萬組移除；Grand 10 萬組改回菲律賓版的設定（Major 初始金額 $20,000、Startup 0.50%／Increment 0.50%）。本節是目標規格；各遊戲檔案的修改狀態見第 2 節與轉換紀錄。

| 欄位 | 定義 |
|---|---|
| 初始金額 | 彩池開出後重置的起始金額（Start Up Pool） |
| Startup% | 押注中用來補足初始金額的比例；`Startup% = RTP − Increment` |
| Increment | 押注中滾入彩池、讓彩池累積上漲的比例（試算表的 Inrc） |
| RTP | 該級距的彩金 RTP；`RTP = Startup% + Increment` |
| 平均開出金額 | `初始金額 ÷ Startup% × RTP` |

- 彩金配置共兩組。Grand 的 Startup%／Increment 兩組都是 0.65%／0.35%；Major 兩組都是 0.50%／0.50%。
- Grand ＋ Major RTP ＝ Link RTP 2.00%。Increment 合計兩組都是 0.85%。
- Major 的初始金額兩組都是 Grand 的五分之一。
- 新手的押注不分高低都會滾入 Increment，但新手不能中彩。

### 1.6 Bet Mode

- Bet Mode 分一般押注（NB）、Extra Bet（EB）、Buy Feature（BF）。
- 老手的押注層級只分 **`< 0.4`／`>= 0.4` 兩級**（低注／高注）；新手不分層級。
- NB／EB 以該模式的實際押注金額判定；Buy Feature 以 **Feature 購買價格 ÷ Feature Price 倍數反推的基礎押注**判定，不用購買總價。
- Buy Feature 單次購買的實付金額上限 `$30,000`；超過的押注不開放、玩家端不顯示（[系統機制](系統機制.md)第 4 節）。超過上限的押注在數學文件裡已有的參數保留，沒有的不必補做。
- 新手單把上限 100×，只適用 NB 與 EB；其他倍率上限依[系統機制](系統機制.md)的系統最大賠付（`$3,000,000`）反推。

### 1.7 後端權重表的數值格式

- 本節只管**後端會使用的權重表**：後端或遊戲程式抽獎時讀進去的權重，例如輪帶或圖標的權重、彩金權重、輪盤權重（使用者 2026-11-16 指示）。
- 權重表內**不得出現負數或小數**，每一個權重都必須是**精確的整數**。由公式算出的值要在公式內用 `ROUND(…, 0)` 取整，不得留下浮點誤差（例如 `7499999.999999998`）。判定方式是儲存格實際存的值與它四捨五入後的值完全相等，不是畫面上看起來是整數。
- 權重不得用機率（0～1 的小數）的形式填寫，要寫成整數權重。
- 下列不是後端權重，不適用本節：押注與 Denom、以百分比表示的 RTP 與彩金參數、賠率與倍數、輪帶上的圖標編號與標記、用來推算權重的設計輸入（目標機率、放大倍率）、統計與驗算用的輸出格。設計輸入可以是小數，但由它算出來給後端讀的權重仍須在公式內取整。
