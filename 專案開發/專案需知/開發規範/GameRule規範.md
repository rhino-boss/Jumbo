# GameRule規範

存放位置：遊戲專案根目錄 `game_rule.md`。

Game Rule 是遊戲規則說明文件。

## 1. 用途

Game Rule 用於設定遊戲玩法規則，是數學模型、Config、Simulator、Demogame、Help 與測試案例共同遵循的規則來源。

## 2. 必要規則

- 每款遊戲必須提供 `game_rule.md`，並明確定義遊戲基礎設定、得分方式、Symbol 功能、判獎順序、Bet Mode、BG／FG 流程、Feature、Retrigger、Multiplier、Max Win、Jackpot 與例外處理。
- Game Rule 必須沿用本節定義的固定章節骨架、標題層級、表格形式及規則表達方式。
- 數學模型、Config、Simulator、Demogame 與 Help 不得自行補充或改寫 `game_rule.md` 未定義的玩法。
- 規則變更時，必須同步檢查並更新數學文件、Config、Simulator、Demogame、`{GameID}_Help.xlsx`、`game_help.md` 與測試案例。
- Game Rule 與其他來源內容衝突時，必須先確認正式規則，不得由開發端自行選擇其中一種實作。

Game Rule 必須保留下列基本結構：

| 順序 | 章節 | 格式要求 |
|---:|---|---|
| 1 | `§1. 遊戲基本資訊` | 使用「項目／說明」表格記錄本節規定的基礎資料。 |
| 2 | `§2. 盤面結構` | 包含盤面示意圖與 Reel／Row、得分方向及補牌流程的文字說明。 |
| 3 | `§3. 符號類別` | 分開定義一般符號與特殊符號，說明出現位置、替代關係及功能。 |
| 4 | `§4. 賠率表（Pay Table）` | 使用表格列出符號、得分數量及倍率口徑。 |
| 5 | `§5. 核心特色` | 依遊戲機制建立子章節，完整說明特色符號、轉換、Multiplier 或其他核心玩法。 |
| 6 | `§6. 免費遊戲（Free Spins / Free Game, FG）` | 分別定義觸發、FG 玩法及 Retrigger。 |
| 7 | `§7. 核心遊戲流程（Base Game）` | 依實際執行順序編號描述 Spin、判獎、消除／補牌、結算與 Feature Trigger。 |
| 8 | `§8. 押注模式` | 依遊戲實際支援內容分別說明 Extra Bet 與 Buy Feature。 |
| 9 | `§9. 邊界 / 例外情境（Edge Cases）` | 依機制分類列出可直接驗證的邊界條件及例外處理。 |

`§1. 遊戲基本資訊` 必須包含下列欄位：

- `Game ID`
- `PARsheet ID`
- `遊戲中文名稱`
- `遊戲英文名`
- `遊戲類型`：依實際遊戲機制列出完整類型，例如 `2,025–32,400 Ways / Megaways / Cascade`。
- `盤面規格`
- `中獎方式`：使用 `Line Game`、`Way Game`、`Pay Anywhere` 或 `Cluster Pay`；只能選擇符合實際判獎邏輯的類型。
- `押注模式`

`§8. 押注模式` 依遊戲實際支援內容包含：

- `Extra Bet`：遊戲有 Extra Bet 時，說明價格、流程與 Normal Bet 的差異；沒有時可省略此子章節。
- `Buy Feature（購買特色）`：遊戲有 Buy Feature 時，說明購買價格、入口 Spin、FG 觸發方式與得分計算；沒有時可省略此子章節。

- §1～§9 的章節名稱與順序不得任意更動；遊戲沒有 FG 時，仍須保留 §6 並明確寫「不適用」或「不提供」。
- 可依各遊戲機制在固定章節下新增子章節，但不得改變核心章節順序。
- 規則必須以開發與測試可直接實作、驗證的方式描述，不得只使用宣傳文案或未定義的概念性敘述。

遊戲類型的統一命名規則見[Demogame規範.md](Demogame規範.md)第 1.1 節；Game Rule、Demogame 與 Help 必須使用相同術語。摘要如下（兩處不一致時以 Demogame規範 第 1.1 節為準）：

- 格式：`Video Slot - <主要派彩類型> / <附加機制> / …`，例：`Video Slot - 1,024 Ways / Cascade / Cascade Multiplier`。
- 主要派彩類型只能選一種，且必須與 §1 的 `中獎方式` 對應：

| §1 `中獎方式` | 遊戲類型的主要派彩類型 | 判定規則 |
|---|---|---|
| `Line Game` | `N Lines`（`N` 換成實際線數，例 `20 Lines`） | 依固定 Payline 判獎。 |
| `Way Game` | `N Ways`（`N` 換成固定 Ways 或「最小–最大 Ways」，例 `1,024 Ways`、`2,025–32,400 Ways`） | 相同符號由最左輪起，在連續相鄰輪出現即得獎。 |
| `Pay Anywhere` | `Pay Anywhere` | 相同符號在整個盤面的總數達門檻即得獎，不要求相鄰、連線或由最左輪開始。 |
| `Cluster Pay` | `Cluster Pay` | 相同符號依規定方向相鄰連接，且連接數量達門檻才得獎。 |

- `Cascade`、`Megaways`、`Cascade Multiplier`、Multiplier 類與 Feature 類（例 `Multiplier Wild`、`OP Jackpot`）屬附加機制，接在主要派彩類型之後，不得代替主要派彩類型。
- 連消流程使用的得分倍數統一稱為 `Cascade Multiplier`。

## 3. 文件格式與各章內容

本章把 §1～§9 每一章「要寫什麼、用什麼格式」寫成可直接照做的規格；不需參考任何既有遊戲的 `game_rule.md` 即可產出。

### 3.1 文件標頭與通用寫法

- 檔名固定為 `game_rule.md`（UTF-8、繁體中文），放在遊戲專案根目錄：`Slots/H0xx_<遊戲中文名>/game_rule.md`。
- 第一行標題固定為：`# <遊戲中文名稱> (<遊戲英文名>) 遊戲規則說明`。
- 標題下可放 `## 目錄`，以連結列出 §1～§9 與各附錄。
- 固定章節使用二級標題，保留 `§` 與編號，文字與第 2 節表格完全相同，例：`## §6. 免費遊戲（Free Spins / Free Game, FG）`。
- 子章節使用三級標題、不帶 `§`，例：`### 6.1 觸發`、`### 5.3 帶倍數 WILD`。
- 固定章節之間以 `---` 分隔。
- 符號一律以代號加反引號書寫（例 `M1`、`C1`、`WW`），首次出現可附中文名（例 `WW` / 小鬼）；代號規則見第 3.2 節。
- 章節互相引用寫成 `（§5.3）`、`（§9.10）`。
- 規則用到的數學參數（權重表、輪帶表、工作表名）以反引號寫出，名稱必須與 Source XLSX 的工作表／參數名及 Config 鍵名一致（例 `Table Selection Weight`、`Multiplier_Wild_Weight_WW`），讓實作端能直接對到資料。
- 規則經使用者定案或改版時，在該條句尾註明日期與前值，例：`（2026-10-13 使用者定案）`、`（2026-11-12 起，原為 1X）`。
- 尚未確定的值標 `⏳`，並列入文末「待確認事項」（第 3.12 節）。
- **不寫模擬實測數據**：正文與附錄都不放模擬／實測結果（RTP、Hit Rate、FG 週期、出現率、平均倍數等）；Game Rule 只寫規則與設計參數，實測數據放數值報告或修改紀錄（2026-11-20 使用者）。

### 3.2 符號代號

| 代號 | 用途 |
|---|---|
| `M1`、`M2`、`M3`、`M4`（更多時依序 `M5`…） | 高分符號；依同連線數的賠率由高到低編號。 |
| `A`、`K`、`Q`、`J`（更多時依序 `TE`、`NI`） | 低分符號；依賠率由高到低排列。 |
| `WW` | 一般 Wild。 |
| `W2`、`W3` | 第二、第三種 Wild（例：分裂 Wild、黏著 Wild、帶倍數的特殊 Wild）。 |
| `C1` | Scatter（觸發 FG、彩金等）。Game Rule 一律寫 `C1`，**不用 `SC`**（程式統計欄位如 `special_symbol_cnt` 說的 `SC` 即指 `C1`）（2026-11-20 使用者）。 |
| `C2`、`C3`… | Wild 與 Scatter 以外的特殊符號（例：倍數符號、收集符號）。 |

- 同賠率的符號依畫面順序排列。
- 符號的「附加狀態」（金框、黏著、倍數標記等）不是獨立符號時，必須明寫「不是符號，是套在一般符號上的旗標」，並說明它是否出現在物理輪帶、是否影響判獎與賠率。
- 每個代號都要在附錄 A 對到 Config `symbol_names` 的 Symbol ID（數字）。

### 3.3 §1. 遊戲基本資訊

使用兩欄表格 `| 項目 | 說明 |`，列順序如下：

| 項目 | 必要 | 填寫方式 | 範例 |
|---|---|---|---|
| 遊戲名稱（內部代號） | 建議 | `<中文名>（H0xx）` | `範例遊戲（H0xx）` |
| `Game ID` | 必要 | 上線用 Game ID，依公司遊戲代號清單填，不得自編；查不到時留空並列入待確認事項 | `10xxxx` |
| `PARsheet ID` | 必要 | 基礎數學模型代號 `H0xx1`（A／B 兩套基礎數學時 `H0xx1A`、`H0xx1B`）；可附 Source 檔與已建立的 RTP／Variant | `H0xx1（Source/H0xx1.xlsx）` |
| `遊戲中文名稱` | 必要 | 內部中文名 | `範例遊戲` |
| `遊戲英文名` | 必要 | 正式英文名 | `Sample Game` |
| `遊戲類型` | 必要 | 第 2 節格式 | `Video Slot - 1,024 Ways / Cascade / Cascade Multiplier` |
| `盤面規格` | 必要 | 輪數 × 列數；各輪列數不同時逐輪寫出 | `5 輪 × 4 列固定盤面`、`6 輪 × 3-4-5-5-4-3 列` |
| `中獎方式` | 必要 | 只能填 `Line Game`／`Way Game`／`Pay Anywhere`／`Cluster Pay` 其一 | `Way Game` |
| 最小 / 最大 Ways | Way Game 必要 | Ways 數與計算式；Line Game 改寫線數或「不適用」 | `最大 1,024 Ways（4 × 4 × 4 × 4 × 4）` |
| `押注模式` | 必要 | 列出全部模式與價格，沒有的模式寫「無」 | `Normal Bet；Extra Bet 2 × Bet；Buy Feature N × Bet` |
| Max Win | 建議 | 固定倍數，或「由卡片系統倍率上限決定（見 §9.x）」 | `由卡片系統的倍率上限決定，見 §9.10` |
| 彩金 | 有彩金時必要 | 彩金種類與章節位置；沒有寫「無」 | `OP Jackpot 四階，見 §5.x` |
| 致敬遊戲／對標競品 | 有時填 | 廠商 - 遊戲名 | `<廠商> - <遊戲名>` |

表格下方加 `補充說明：` 條列：衍生自哪款前作及沿用／新增的項目、數學模型來源（`Source/H0xx1*.xlsx`）、Coin／Credit 基準（例：`Coin / Credit 基準為 100；Help 顯示賠率以 100 Credit Bet 為基準`）。

### 3.4 §2. 盤面結構

1. 盤面示意圖：以 `text` 程式碼區塊畫 ASCII 格狀圖，輪數與各輪列數照實際；各輪不等高時要畫出形狀。範本（5 輪 × 4 列）：

```text
   R1   R2   R3   R4   R5
   ↓    ↓    ↓    ↓    ↓
┌────┬────┬────┬────┬────┐
│    │    │    │    │    │
├────┼────┼────┼────┼────┤
│    │    │    │    │    │
├────┼────┼────┼────┼────┤
│    │    │    │    │    │
├────┼────┼────┼────┼────┤
│    │    │    │    │    │
└────┴────┴────┴────┴────┘
```

2. 示意圖下方條列，必須逐項交代：
   - 輪數、每輪可見列數、總格數；有無 Extra Reel（有則寫位置、格數與作用）。
   - 得分方向與最少成立條件（例：由 R1 起向右連續至少 3 輪）。
   - Ways／線數的計算方式（例：同輪多顆相同符號相乘；固定線則附線型或寫明線數）。
   - 同一符號同時成立不同長度時只付最長（或依本作實際規則）。
   - 補牌方式，只能擇一並寫清楚：**原地補牌**（被消除的格子原位補新符號，其餘不動）或**重力掉落**（剩餘符號往下掉，空位由上方補入）；補牌依哪一張權重表抽取；補牌是否限制某些符號（例：該輪已有 `C1` 不再補 `C1`）。

### 3.5 §3. 符號類別

- `### 3.1 一般符號`：表格 `| 類別 | 符號 |`，至少兩列「高分符號」「低分符號」；表下條列寫符號尺寸（全部 1×1 或有大符號）、附加狀態（第 3.2 節）。
- `### 3.2 特殊符號`：表格 `| 符號 | 出現位置 | 行為 |`，每個特殊符號一列：
  - 出現位置：哪些輪可出現、是否自然出現在輪帶、同輪可否多顆、或只由其他機制產生。
  - 行為：替代範圍（替代哪些、不替代哪些）、有無自身賠率、是否參與連線、是否會被消除、觸發什麼（引用章節）。
- 表下條列補充跨符號限制（例：`R1 永不出現 Wild`、`C1 不被 Wild 替代`）。

### 3.6 §4. 賠率表（Pay Table）

- 表上方標明單位，例：`**單位：Credit；以 100 Credit Bet 顯示。**`。Config 的 `pays` 以「× 總押注」記錄，等於表值 ÷ 100（例：表值 `25` → `0.25`）。
- Line／Way Game 表格欄位：`| 符號 | 3 連 | 4 連 | 5 連 |`（連線數依本作，**短在左、最長在右**，與 Config `pays` 由短到長一致；2026-11-20 使用者）；Pay Anywhere／Cluster Pay 以得分數量分欄（例 `8–9 顆`、`10–11 顆`、`12+ 顆`）。
- 只列會派彩的符號；Wild、Scatter 等沒有賠率的符號不進表，在表下寫明「無派彩」或其派彩方式（Scatter Pay）。
- 表下加 `計算規則：` 條列，必須包含：
  - 單一得分的完整公式，列出所有乘數與相乘順序，例：`賠率 × 該符號 Ways 數量 × Bet 基準 × Cascade Multiplier × <其他倍數>`。
  - 每個倍數的定義與無倍數時的值（例：總和為 0 時視為 `×1`）。
  - 多個符號同時中獎時各自計算後相加。
  - 是否提供 Scatter Pay。

### 3.7 §5. 核心特色

- 每個機制一個子章節（`### 5.1`、`### 5.2`…），每個子章節必須寫出：產生或觸發條件、出現範圍（哪些輪、哪些格、BG／FG 是否不同）、抽取使用的權重表名稱、效果、數值範圍、與其他機制的先後，以及至少一個帶數字的算例（例：`Cascade Multiplier ×3、用到 ×2 與 ×5 兩顆 WILD → 該波 ×21（3 × (2 + 5)）`）。
- 有 Cascade 的遊戲必須有「Cascade 消除與補位」子章節（消除範圍、同格多線只消一次、哪些符號不消除、何時結束）。
- 有倍數階梯時用表格列出各模式的每一階：

| 模式 | 第 1 次中獎 | 第 2 次中獎 | 第 3 次中獎 | 第 4 次中獎 | 第 5 次起 |
|---|---:|---:|---:|---:|---:|
| Base Game | ×a | ×b | ×c | ×d | ×e |
| Free Game | ×f | ×g | ×h | ×i | ×j |

  並寫明：何時推進、到頂是否停留、何時重置（每 Spin／每場 FG）、無中獎是否推進。
- 一次 Cascade 內有兩個以上步驟時（結算、消除、轉換、補牌、分裂…），必須有「處理順序」子章節，以編號列出固定執行順序。
- 有彩金（如 OP Jackpot）時另開子章節（或獨立章節），寫明：彩金階級、觸發符號與判定時機（每一轉或只看最終盤面）、與 FG 同時成立時的先後、解鎖押注門檻、小遊戲流程、是否計入一般 win 與 Max Win、參數來源。

### 3.8 §6. 免費遊戲（Free Spins / Free Game, FG）

固定三個子章節；遊戲沒有 FG 時保留 §6 並只寫「本作不提供 Free Game（不適用）」。

| 子章節 | 必須寫明 |
|---|---|
| `### 6.1 觸發` | 觸發符號與數量門檻、判定時機（例：所有 Cascade 結束後的最終盤面）、給幾場（是否依數量不同）、位置限制。 |
| `### 6.2 FG 玩法` | 與 BG 相同／不同的規則、選表方式、進場盤面（沿用 BG 最後盤面或重新產生）、倍數起始值、Bet 固定為觸發時 Bet、結束後回到 BG 的狀態。 |
| `### 6.3 Retrigger（加局）` | 條件、加幾場、最後一場可否 Retrigger、單次 FG 總場數上限、加場超過上限時的處理（例：只加到上限、多的切掉）。 |

### 3.9 §7. 核心遊戲流程（Base Game）

以編號清單依實際執行順序寫出一局 BG，至少涵蓋：開始 Spin（扣款）→ 選表（依 `Table Selection Weight`）→ 產生初始盤面 → 倍數初始化 → 特殊符號統計／彩金判定 → 判獎 → 無中獎則結束 Cascade → 有中獎則計分 → 消除／轉換／補牌（引用處理順序章節）→ 倍數推進 → 回到判獎 → 最終盤面判定 FG 觸發 → Max Win 截斷。每一步寫「做什麼」與「依哪一節規則」，例：`8. 若有中獎，依 §4 計算並累加本次 Cascade 得分。`

### 3.10 §8. 押注模式

- 可先放總表 `| 模式 | 價格 | 內容 |`，再依模式分子章節：`### 8.1 Extra Bet（額外投注）`、`### 8.2 Buy Feature（購買特色）`，有時再加 `### 8.3 Super Feature`、`### 8.x 批次購買操作`；遊戲沒有的模式寫「不提供」或省略該子章節（依第 2 節規定）。
- 每個模式必須寫明：

| 項目 | 說明 |
|---|---|
| 價格／扣款 | `N × Bet`。 |
| 模式代號 | 程式與 Config 使用的 `bet_mode` 整數：新遊戲固定 `0`＝NB、`1`＝EB、`2`＝EB2、`3`＝BF、`4`＝SF（沒有的模式跳過不補位）；既有遊戲維持原代號（2026-11-20 使用者）。另有平台端代號時一併寫出。 |
| 與 Normal Bet 的差異 | 盤面、選表、判獎、FG 規則哪些相同、哪些不同（例：FG 出現率為 Normal Bet 的 N 倍，由卡片系統控制）。 |
| RTP 與倍率分母 | RTP 以該模式實際押注為分母；卡片倍率判定以 Normal Bet 底注為分母。 |
| 進場方式（BF／SF） | 進場盤面如何產生（專用輪帶表名稱）、保證條件（例：保證 `C1 >= 3`、保證進場盤不得分）、進場後給幾場 FG、FG 使用哪組參數。 |
| 可購買條件（BF／SF） | 例：`N × Bet <= 餘額` 才可點擊，否則按鈕壓灰。 |

### 3.11 §9. 邊界 / 例外情境（Edge Cases）

- 依本作機制分類為 `### 9.1`、`### 9.2`…，常用分類：特色符號／Wild、倍數、Scatter、Free Game、Buy Feature、判獎計算（Ways／Line）、Cascade、彩金、Max Win、輪帶配置限制（數學前置條件）。
- 每條格式：`* **9.k.n 標題**：可直接寫成測試案例的敘述。`，例：`* **9.5.3 上限 50 場**：Retrigger 加場後超過 50 場時只加到 50 場，多出的場次切掉。`
- Max Win 分類必須寫明：上限來源（固定倍數或卡片系統倍率上限）、統計範圍（單一 Spin 含其觸發的全部 FG 場次）、達上限的處理（立即結束並以上限派彩）、Card System Off 是否套用、彩金是否納入。
- 輪帶配置限制必須寫明哪些符號不得出現在物理輪帶、專用輪帶（如 BF 進場表）必須保證的條件。

### 3.12 附錄與待確認事項

§9 之後依需要加入下列附錄，標題固定：

- `## 附錄 A. 詞彙對照`：表格欄位為「本文用語／程式 / 數學模型代號／英文／前端 / 規格書用語」；符號列的代號欄寫 `代號（ID n）`，例 `WW（ID 0）`，ID 與 Config `symbol_names` 一致。
- `## 附錄 B. 文件來源 / 參考`：表格欄位為「來源／內容」，列出前端規格書、前作 game_rule、數學模型等來源；下接 `### 來源優先級`，以編號清單寫：1. 本 `game_rule.md`（玩法正式來源）；2. `Source/H0xx1*.xlsx`（數值正式來源）；3. 前端遊戲規格書（演出與 UI）。
- 決策紀錄（放在附錄 B 內）：每次決策一節 `### YYYY-MM-DD <主題>`，表格欄位為「#／爭點／決策／影響章節」或「項目／調整前／調整後」，最後寫影響章節與需要同步的檔案。
- 與前端規格書的差異紀錄（放在附錄 B 內）：表格欄位為「項目／規格書／本文件／原因」。
- `## 待確認事項`：表格欄位為「#／問題／決議」；未決的寫 `⏳`，決議後填結論與日期。
