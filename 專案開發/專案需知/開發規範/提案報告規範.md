# 提案報告規範

本文件屬於 `專案需知/` 專案需知文件集（Omniplay 產線），總覽、共通原則與完成條件見 [_README.md](../其他/_README.md)。

**存放位置**（總表見[產出與紀錄規範](產出與紀錄規範.md#3-專案目錄與存放位置)）：

| 檔案 | 存放位置 |
|---|---|
| 發想中遊戲（尚無 Game ID）的提案簡報 | `Slots/其他/其他遊戲/遊戲發想/<遊戲名>/其他/提案/` |
| 已有 Game ID 的遊戲的提案簡報 | `Slots/H0xx_遊戲名稱/其他/提案/` |

提案簡報一律放專案的 `其他/提案/`，不放專案根目錄，也不放 `對外文件/`（2026-11-19 使用者）。

## 1. 用途與範圍

提案報告（遊戲提案說明簡報）用於向內部或客戶說明一款遊戲的玩法、規格、特色與競品差異，適用於遊戲發想與正式專案。

- **版式直接參考指定的過去簡報修改**，不另訂版面規則；沒有指定時用**最新的一份提案簡報**（各專案 `其他/提案/` 內修改時間最新的 `*_提案說明_v*.pptx`；2026-11-20 使用者），與第 6 節版面規格不同時以最新簡報為準並回頭更新第 6 節。
- 範例：`Slots/H039_急速糖果 2/其他/提案/CANDY_RUSH_2_提案說明_v14.pptx`。
- **取不到上述簡報時**（例：其他團隊的 AI），照第 6 節「版面規格」從零建立；第 6 節就是上述簡報的版式整理（尺寸、配色、字型、座標、元件），照做即可得到同一版式，不需任何過去檔案。
- **輸入資料**：`game_rule.md`（規則、符號、賠率、FG、押注模式；英文遊戲名取其「遊戲英文名」）、Config（數值）、該遊戲 Demogame（截圖）、符號圖檔（Demogame 素材）、競品資訊（規則基底遊戲的 `game_rule.md` 或競品分析報告）。

## 2. 檔案

| 項目 | 規則 |
| --- | --- |
| 格式 | `.pptx`，16:9 |
| 檔名 | `{英文遊戲名大寫，空格改底線}_提案說明_v{兩位數版本}.pptx`，例：`CANDY_RUSH_2_提案說明_v01.pptx` |
| 版本 | 內容每次修改版本 +1，舊版保留不覆蓋 |

## 3. 章節結構

章節名稱與順序固定。中文標題不加編號；右上頁碼用兩位數章節號（`01`～`08`），同一章的多頁沿用該章頁碼。

| 頁碼 | 英文小標 | 章節 | 必要內容 |
| --- | --- | --- | --- |
| — | — | 封面 | 英文遊戲名、中文遊戲名、三個賣點標籤、`遊戲提案說明 · 遊戲代號 · 規則基底／數學 · JumboRD`（遊戲代號＝6 碼 Game ID，尚無寫「遊戲代號 待定」；規則基底寫遊戲名稱，例：`規則基底 彩罐熱舞`） |
| 01 | OVERVIEW | 遊戲概述 | 簡單說明玩法與核心特色：主題與定位一句話、核心特色、demo 主畫面 |
| 02 | GAME SPEC | 遊戲規格一覽 | 只列規格，不說明怎麼玩：Line／Way 類型、盤面、押注模式、最大贏分／RTP 等 |
| 03 | SYMBOLS | 符號說明與賠付 | 符號種類（一般符號、特殊符號）與賠率表；註腳寫得分公式 |
| 03 | ART REQUIREMENT | 符號與美術需求（**隱藏頁**） | 一般與特殊符號清單（代號、等級）、美術風格參考、其他需求（場景、Loading、大廳 Icon、特色演出）；**一定要做，但設為隱藏投影片**，簡報時不播放 |
| 04 | CORE GAMEPLAY | 核心玩法 | 逐項說明玩法要素；內容多時拆成多頁，每頁只講一個特色 |
| 05 | FREE GAME | 免費遊戲 | 觸發、FG 內規則（例：倍數累積或重置）、加局 |
| 06 | GAME FLOW | 遊戲流程圖 | 不要畫太細，只針對容易看不懂的地方畫流程 |
| 07 | SPECIAL BET | 特殊押注 | Extra Bet、Buy Feature 等；有才放，每種押注一頁（例：3 種 EB、2 種 BF 拆成 5 頁） |
| 08 | VS. {競品} | 與{競品}差異對照 | 一句話核心差異＋對照表（最右欄為本作）＋結論註腳；英文小標寫競品英文名大寫（例：`VS. PINATA BEAT`），不寫 H0xx |
| — | — | Q&A | 只放「Q & A」大字、`英文名 · 中文名` 與註腳「※ 數值仍待數學調校，最終以認證版本為準。」；**不列待確認問題清單**（2026-11-12 使用者） |

- 主章節不可刪除；只有「特殊押注」在遊戲沒有 Extra Bet、Buy Feature 時整章省略，並在規格表寫「不提供」。
- 競品預設為規則基底遊戲；另有指定時依指定。
- **全份不寫 Math ID（H0xx）**：前作、規則基底、競品、對照表表頭一律寫遊戲名稱（例：寫「彩罐熱舞」，不寫「彩罐熱舞 1000（H026）」）（2026-11-12 使用者）。

### 3.1 各頁內容與版面

元件名稱（標題列、數字卡、編號條列、重點框、截圖框、表格、註腳）定義見第 6 節。每頁都有標題列；除封面與 Q&A 外，頁面下緣可放註腳。

| 章節 | 版面（左→右／上→下） | 內容寫法 |
| --- | --- | --- |
| 封面 | COVER 版；置中：遊戲圖示（可省）→ 英文名 → 中文名（字與字間加空格，例：`彩 罐 熱 舞`）→ 三個賣點標籤 → 底部一行說明 | 賣點標籤每個 ≤ 8 字，講玩家看得到的特色 |
| 01 遊戲概述 | 左半：粗體一句定位（紅字）＋一段 2 行內說明 → 3 張數字卡（盤面、核心機制、最高倍數等）→ 重點框一句；右半：demo 主畫面截圖＋圖說 | 一句話講「這是什麼遊戲、玩點在哪」 |
| 02 遊戲規格一覽 | 上方 4 張數字卡（中獎方式、盤面、FG 局數、押注選項數）→ 4 欄規格表（項目｜規格｜項目｜規格）→ 註腳 `※ 依 game_rule.md v<版本>（規則基底 <遊戲名>）；* 為待確認數值。` | 規格表列：遊戲類型、盤面、中獎方式、符號、免費遊戲、押注選項、特色機制、最大贏分／RTP |
| 03 符號說明與賠付 | 上方左：一般符號圖示列（每個符號圖＋代號）；上方右：特殊符號圖示＋一句功能；下方：賠率表（列＝符號、欄＝連線數或群集數）；註腳寫得分公式 | 賠率單位寫在表標題（例：`一般符號賠付（× Bet，依連線數）`） |
| 03 符號與美術需求（隱藏） | 一句概述（符號數量、美術風格參考）→ 一般符號大圖列（代號）→ 特殊符號與演出標記（圖＋名稱）→ 註腳列其他需求（場景、Loading、大廳 Icon、特色演出） | 寫給美術看，標明哪些沿用、哪些新增 |
| 04 核心玩法 | 第 1 頁：左側 4 項編號條列（每項標題＋一行說明）、右側截圖；後續每頁一個特色：上方「一句話：…」主旨列，下方編號條列＋截圖，或 2～3 張截圖由左到右標 ①②③ 說明步驟 | 每頁只講一個特色；數值未定加 `*` |
| 05 免費遊戲 | 左：粗體標題＋說明 → 「觸發」「加局」「其餘規則」小標各一兩行；右：FG 截圖＋圖說 | 觸發條件與局數寫成 `3 / 4 / 5 Scatter → 10 / 15 / 20 局` 形式 |
| 06 遊戲流程圖 | 上方「一句話」→ 一列 4～5 個步驟方塊（① 判定 → ② 計分 → …）以箭頭連接，回圈處標「有新中獎 → 回到 ①」→ 下方 3 個編號重點（容易誤解的地方） | 只畫容易看不懂的部分 |
| 07 特殊押注 | 每種押注一頁：「一句話」→ 左：截圖（1～2 張）或數字卡；右：「項目｜設定」2 欄表（價格、玩法差異、RTP、保底等） | 標題寫 `特殊押注：Extra Bet`、`特殊押注：Buy Feature` |
| 08 差異對照 | 「本作核心差異：…」一句 → 3 欄對照表（項目｜競品｜本作），本作欄表頭紅底、內容粗體 → 結論註腳 `→ …`；需要時加一頁「相較競品的調整」：3 張數字卡（`7×7 → 5×5` 等）各附「調整原因」 | 列 6～10 項差異 |
| Q&A | COVER 版；置中「Q & A」→ 遊戲名 → 註腳 | 不列待確認 |

## 4. 內容規則

- **規則與數值**一律以 `game_rule.md` 與 Config 為準，不得出現與 Game Rule 不一致的內容。
- **未定案的數值**在數字後加 `*`，該頁註腳寫「* 為待確認數值」；尚未調校完成的 RTP、最大贏分寫「待數學訂定」（不列入 Q&A 頁，見第 3 節）。不得用 ⏳ 等 emoji（PowerPoint 會顯示成圖示）。
- **文字精簡**：每頁一句話主旨＋條列不超過 4～5 項，細節留在 Game Rule；賠率表欄位過多時只列代表欄，註腳註明完整賠率見 `game_rule.md`。
- **demo 截圖**一律從該遊戲 Demogame 擷取，不用示意繪圖代替：
  - 用 Debug 的 RNG Seed 重現指定局、逐幀停在要展示的瞬間，以 2 倍解析度擷取，確保可重現。
  - 只取 By Game 區域（Feature Status＋盤面＋盤面訊息），不得帶到 Debug 面板；Stats 不得出現誤導數字（需要時用全新頁面跑單局）。
  - 每張截圖附一行圖說，說明畫面重點。

## 5. 製作與檢查

- 建議以 `pptxgenjs` 產生（版面以程式定義，方便改版重建）；產生腳本與暫存截圖放暫存區，專案內只保留最終 `.pptx`。
- 交付前檢查：
  - [ ] 章節與頁碼符合第 3 節，「符號與美術需求」頁已設為隱藏。
  - [ ] 規則、數值、截圖符合第 4 節。
  - [ ] 以 PowerPoint 匯出圖片逐頁目視：沒有文字溢出、元件重疊。
  - [ ] 檔名、版本符合第 2 節，pptx 技能的 `validate.py` 通過。
  - [ ] 全份搜尋不到 `H0` 開頭的 Math ID；Q&A 頁沒有待確認清單。
  - [ ] 版面符合第 6 節（底色、字型、標題列座標、頁碼）。

## 6. 版面規格

過去提案簡報的版式整理；沒有參考檔時照此建立，有參考檔時以參考檔為準。尺寸單位為英吋（in），座標為元件左上角 (x, y)、大小為 寬×高。

**畫布與版型**

| 項目 | 規格 |
| --- | --- |
| 尺寸 | 13.333 × 7.5 in（16:9，pptxgenjs `LAYOUT_WIDE`） |
| COVER 版（封面、Q&A） | 底色 `#1A0F3A`（深紫） |
| CONTENT 版（其餘各頁） | 底色 `#FFFBF4`（米白） |
| 字型 | 中文 `Microsoft JhengHei`；英文小標、頁碼、大數字、英文遊戲名 `Georgia` |
| 不用 | emoji、漸層、陰影以外的特效；文字一律可編輯（不轉圖） |

**pptxgenjs 骨架**（標題列與註腳寫成共用函式，每頁呼叫）：

```js
const pptxgen = require("pptxgenjs");
const p = new pptxgen(); p.layout = "LAYOUT_WIDE";
const ZH = "Microsoft JhengHei", EN = "Georgia";
p.defineSlideMaster({ title: "COVER", background: { color: "1A0F3A" } });
p.defineSlideMaster({ title: "CONTENT", background: { color: "FFFBF4" } });
function head(s, en, zh, no) {
  s.addText(en, { x: 0.7, y: 0.4, w: 9.0, h: 0.4, fontFace: EN, fontSize: 12.5, color: "E9A825", charSpacing: 2 });
  s.addText(zh, { x: 0.7, y: 0.8, w: 11.0, h: 0.7, fontFace: ZH, fontSize: 30, bold: true, color: "1F1147" });
  s.addText(no, { x: 11.7, y: 0.6, w: 1.0, h: 0.3, fontFace: EN, fontSize: 13, color: "E9A825", align: "right" });
}
function foot(s, t) { s.addText(t, { x: 0.7, y: 6.9, w: 11.9, h: 0.3, fontFace: ZH, fontSize: 11, color: "7D6A80" }); }
// 美術需求頁要隱藏：存檔後用 python-pptx 在該頁設 slide._element.set("show", "0")（PowerPoint 的「隱藏投影片」）
p.writeFile({ fileName: "<英文名大寫>_提案說明_v01.pptx" });
```
