# 數值報告規範

卡片權重完成後（開發流程步驟 2.4 遊戲調性調整），產出數值報告（即本作與競品、前作的差異分析），比較本作與競品（及使用者指定的前作）的玩法指標，作為調性是否到位的依據。

本規範自足：照本文的名詞、指標定義、md 骨架、圖表資料格式與附錄 A 的 HTML 外殼，不需參考任何過去報告即可產出。文中遊戲名（Super Ace、Lucky Diamond 等）只是「例」，規則以文字為準。

**名詞**

| 名詞 | 意思 |
|---|---|
| 本作／競品／前作／同系列 | 本作＝這次要出報告的遊戲；競品＝對標的他廠遊戲（預設為規則基底遊戲）；前作＝使用者指定的自家舊作；同系列＝同 IP／同玩法的自家作品 |
| NB／EB／BF／SF | 押注模式：Normal Bet（一般）、Extra Bet（加注）、Buy Feature（購買免費遊戲）、Super Feature（較貴的購買） |
| BG／FG | Base Game（一般遊戲，付費的那一轉含其所有連消）／Free Game（免費遊戲） |
| 局／轉／場 | 局＝一次付費下注（含連消，不含觸發後的 FG）；轉＝一次免費轉；場＝一次 FG 從觸發到結束（含加局） |
| 底注 | 一次 NB 下注金額；所有「x 倍」都以底注為分母（BF／SF／EB 也一樣），只有 RTP 與標準差用各模式的實際押注或購買價 |
| Card-On／Card-Off（自然） | Card-On＝套用卡片權重（正式 RTP／Variant 的 config）後的模擬；Card-Off＝不套卡片、只有輪帶與規則的「自然機率」 |
| Oldhand／Newbie | 卡片 Profile：老手／新手；數值報告一律用 Oldhand |
| 92A、94B… | RTP 檔位＋版本（92% A 版），對應 `config_01A.js` 的 `92A` 層級 |
| Record 報表 | Simulator 輸出的 xlsx（放 `Record/`），檔名格式 `<MathID>_<版本8碼>_<時間>_betmode<N>_<log10局數><…>_<RTP萬分位>_<profile>_<bet 層級>_card.xlsx`；`betmode0`＝NB、`1`＝EB、`2`＝BF、`3`＝SF；Card-Off 報表無 `_card` |

**檔案與格式**

- 檔名：md 為 `個人筆記/數值報告.md`，HTML 為專案根目錄 `report.html`（與 `index.html` 同層），兩份內容一致；不另取其他檔名（2026-11-03 起；舊名 `其他/數值報告_<遊戲中文名>.md／.html`）。舊名 `差異分析_<遊戲中文名>` 一律改為此名。
- 遊戲名稱一律用英文名（例：Super Diamond、Super Ace、Lucky Ace），不用 H0xx 代號。
- **頁首照競品分析報告**（2026-11-09 起）：上方小字 `Omniplay · 數值報告`（遊戲商一律 Omniplay），大標題＝`<遊戲中文名> <遊戲英文名>`（例：`幸運鑽石 Lucky Diamond`；英文名取 `game_rule.md` 的「遊戲英文名」，缺的不顯示），由 `_report_card_style.py` 自動寫入；KPI 列用競品報告的細框格子。`<title>` 與 md 的 `#` 標題維持 `數值報告_<遊戲中文名>`。不寫「A vs B vs C」；比較對象改在「基本資訊」章交代。
- 章節（頁簽）名稱照下表「必要章節」的中文名，不加英文括號（例：寫「連消分布」，不寫「連消分布（Combo）」）。
- HTML 最上方放「← 返回 Demo」，連回 `./index.html`；從 Demo 點進來時改為回上一頁。Demo 的數值報告按鈕在同一分頁開啟，推上網頁後也能用瀏覽器上一頁返回。
- **新報告要收錄到 Omniplay 首頁**：數值報告區不會自動掃描，第一次產出並推上 GitHub 後，在 `AI 工作區/Jumbo_Output/catalog.js` 的「數值報告」區加一筆（title 遊戲中文名、kind "數值報告"、url 用 rhino-boss.github.io 完整網址、game 代號、desc 一行「本作 vs 競品：主要章節」、date 產出日期），同時把 index.html／all.html 的 `?v=` 快取版號加一碼，再推上 Jumbo_Release。
- HTML 版式同 `市場資訊/H5/遊戲資訊/` 的競品分析報告：每章一個頁簽、頁簽只排一列可橫拉但不顯示拉條；表格儲存格不換行，表格放不下時左右拖曳捲動（不顯示拉條，2026-11-20 使用者）。版式已完整寫在附錄 A（外殼）與 `_report_card_style.py`（卡片版型），不需開競品報告參考。
- **重產網頁**：`py -X utf8 專案需知/其他/_report_build.py <專案>/report.html [曲線.json]` 由 `個人筆記/數值報告.md` 重畫報告頁簽、倍率線型（md 的 `<!--CHART:key-->`，資料 json 格式見腳本說明）與頁首 KPI，並自動套卡片版型。
- **手機版字級**（2026-11-20）：`html` 設 `text-size-adjust:100%`，表格內的字不讓 iOS 自動放大，跟內文同字級；由 `_report_card_style.py` 寫入。
- **卡片版型**：HTML 產出後一律跑 `py -X utf8 專案需知/其他/_report_card_style.py <專案>/report.html`：淺灰底＋圓角卡片（深色模式為深灰卡片）、膠囊頁簽、競品報告式頁首與 KPI 格，每節（`###`）一張卡片；倍率線型的圖例每一條線都可點選開關。可重複執行，重產 HTML 後再跑一次即可。
- **自動頁簽**：`_report_card_style.py` 同時產生三個頁簽（單跑：`_report_notes.py <專案>/report.html`），md 不重複內容：**玩法說明**（第 2 頁，取 `game_help.md` 繁中規則說明與中文賠率表，不放 Game Meta、GAME RULE）、**修改紀錄**（`個人筆記/修改紀錄.md`）、**其他**（`個人筆記/上線觀察.md`＋`注意事項.md`：上線觀察、開發注意事項、歷史錯誤紀錄）；頁簽號自動重編。改了這些 md 要重跑。
- 百分比表格套條件式橫條（同競品報告：同表共用刻度、最大值以強調色、合計列不畫）；表格內只放百分比，不附括號內的分子／分母。

**比較口徑**

- 本作與前作一律用 **Card-On**（正式 RTP／Variant、Oldhand）報表；競品用實機側錄資料。自然機率（Card-Off）只可作附加欄，不得當主比較欄。
- 模擬在模擬機執行（NB ≥ 10⁶ 局、BF ≥ 10⁵ 次），報表存 `Record/` 並在報告來源表列出檔名。
- 指標口徑與競品報告一致；口徑不同時（例：分母只算初始盤面）以競品口徑為準並在該節說明。

**必要章節**

| 章節 | 內容 |
|---|---|
| 1. 基本資訊 | 頁簽之外只留頁首。節的順序：**遊戲簡介**（200 字內：盤面、怎麼贏、特色機制、FG 怎麼觸發、BF 價格，寫到玩家看完就懂規則）→ **比較對象** → **報告資訊**。**比較對象**表：固定三欄「類別｜遊戲｜為什麼比」、固定三列「競品／前作／同系列」；遊戲寫英文名＋廠商或版本（例：Money Coming（JILI）、Money Boost 1.0.0.2（原始版））；為什麼比用一句話說明比較目的；沒有的列遊戲欄填「—」並註明（例：目前沒有同系列作品。）。**報告抬頭資訊一律放在本章**：產出日期、比較口徑（本作／前作／競品各用哪種資料、Profile）、本作版本與主要設定摘要（盤面表與選表比例、補牌與倍數規則、賠率、FG 階梯、BF 價格、EB、自然率門檻、Max Win 等）、**資料來源表**（來源｜樣本數｜報表檔名）。 |
| 2. 玩法說明 | 自動頁簽：`game_help.md` 的規則介紹（含賠率表），見上方「自動頁簽」。 |
| 3. 共同指標 | **基本指標**（第一節，一張表）：**有「押注模式」表的遊戲，基本指標只列 NB**，BF／SF 的價格、RTP、贏錢率、平均倍數、標準差、門檻週期、自然允許最大區間都只放押注模式表，不在基本指標重複（2026-11-20 使用者，H032）；Total RTP、BG／FG RTP、BG Hit Rate、FG Hit Rate（每轉）、FG 週期、FG 平均倍數，併入原「玩法深淺」的 NB 標準差、FG 標準差（每場，以押注計；2026-11-11 起）、≥1000x／≥5000x／≥10000x 週期，有 Buy Feature 再列 BF 價格、BF RTP、BF 贏錢率（贏分 > 購買價）、BF 平均倍數、BF 標準差與高倍週期；競品／前作／同系列並列，沒有的填「—」；表後一句「平／深」結論（看標準差與存活中位數，平均把數由 RTP 決定不具鑑別度）。**第二節為存活模擬**：1000 人各帶 1000 元、每把押 1 元玩 NB 至不夠下注，**以比例顯示**：列＝第 1,000／5,000／10,000／20,000 把仍存活的玩家比例（2026-11-09 起）；以 Card-On 報表每局總得分分布（BG 非觸發局＋觸發局含觸發把）抽樣，註明抽樣方式。 |
| 4. 特殊指標 | 依遊戲機制挑選，每個指標一節（`###`），BG／FG 用 `####`。例：**金框比例**：平均每盤金框數、每格金框率、有金框盤面占比、各輪金框率（BG／FG 分開）；**金框使用率**：被消到而翻牌的金框數 ÷ 初始盤面金框數（BG／FG 分開）；**連消分布**：BG 每局、FG 每轉的 0／1／2／3／4／5+ 次（不加 3+ 合計列）；**大鬼出現率**：BG 每局、FG 每轉；並註明本作 BG 幾局一次、FG 每場幾次；**符號消除分布**：各符號 3／4／5 連的 Hit Rate 與 RTP（BG／FG 分開）；**WILD 倍數分布**：有帶倍數 Wild 的遊戲才需要：各種 Wild（如小鬼、大鬼本體、分裂）分開列各倍數占比。 |
| 5. 倍率線型 | NB-BG、NB-FG、BF **各一張**折線圖（預設縱軸 BG 0–1%、FG／BF 0–16%；**滑鼠滾輪縮放縱軸、雙擊還原**（手機等觸控裝置：兩指捏合縮放、點兩下還原，不放按鈕，2026-11-20），由 `_report_card_style.py` 內嵌 `_chart_yzoom.js`，2026-11-09 起不再另畫放大圖），每張都含競品、前作、本作（卡片後，實線）與**本作自然機率（Card-Off，卡片前，同色虛線，預設隱藏、點圖例才顯示）**；64 區間全標；縱軸固定（BG 0–1%、FG／BF 0–16%），**圖例可點選切換各線顯示／隱藏**（關閉的圖例淡化加刪除線）；附 FG／BF 門檻機率表（含本作自然欄）；**滑鼠游標移到圖上鎖定該區間**，畫垂直線並列出各線數值（隱藏的線不列）；**圖例只寫名稱＋版本**（例：Super Ace、Super Diamond v5.0.0.0、Super Diamond v5.0.0.0 自然），不加括號說明；**圖下不加說明**；**每個區間都畫點**，機率 0 的點在 0 的位置，整條線全部連起來（不斷開）且**線半透明**，超過縱軸上限的部分被圖框裁掉；**x 軸寫法** `0`、`0 < x <= 1`、`1 < x <= 2`…（整數不加小數點，有小數才寫）；**競品一律灰色**，本作用彩色 |
| 6. 修改紀錄 | 自動頁簽（`個人筆記/修改紀錄.md`），每個版本一節。 |
| 7. 其他 | 自動頁簽：上線觀察、開發注意事項、歷史錯誤紀錄（取自 `個人筆記/上線觀察.md`、`注意事項.md`）。 |

特殊指標的版面（2026-11-11 起）：第一節「重點一覽」把單一數值的指標（平均、比例、使用率、Max／中位數／平均等）收成一張表；其餘每個分布一節、一張表，列＝分段，欄＝`BG · 競品`、`BG · 本作`、`FG · 競品`、`FG · 本作` 並排（只有 FG 的指標就兩欄），不再 BG／FG 各拆一張上下疊；表頭照「BG · 名稱」寫，`_report_card_style.py` 會在 BG 與 FG 欄組之間自動留空。和競品比較的單一數值（重點一覽等），本作比競品好的用綠字、差的用紅字、相同不上色：md 儲存格結尾寫 ` {+}`（好）或 ` {-}`（差），`_report_build.py` 會轉成顏色並去掉標記；好壞以玩家感受判斷，判斷方向寫在表下說明。**不加與競品的差（pp）欄、不加 3+ 等合計列**；口徑說明寫在表前一句或重點一覽下方的條列。

沒有對應機制的章節（例如無金框、無大鬼）可省略，但要在報告開頭註明；頁簽編號一律從 1 依序連號，省略章節後也重新連號（不沿用本表編號）。指標未達使用者設定的對標目標時，於回報中列出差距與可調的槓桿，由使用者決定是否調整；調整後重跑 Card-On 並重出數值報告。

## 產生流程（從零開始）

1. **備資料**：
   - 本作 Card-On 報表：NB（betmode0）必備；有 EB／BF／SF 各跑一份（betmode1／2／3）；Oldhand、中 Bet（`medium_bet`）、主版本 92A（有 B 版另跑 92B）。
   - 本作 Card-Off 自然報表：NB、BF（有 EB／SF 也跑），只用於倍率線型虛線與「自然允許最大區間」。
   - 前作：同口徑 Card-On 報表（`Record/` 內現成的即可，檔名寫進來源表）。
   - 競品：實機側錄整理出的數據報告（`遊戲數據_<英文名>.md`，由 game-data-report 產出；指標口徑同下方「指標定義」）。沒有的指標填「—」，不要自己估。
2. **寫 md**：照下方「md 骨架」寫 `個人筆記/數值報告.md`，數值照「指標定義」計算。
3. **備圖表資料**：照「倍率線型資料」產生 `curves.json`（可放暫存區，不留在專案）。
4. **建外殼（工具自動）**：專案還沒有 `report.html` 時，第 5 步的 `_report_build.py` 會用附錄 A 的外殼（模板檔 `專案需知/其他/_report_shell.html`）自動建立，不要手動貼：MathID 與中文名取自專案資料夾名 `H0xx_中文名`，英文名取自 `game_rule.md` 的「遊戲英文名」；取不到時加 `--id H045 --name 幸運鑽石 --en "Lucky Diamond"`。已有 `report.html` 就沿用，不會重建。
5. **重產網頁**：`py -X utf8 -B 專案需知/其他/_report_build.py <專案>/report.html curves.json`（會自動跑 `_report_card_style.py`，產生玩法說明／修改紀錄／其他頁簽與卡片版型）。
6. **檢查**：瀏覽器開啟逐頁簽看（含手機寬度與深色模式），對照文末「交付檢查」。
7. **收錄首頁**：第一次產出時依「檔案與格式」把報告加進 Omniplay 首頁 catalog。

## md 骨架（`_report_build.py` 的讀取規則）

- 第一行 `# 數值報告_<遊戲中文名>`。
- 每章 `## N. 章名`（N 從 1 連號）；**一章＝一個頁簽**，頁簽名稱照章名。章名為「玩法說明」「修改紀錄」「其他」的章是自動頁簽，md 只留一行說明，內容不會被讀。
- 每節 `### 節名`＝一張卡片；節內再分 BG／FG 用 `####`。章開頭、第一個 `###` 之前的文字是說明列（不成卡片，含表格或圖時才成卡片）。
- 表格用 GitHub 表格語法，數值欄對齊寫 `---:`。一格只放一個值。
- 圖表位置寫 `<!--CHART:bg-->`、`<!--CHART:fg-->`、`<!--CHART:bf-->`（key 對應 `curves.json`），建議每張圖自己一個 `###` 節（卡片標題取代圖內標題）。
- 本作比競品好／差：儲存格結尾寫 ` {+}`／` {-}`（只用於和競品比較的單一數值）。
- 頁首 KPI 自動取「基本指標」表**本作欄**（表頭＝`game_rule.md` 的「遊戲英文名」，找不到用開頭相同的欄，再不行用第 2 欄）的這 8 列，列名必須**一字不差**：`Total RTP`、`BG RTP`、`FG RTP`、`BG Hit Rate`、`FG Hit Rate（每轉）`、`FG 週期`、`FG 平均倍數（每場）`、`BF RTP`；值為空或「—」不顯示。
- 百分比橫條自動判斷：一欄中 ≥ 60% 的格子是「數字%」才畫；第一欄含「合計／總計／小計／Total」的列不畫；「基本指標」表不畫。
- 表格內數字格式：百分比 2 位小數（`23.54%`，存活比例 1 位）；週期 `1/150.0`（FG 週期 1 位小數；高倍週期取整數、千分位 `1/341,661`）；倍數 `37.71x`；標準差 2 位；局數、次數千分位。

最小範例（佔位符 `<…>` 換成實際內容；沒有的機制整節刪掉並在基本資訊註明）：

```markdown
# 數值報告_<遊戲中文名>

## 1. 基本資訊

### 遊戲簡介

<200 字內：盤面、怎麼贏、特色機制、FG 怎麼觸發、BF 價格>

### 比較對象

| 類別 | 遊戲 | 為什麼比 |
|---|---|---|
| 競品 | <英文名>（<廠商>） | <一句話比較目的> |
| 前作 | <英文名>（<版本或代號>） | <一句話> |
| 同系列 | — | 目前沒有同系列作品。 |
```

## 指標定義

所有指標（含高倍週期與標準差）一律以套卡片的模擬報表（Card-On Record）計算，不用卡片理論分布估算（2026-11-20 使用者）；欄位名指報表工作表 `Overview`（Index／Value 兩欄）與 `Multiplier Line`（每列一個倍率區間）。競品用側錄資料照同一定義計算。

**基本指標（NB 報表）**

| 列名（照寫） | 定義 | 報表來源 |
|---|---|---|
| Total RTP | 總派彩 ÷ 總押注。有 OP Jackpot 時 Total 含彩金（Link＋Bonus），另加 `Game RTP`（不含彩金）與 `OP Jackpot RTP（Link＋Bonus）` 兩列 | `rtp_total`、`rtp_game`、`rtp_link`、`rtp_bonus` |
| BG RTP | BG 派彩 ÷ 總押注 | `rtp_bg` |
| FG RTP | FG 全部派彩 ÷ **總押注**（對 Total 的貢獻，不是 FG 內部回報率） | `rtp_fg` |
| BG Hit Rate | BG 有得分（> 0）的局數 ÷ 付費局數 | `hit_rate_bg` |
| FG Hit Rate（每轉） | 有得分的免費轉 ÷ 免費轉總數 | `hit_rate_fg` |
| FG 週期 | 付費局數 ÷ FG 觸發次數（FG 內加局不算觸發），寫 `1/N` | `fg_trigger_rate` 括號內的 cycle |
| FG 平均倍數（每場） | 每場 FG 全程得分 ÷ 底注 的平均（＝ FG RTP × FG 週期，可互相驗算） | 同左計算 |
| NB 標準差（以押注計） | 每局總得分（含該局觸發的整場 FG）÷ 押注 的標準差 | `volatility_std` |
| FG 標準差（每場，以押注計） | 每場 FG 全程得分 ÷ 押注 的標準差 | Simulator 直接輸出逐場標準差（`Overview` 的 `volatility_std_fg`，2026-11-20 使用者；不用區間平均估算） |
| NB ≥1,000x／≥5,000x／≥10,000x 週期（底注，每局） | 付費局數 ÷「每局總得分 > 門檻 × 底注」的局數，寫 `1/N`；樣本內沒出現寫「—」或「未觀測（樣本數）」 | `Multiplier Line`：下界 ≥ 門檻的區間，`base_game_cnt`（非觸發局）＋`free_game_cnt`（觸發局，以整場 FG 得分計）合計 |
| BG／FG 自然允許最大區間（選用） | Card-Off 自然機率中發生率 ≥ 0.05% 的最高倍率區間，寫 `350 ~ 400x`；再往上的區間不能配卡片權重 | Card-Off 報表 `Multiplier Line` |

**Buy Feature 類（BF／SF 報表；遊戲有「押注模式」表時只放押注模式表，見必要章節）**

| 列名（照寫） | 定義 | 報表來源 |
|---|---|---|
| BF 價格 | 購買價 ÷ 底注，寫 `50x` | `feature_price_multiplier` |
| BF RTP | 購買全程派彩 ÷ 購買價合計 | `rtp_total`（有彩金時另列 Game） |
| BF 贏錢率（贏分 > 購買價） | 全程得分 **嚴格大於** 購買價的次數 ÷ 購買次數 | `Multiplier Line` `free_game_cnt`：下界 ≥ 價格的區間合計（價格不在區間邊界時，例 40.5x，改用逐筆購買資料計算） |
| BF 平均倍數（每次購買） | 每次購買全程得分 ÷ 底注 的平均（＝ BF RTP × 價格） | 同左計算 |
| BF 標準差（以購買價計） | 每次購買全程得分 ÷ 購買價 的標準差 | `volatility_std` |
| BF ≥1,000x／≥5,000x／≥10,000x 週期（底注，每次購買） | 購買次數 ÷ 全程得分 > 門檻 × 底注 的次數 | `Multiplier Line` `free_game_cnt` |

**押注模式表**（有 EB／BF／SF 時，欄＝Normal Bet、Extra Bet、Buy Feature、Super Feature，有幾種放幾欄）列固定為：價格（倍 Bet）、Total RTP、（有彩金時）Game RTP／Link RTP／Bonus RTP、BG RTP、FG RTP、BG Hit Rate、FG Hit Rate（每轉）、FG 週期、FG 平均倍數（每場，底注）、贏錢率（贏分 > 購買價）、標準差（以押注／購買價計）、≥1,000x／≥5,000x／≥10,000x 週期（底注）、BG／FG 自然允許最大區間。不適用填「—」（例：BF 沒有 BG RTP、FG 週期）。RTP 分母為各模式實際押注（EB 2 倍、BF 價格倍）；倍數與門檻週期一律以底注計；表後寫一段分母說明。

**平／深結論**：看 NB 標準差與存活模擬（10,000 把仍存活比例、存活中位數）和比較對象相比；標準差較高且存活比例較低為「深」，反之為「平」；不訂數字門檻（2026-11-20 使用者）。平均把數由 RTP 決定，不具鑑別度，不作判斷依據。

**存活模擬**（`專案需知/其他/_survival.py`，輸入 NB Card-On 報表，所有遊戲同一套算法）：

| 項目 | 規則 |
|---|---|
| 玩家 | 1000 人，各帶 1000 元，每把押 1 元，玩到餘額 < 1 為止 |
| 每把得分 | 從報表「每局總得分 ÷ 底注」分布抽樣：BG 非觸發局用 `base_game_cnt`／`base_game_pay`；觸發局用 `free_game_cnt`／`free_game_pay`（整場 FG），再加觸發把的平均 BG 得分（`bg_trigger_fg_pay ÷ bg_trigger_fg_cnt`）；抽中區間後取該區間平均得分 |
| 驗算 | 抽樣分布平均＝報表 NB RTP（Game RTP，不含彩金） |
| 亂數 | 種子 1～6 各跑一次（每份報表各自 `numpy.random.default_rng(seed)`），比例取 6 次平均 |
| 輸出 | 第 1,000／5,000／10,000／20,000 把仍存活比例（＝還能下第 N 把的人數比例）；另附平均把數與中位數（6000 人合併） |

**特殊指標**：依遊戲機制自訂，每個指標在表前用一句寫清楚「分子 ÷ 分母、統計單位（每局／每轉／每場）、資料來源」。常見定義：

| 指標 | 定義 |
|---|---|
| 平均每盤金框數 | 初始盤面（停輪，不含補牌）金框總數 ÷ 盤面數 |
| 每格金框率 | 初始盤面金框總數 ÷（盤面數 × 盤面格數）；分輪時分母用該輪格數 |
| 有金框的盤面 | 初始盤面至少 1 個金框的盤面 ÷ 盤面數 |
| 金框使用率 | 被消到而翻牌的金框數（含補牌補上的）÷ 初始盤面金框數 |
| 連消分布 | 每局（BG）／每轉（FG）的得分次數 0／1／2／3／4／5+ 占比；0 次比例 ＋ Hit Rate ＝ 100% |
| 符號消除分布 | Hit Rate＝該符號該連線數的中獎次數 ÷ 該 Scene 轉數；RTP＝該符號該連線數派彩（已乘連消倍數）÷ 總押注；來源 `Symbol Length` 工作表 |
| WILD 倍數分布 | 各種帶倍數 Wild 分開，各倍數顆數 ÷ 該種 Wild 總顆數，表末列「顆數」 |
| 出現率類（大鬼等） | 事件數 ÷ 該 Scene 轉數，並換算「BG 幾局一次」「FG 每場幾次」 |

## 倍率線型資料

**64 區間**（倍率＝得分 ÷ 底注，區間為左開右閉 `(下界, 上界]`，不可增減）：

| 範圍 | 間距 | 區間數 |
|---|---|---|
| 0（得分為 0） | — | 1 |
| 0～10 | 1 | 10 |
| 10～50 | 5 | 8 |
| 50～100 | 10 | 5 |
| 100～200 | 20 | 5 |
| 200～1,000 | 50 | 16 |
| 1,000～10,000 | 1,000 | 9 |
| 10,000～100,000 | 10,000 | 9 |
| 100,000 以上 | 上界寫 9999999 | 1 |

標籤寫法：`0`、`0 < x <= 1`、`1 < x <= 2`…`100000 < x <= 9999999`（整數不加小數點、不加千分位）。Record 報表 `Multiplier Line` 的 `Interval` 欄寫成 `0.0 < X <= 1.0`，轉成上面的寫法。

**每條線的數值**＝該區間占比（%，數字 0.5 代表 0.5%），同一條線 64 格合計 100：

| 圖 | key | 統計單位 | 報表欄位 | 縱軸 ymax |
|---|---|---|---|---|
| NB-BG | `bg` | 每個**未觸發 FG** 的局（觸發局不計入，剩下的重新正規化為 100%） | `base_game_cnt` ÷ 其合計 | 1 |
| NB-FG | `fg` | 每場 FG 全程得分 | `free_game_cnt` ÷ 其合計 | 16 |
| BF | `bf` | 每次購買全程得分 | BF 報表 `free_game_cnt` ÷ 其合計 | 16 |

EB、SF 併入同一張圖（例：NB-FG 圖加一條 EB-FG 線、BF 圖加一條 SF 線），不另開圖。
