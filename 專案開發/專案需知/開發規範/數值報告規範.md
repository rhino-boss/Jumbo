# 數值報告規範

卡片權重完成後（開發流程步驟 2.4 遊戲調性調整），產出數值報告（即本作與競品、前作的差異分析），比較本作與競品（及使用者指定的前作）的玩法指標，作為調性是否到位的依據。

**檔案與格式**

- 檔名：md 為 `個人筆記/數值報告.md`，HTML 為專案根目錄 `report.html`（與 `index.html` 同層），兩份內容一致；不另取其他檔名（2026-11-03 起；舊名 `其他/數值報告_<遊戲中文名>.md／.html`）。舊名 `差異分析_<遊戲中文名>` 一律改為此名。
- 遊戲名稱一律用英文名（例：Super Diamond、Super Ace、Lucky Ace），不用 H0xx 代號。
- **頁首照競品分析報告**（2026-11-09 起）：上方小字 `Omniplay · 數值報告`（遊戲商一律 Omniplay），大標題＝`<遊戲中文名> <遊戲英文名>`（例：`超級鑽石 Lucky Diamond`；英文名取 `game_rule.md` 的「遊戲英文名」，缺的不顯示），由 `_report_card_style.py` 自動寫入；KPI 列用競品報告的細框格子。`<title>` 與 md 的 `#` 標題維持 `數值報告_<遊戲中文名>`。不寫「A vs B vs C」；比較對象改在「基本資訊」章交代。
- 章節（頁簽）名稱照下表「必要章節」的中文名，不加英文括號（例：寫「連消分布」，不寫「連消分布（Combo）」）。
- HTML 最上方放「← 返回 Demo」，連回 `./index.html`；從 Demo 點進來時改為回上一頁。Demo 的數值報告按鈕在同一分頁開啟，推上網頁後也能用瀏覽器上一頁返回。
- **新報告要收錄到 Omniplay 首頁**：數值報告區不會自動掃描，第一次產出並推上 GitHub 後，在 `AI 工作區/Jumbo_Output/catalog.js` 的「數值報告」區加一筆（title 遊戲中文名、kind "數值報告"、url 用 rhino-boss.github.io 完整網址、game 代號、desc 一行「本作 vs 競品：主要章節」、date 產出日期），同時把 index.html／all.html 的 `?v=` 快取版號加一碼，再推上 Jumbo_Release。
- HTML 版式同 `市場資訊/H5/遊戲資訊/` 的競品分析報告：每章一個頁簽、頁簽只排一列可橫拉但不顯示拉條；表格不得出現橫向拉條（儲存格自動換行）。
- **重產網頁**：`py -X utf8 專案需知/其他/_report_build.py <專案>/report.html [曲線.json]` 由 `個人筆記/數值報告.md` 重畫報告頁簽、倍率線型（md 的 `<!--CHART:key-->`，資料 json 格式見腳本說明）與頁首 KPI，並自動套卡片版型。
- **卡片版型**：HTML 產出後一律跑 `py -X utf8 專案需知/其他/_report_card_style.py <專案>/report.html`：淺灰底＋圓角卡片（深色模式為深灰卡片）、膠囊頁簽、競品報告式頁首與 KPI 格，每節（`###`）一張卡片；倍率線型的圖例每一條線都可點選開關。可重複執行，重產 HTML 後再跑一次即可。
- **自動頁簽**：`_report_card_style.py` 同時產生三個頁簽（單跑：`_report_notes.py <專案>/report.html`），md 不重複內容：**玩法說明**（第 2 頁，取 `game_help_draft.md` 繁中規則說明與中文賠率表，不放 Game Meta、GAME RULE）、**修改紀錄**（`個人筆記/修改紀錄.md`）、**其他**（`個人筆記/上線觀察.md`＋`注意事項.md`：上線觀察、開發注意事項、歷史錯誤紀錄）；頁簽號自動重編。改了這些 md 要重跑。
- 百分比表格套條件式橫條（同競品報告：同表共用刻度、最大值以強調色、合計列不畫）；表格內只放百分比，不附括號內的分子／分母。

**比較口徑**

- 本作與前作一律用 **Card-On**（正式 RTP／Variant、Oldhand）報表；競品用實機側錄資料。自然機率（Card-Off）只可作附加欄，不得當主比較欄。
- 模擬在模擬機執行（NB ≥ 10⁶ 局、BF ≥ 10⁵ 次），報表存 `Record/` 並在報告來源表列出檔名。
- 指標口徑與競品報告一致；口徑不同時（例：分母只算初始盤面）以競品口徑為準並在該節說明。

**必要章節**

| 章節 | 內容 |
|---|---|
| 1. 基本資訊 | 頁簽之外只留頁首。節的順序：**遊戲簡介**（200 字內：盤面、怎麼贏、特色機制、FG 怎麼觸發、BF 價格，寫到玩家看完就懂規則）→ **比較對象** → **報告資訊**。**比較對象**表：固定三欄「類別｜遊戲｜為什麼比」、固定三列「競品／前作／同系列」；遊戲寫英文名＋廠商或版本（例：Money Coming（JILI）、Money Boost 1.0.0.2（原始版））；為什麼比用一句話說明比較目的；沒有的列遊戲欄填「—」並註明（例：目前沒有同系列作品。）。**報告抬頭資訊一律放在本章**：產出日期、比較口徑（本作／前作／競品各用哪種資料、Profile）、本作版本與主要設定摘要（盤面表與選表比例、補牌與倍數規則、賠率、FG 階梯、BF 價格、EB、自然率門檻、Max Win 等）、**資料來源表**（來源｜樣本數｜報表檔名）。 |
| 2. 玩法說明 | 自動頁簽：`game_help_draft.md` 的規則介紹（含賠率表），見上方「自動頁簽」。 |
| 3. 共同指標 | **基本指標**（第一節，一張表）：Total RTP、BG／FG RTP、BG Hit Rate、FG Hit Rate（每轉）、FG 週期、FG 平均倍數，併入原「玩法深淺」的 NB 標準差、FG 標準差（每場，以押注計；2026-11-11 起）、≥1000x／≥5000x／≥10000x 週期，有 Buy Feature 再列 BF 價格、BF RTP、BF 贏錢率（贏分 > 購買價）、BF 平均倍數、BF 標準差與高倍週期；競品／前作／同系列並列，沒有的填「—」；表後一句「平／深」結論（看標準差與存活中位數，平均把數由 RTP 決定不具鑑別度）。**第二節為存活模擬**：1000 人各帶 1000 元、每把押 1 元玩 NB 至不夠下注，**以比例顯示**：列＝第 1,000／5,000／10,000／20,000 把仍存活的玩家比例（2026-11-09 起）；以 Card-On 報表每局總得分分布（BG 非觸發局＋觸發局含觸發把）抽樣，註明抽樣方式。 |
| 4. 特殊指標 | 依遊戲機制挑選，每個指標一節（`###`），BG／FG 用 `####`。例：**金框比例**：平均每盤金框數、每格金框率、有金框盤面占比、各輪金框率（BG／FG 分開）；**金框使用率**：被消到而翻牌的金框數 ÷ 初始盤面金框數（BG／FG 分開）；**連消分布**：BG 每局、FG 每轉的 0／1／2／3／4／5+ 次（不加 3+ 合計列）；**大鬼出現率**：BG 每局、FG 每轉；並註明本作 BG 幾局一次、FG 每場幾次；**符號消除分布**：各符號 3／4／5 連的 Hit Rate 與 RTP（BG／FG 分開）；**WILD 倍數分布**：有帶倍數 Wild 的遊戲才需要：各種 Wild（如小鬼、大鬼本體、分裂）分開列各倍數占比。 |
| 5. 倍率線型 | NB-BG、NB-FG、BF **各一張**折線圖（預設縱軸 BG 0–1%、FG／BF 0–16%；**滑鼠滾輪縮放縱軸、雙擊還原**，由 `_report_card_style.py` 內嵌 `_chart_yzoom.js`，2026-11-09 起不再另畫放大圖），每張都含競品、前作、本作（卡片後，實線）與**本作自然機率（Card-Off，卡片前，同色虛線，預設隱藏、點圖例才顯示）**；64 區間全標；縱軸固定（BG 0–1%、FG／BF 0–16%），**圖例可點選切換各線顯示／隱藏**（關閉的圖例淡化加刪除線）；附 FG／BF 門檻機率表（含本作自然欄）；**滑鼠游標移到圖上鎖定該區間**，畫垂直線並列出各線數值（隱藏的線不列）；**圖例只寫名稱＋版本**（例：Super Ace、Super Diamond v5.0.0.0、Super Diamond v5.0.0.0 自然），不加括號說明；**圖下不加說明**；**每個區間都畫點**，機率 0 的點在 0 的位置，整條線全部連起來（不斷開）且**線半透明**，超過縱軸上限的部分被圖框裁掉；**x 軸寫法** `0`、`0 < x <= 1`、`1 < x <= 2`…（整數不加小數點，有小數才寫）；**競品一律灰色**，本作用彩色 |
| 6. 修改紀錄 | 自動頁簽（`個人筆記/修改紀錄.md`），每個版本一節。 |
| 7. 其他 | 自動頁簽：上線觀察、開發注意事項、歷史錯誤紀錄（取自 `個人筆記/上線觀察.md`、`注意事項.md`）。 |

特殊指標的版面（2026-11-11 起）：第一節「重點一覽」把單一數值的指標（平均、比例、使用率、Max／中位數／平均等）收成一張表；其餘每個分布一節、一張表，列＝分段，欄＝`BG · 競品`、`BG · 本作`、`FG · 競品`、`FG · 本作` 並排（只有 FG 的指標就兩欄），不再 BG／FG 各拆一張上下疊；表頭照「BG · 名稱」寫，`_report_card_style.py` 會在 BG 與 FG 欄組之間自動留空。和競品比較的單一數值（重點一覽等），本作比競品好的用綠字、差的用紅字、相同不上色：md 儲存格結尾寫 ` {+}`（好）或 ` {-}`（差），`_report_build.py` 會轉成顏色並去掉標記；好壞以玩家感受判斷，判斷方向寫在表下說明。**不加與競品的差（pp）欄、不加 3+ 等合計列**；口徑說明寫在表前一句或重點一覽下方的條列。

沒有對應機制的章節（例如無金框、無大鬼）可省略，但要在報告開頭註明；頁簽編號一律從 1 依序連號，省略章節後也重新連號（不沿用本表編號）。指標未達使用者設定的對標目標時，於回報中列出差距與可調的槓桿，由使用者決定是否調整；調整後重跑 Card-On 並重出數值報告。
