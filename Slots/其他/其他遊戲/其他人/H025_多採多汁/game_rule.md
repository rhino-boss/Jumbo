## §2. 盤面結構

盤面以 7×7 陣列儲存，但只有下列 37 格有效；`W` 為固定中央 Wild，`·` 為盤面外位置：

```text
       R1  R2  R3  R4  R5  R6  R7
row 0  □   □   □   □   ·   ·   ·
row 1  □   □   □   □   □   ·   ·
row 2  □   □   □   □   □   □   ·
row 3  □   □   □   W   □   □   □
row 4  ·   □   □   □   □   □   □
row 5  ·   ·   □   □   □   □   □
row 6  ·   ·   ·   □   □   □   □
```

- 初始盤面依 `ReelWeight` 抽選一套輪帶，再依該套輪帶與 MY 權重生成符號。
- 相鄰方向為上、下、左上、左下、右上、右下。
- 中央 Wild 固定在 `[col=3, row=3]`，不會因消除離開盤面。

## §3. 符號類別

### 3.1 一般符號

| 類別 | 符號 |
| --- | --- |
| 一般付獎符號 | M1、M2、M3、M4、M5、M6、M7 |
| 轉換用中介符號 | MY1、MY2、MY3；依數學權重轉換為目標符號 |

- 一般符號達 6 格以上相連才付獎。
- 來源沒有一般符號的大圖塊規格；2×2 Mega 圖塊屬於特色生成結果。

### 3.2 特殊符號

| 符號 | 出現位置 | 行為 |
| --- | --- | --- |
| **Wild（WW／ID 0）** | 固定中央格 | 可加入任一 M1～M7 Cluster，中央格保留、不被清除 |
| **Scatter（C1／ID 1）** | 各邏輯輪最多 1 顆 | 不參與 Cluster；所有 Cascade 結束後按總數觸發或增加 FG |

## §5. 核心遊戲流程（Base Game）

1. 依 `ReelWeight` 抽選初始輪帶組並建立 37 格盤面。
2. 依 MY 權重完成中介符號轉換，並限制每個邏輯輪最多 1 顆 C1。
3. 將中央格設為固定 Wild。
4. 尋找所有至少 6 格的相同符號 Cluster；中央 Wild 可加入相鄰 Cluster。
5. 每個 Cluster 依賠率表計算基礎分，再乘以本 Cascade 開始時的全域 Wild 倍數。
6. 清除中獎符號；中央 Wild 不清除。
7. 所有符號下落，依消除次數抽選 Drop 組合與 Random／Parallel 補位方式，再次限制每輪 C1 數量。
8. 每完成一個有中獎的 Cascade，Wild 倍數計數增加 1；包含中央 Wild 的 Cluster 另推進 Mega 系統。
9. 沒有一般 Cluster 時，若有待放置 Mega 圖塊，先執行 Mega Eliminate；成功放置後回到步驟 4。
10. 沒有 Cluster 且不能再放置 Mega 圖塊時結束本局，統計最終 C1 數量。

## §6. 核心特色

### 6.1 固定 Wild 與全域倍數

- 中央 Wild 永久固定，不能被清除或被 Mega 圖塊覆蓋。
- Wild 倍數計數在 Base Game 每局開始時歸零。
- 實際程式是「每完成一次有中獎的 Cascade，計數加 1」，不要求該次中獎 Cluster 一定包含 Wild。
- 倍數序列為：第一個 Cascade `×1`、第二個 `×2`、第三個 `×4`，之後每次增加 `2`，最高 **`×100`**。
- 同一 Cascade 的所有中獎 Cluster 都乘上同一個全域倍數。

### 6.2 Mega Level／Mega Count

- 每個包含中央 Wild 的 Cluster 使 Mega Level 增加 1；同一 Cascade 若有 2 組以上包含 Wild，最多增加 2。
- Mega Level 上限為 2；到達 2 時 Mega Count 增加 1，Mega Level 歸零。
- Mega Count 最多累積 3。
- 當盤面沒有一般 Cluster 時，依 Mega Count 嘗試放置相同符號的 2×2 菱形圖塊。
- 圖塊不得超出有效六角盤面、不得覆蓋中央 Wild、盤面外位置或其他已固定 Mega 格。
- 若選定圖塊位置含 C1，C1 保留，不被改寫。
- 實際放置成功幾個圖塊，就扣除幾點 Mega Count；未放下的數量保留到下一個無中獎檢查點。

## §7. 免費遊戲（Free Spins / Free Game, FG）

### 7.1 觸發

所有 Cascade 與 Mega Eliminate 結束後，依最終盤面 C1 數量給予 FG：

| C1 數量 | FG 次數 |
| ---: | ---: |
| 3 | **8** |
| 4 | **10** |
| 5 | 15 |
| 6 | 20 |
| 7 | 30 |

### 7.2 FG 玩法

- FG 使用 Free Game 專用 Reel／Drop／Eliminate 權重。
- Wild 倍數計數、Mega Level 與 Mega Count在整場 FG 內跨 Spin 保留。
- 每個 FG Spin 仍依一般 Cluster → Cascade → Mega Eliminate 流程執行。

### 7.3 Retrigger（加局）

- 每個 FG Spin 結束後重新統計 C1。
- 3／4／5／6／7 顆 C1 分別立即增加 **8／10／15／20／30** 次 FG。
- 最後一局仍可加局。

## §8. Buy Feature（購買特色）

- Excel 來源描述 Buy Feature 與 Super Buy 會使用 `Buy Feature Symbol` 生成初始盤面，再依 BG Scatter 權重放置 3～5 顆 C1。
- 進入 FG 後改用 Free Eliminate 參數。
- 購買價格、實際扣款 Bet、Super Buy 差異與 UI 流程均未提供，標記為 ⏳待確認。
- 現有 `Simulator.py` CLI 沒有串接 Buy Feature，因此本節不得視為已完成的可執行功能。

## §9. 邊界 / 例外情境（Edge Cases）

### 9.1 Wild／倍數相關

- **9.1.1 中央 Wild 不清除**：中央 Wild 參與 Cluster 後仍保留在原位。
- **9.1.2 全域倍數結算時機**：本 Cascade 先使用當前倍數結算，完成消除後才增加倍數計數。
- **9.1.3 倍數上限**：使用者已確認採程式值 `×100`，不採 Excel 部分文字的 `×1000`。

### 9.2 Scatter 相關

- **9.2.1 每輪上限**：每個邏輯輪最多保留 1 顆 C1；補位產生重複 C1 時，優先保留既有 C1。
- **9.2.2 不參與 Cluster**：C1 不作為 Cluster 起點，也不直接付分。
- **9.2.3 觸發判定點**：一個 Spin 的所有 Cascade／Mega 流程結束後才統計 C1。

### 9.3 Mega 相關

- **9.3.1 多組 Wild Cluster**：同一 Cascade 對 Mega Level 的增加量最多為 2。
- **9.3.2 圖塊無法全數放置**：只放置可合法放下的數量；剩餘 Mega Count 保留。
- **9.3.3 圖塊中的 C1**：C1 格不被 Mega 符號覆蓋，其餘合法格仍可固定為同一 Mega 符號。

### 9.4 Free Game 相關

- **9.4.1 FG 末場加局**：最後一場若有 3 顆以上 C1，仍立即增加剩餘場次。
- **9.4.2 狀態保留**：Wild 倍數與 Mega 狀態只在每場 FG 開始時重置，場內跨 Spin 保留。

### 9.5 尚未定義的產品行為

- **9.5.1 Max Win**：⏳未定義硬上限或截斷。
- **9.5.2 斷線重連／Auto Spin**：⏳純數學模擬器未定義狀態保存與操作流程。
- **9.5.3 Buy Feature**：⏳Auto Spin／FG 期間是否可用及購買確認流程未定義。
